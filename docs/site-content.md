# 記事・お知らせ・アラート

記事 (ガイドラインや利用規約などの読み物)、お知らせ、全ページの上部に表示するアラートの決まりをまとめる。語の意味は [concepts.md](concepts.md) にある。記事・お知らせ・アラートには、研究とは別の決まりを適用する。研究のバージョン・ID の割り当て・下書き・公開用の表示データのどれも使わず、公開検索の対象にもしない。編集には `manage-site-content` の権限が要る ([auth.md](auth.md))。記事から参照する画像と PDF は、公開の bucket の `common/` にアップロードする ([files.md](files.md))。

## 画面と記事の分け方

どの文章を admin が記事として編集し、どの文章をコードに書くかの決まりである。

- 本文のあるページは記事にして、admin が編集する。本文の無いページは、画面としてコードに書く。データの提供・利用・問い合わせのページは、ボタンと短い文だけなので、画面としてコードに書く。トップページも画面で、紹介の文もコード (`app/i18n/messages.ts`) に書く。紹介の文は数段落で、変えることが少なく、記事にするとトップと同じ文の別のページ (`/home`) ができるためである。
- 画面の部品は React のコンポーネントとして書き、記事の本文には入れない。本文に部品を入れると、markdown にレイアウト用の拡張記法と HTML が混ざるためである。
- グローバルナビとフッタは、コードの定数 (`app/public/navigation.ts`) で定義し、DB には保存しない。admin が編集する画面が無いためである。リンク先が実在することは、移行元の CMS の dump がある環境でだけ、テストで確かめている。

## 本文の保存形式

記事とお知らせの本文は、言語ごとの markdown の文字列として保存する。

- 本文と公開状態は言語ごとにある。公開していない言語のページは 404 になり、もう一方の言語にはフォールバックしない。
- 書式は CommonMark と GFM (表・取り消し線・タスクリスト・自動リンク・脚注) で、HTML は書けない。描画はサーバー (`app/public/markdown.server.ts`) で行い、HTML を解釈しない。そのため、ページに表示される要素は、markdown で書けるものに限られる。markdown で書けるものに限られることは、PBT で確かめている。記事とお知らせの本文は、研究の内容の書式付きテキスト ([data-model.md](data-model.md)) とは別の決まりだが、公開用の表示データ・検索・API のどれとも関わらない。
- 保存では、本文そのものを書き換える。下書きは無く、公開中の記事は、保存した時点で公開ページが変わる。読者に見せずに書き進めたい改訂は、バージョンのある記事の次のバージョンとして書く (下の「slug とバージョン」)。
- 保存するときに本文を解析する。HTML と許可しないリンク先があれば、保存全体を止めて、言語・種類・行番号を画面に表示する (その行の文字列は表示しない)。描画では警告なしに除くので、書いた人が気付けるのは保存のときだけである。
- 保存では更新番号 ([concepts.md](concepts.md)) を照合する。一致しなければ何も書き込まずに、衝突したことを画面に表示する。
- 公開のボタンを押すと、画面にある本文を保存してから公開する。保存し忘れて、1 つ前の本文が公開されることを防ぐためである。公開と公開停止は、確認なしで何度でも切り替えられる。
- 記事・記事のバージョン・お知らせの編集画面には、公開ページを言語ごとに新しいタブで開くボタンがある。記事のバージョンの画面では、このボタンで代表アドレス (下の「バージョンのある記事」) を開く。その言語を公開していないあいだは、ボタンを押せない。公開ページが 404 になるためである。
- 確認を求めるのは、削除と slug の変更だけである。削除は記事やお知らせ全体に対して行い、言語ごとの本文は削除できない。読者に見せたくない言語は、公開停止にすればよいためである。
- 利用ポリシーの値から指されている記事 (ポリシーの本文) を削除すると、語彙の値の指定は外れ、公開ページのリンクが消える ([catalog.md](catalog.md) の「画面から編集できる語彙」)。削除の確認で、指定が外れてリンクが消えることを表示する。
- 但し書きは GitHub の alert の記法 (`> [!NOTE]` など 5 種類) で書き、画面の注記と同じ見た目で表示する。種類を指定しない `>` は引用のままである。
- 見出しには、見出しの文字列から作った id が付き、URL で節を指定できる。id の規則は `app/public/heading-id.ts` の 1 つだけで、同じ文字列の見出しにだけ連番を付ける。見出しに番号で id を振ると、節を足しただけで、共有済みの URL が別の節を指してしまうためである。

## slug とバージョン

slug は admin が入力する記事の識別子で、記事の日本語の URL は `/{slug}`、英語の URL は `/en/{slug}` になる。

- slug には `/` を含められる。保存のときに、次の 4 つを検査する。slug の形、画面の URL との衝突 (`app/public/urls.ts` の `SCREEN_PATHS` と、言語の `ja` `en`)、旧ポータルの URL との衝突 ([public-site.md](public-site.md) の「旧ポータルの URL」)、記事とバージョンのある記事の両方での重複である。重複は 2 つのテーブルにまたがり、DB の制約 1 つでは防げない。そのため、保存する処理で両方を確かめ、テストで確かめている。
- slug を変えると外部からのリンクが切れるので、変更の前に確認を求める。

### バージョンのある記事

ガイドラインのように改訂を残す記事は、バージョンごとに独立した記事にし、slug を `{slug}/version/{n}` にする。バージョンの付かない `{slug}` を、代表アドレスと呼ぶ。代表アドレスには本文が無く、代表アドレスの行は、今のバージョンを指す行 (`document_series`) になる。

- 1 つの記事の行は、本文か、今のバージョンの指定かのどちらか一方である。今のバージョンの本文は 1 か所だけにあり、代表アドレスの行には本文のコピーを保存しない。
- 代表アドレスの URL はずっと 200 を返し、リダイレクトしない。外部のデータ提供の metadata に代表アドレスの URL が書き込まれており、引用する人がバージョン付きの URL をコピーすると、次の改訂で古いバージョンを指してしまうためである。代表アドレスの公開状態は、指しているバージョンの公開状態に従う。指しているバージョンがその言語で公開されていなければ、代表アドレスは 404 になるので、管理画面で警告する。
- 今のバージョンの指定は必須で、指されているバージョンは単独では削除できない。バージョンのある記事をやめるときは、代表アドレスの行と全バージョンを 1 つの操作で削除する。
- 今のバージョンの切り替えは、admin が手で行う。バージョンを公開しても、自動では切り替わらない。
- バージョンを追加すると、番号がいちばん大きいバージョンのタイトルと本文を言語ごとにコピーし、未公開で作る。改訂は前のバージョンの文を直して書くので、全文を入力し直すと意図しない違いが入るためである。
- 記事に初めてバージョンを付ける操作では、今の本文を `{slug}/version/{n}` に移し、空いた `{slug}` に代表アドレスの行を作る。バージョン番号は admin が決める。本文に書かれた `Ver.` と揃えるためである。バージョンの slug は後から変えられない。
- バージョンのある記事をバージョンの無い記事に戻す操作は無い。戻すと、バージョンの URL が 404 になるか、本文が 2 つに分かれるためである。

## お知らせ

お知らせは、言語ごとの本文と、お知らせ 1 件に 1 つの公開日時からなる。公開日時は、一覧の並び順に使い、公開サイトに表示するかどうかの判定にも使う。

- 作った時点では、公開日時は空である。作った時刻を入れると、その日付を選んだように見えるためである。公開日時が空のお知らせは公開できない。
- 公開サイトに表示されるのは、公開日時が現在以前で、かつその言語が公開中のお知らせである。公開日時を未来の日時にすると予約公開になり、その時刻になれば操作なしで表示される。言語ごとの状態は「公開中」「公開予定」「未公開」の 3 つである。
- 公開中の言語があるあいだは、公開日時を空にできない。空にすると、公開サイトからは消えるのに、状態は公開中のまま残るためである。
- 公開日時は、タイムゾーンの無い timestamp に日本時間の値で保存し、現在時刻も日本時間で求める (`now() at time zone 'Asia/Tokyo'`)。判定がサーバーの時計の設定に左右されないようにするためである。読者に表示するのは日付までである。
- 公開サイトのお知らせの検索は、公開検索とは別である。入力した文字列で、題名と本文を部分一致で探す。LIKE の `%` `_` はエスケープする。

## アラート

アラートは、全ページの上部に表示する短い文である。表示と非表示の切り替えと、表示期間がある。本文は日本語と英語の組で書く。

- 表示中のアラートには、必ず両方の言語の本文がある。アラートは全ページに表示されるので、片方の言語が無いと読めない読者が出るためである。片方が空のうちは、表示にできない。描画でもう一方の言語を代わりに使うのは、表示中のアラートには両方の言語の本文がある、という決まりが守られていないときのための備えである。
- 本文の保存では、表示状態は変わらない。表示にする操作では、画面にある本文を保存してから表示する。誰も読んでいない文面で表示されることを防ぐためである。
- 表示期間は開始と終了の日時で、どちらも空にできる。公開サイトに表示するのは、表示中で、開始が空か現在以前で、終了が空か現在より後のアラートである。状態は「表示中」「表示予定」(開始前)「表示終了」(終了後)「非表示」の 4 つである。期間の途中でも、非表示にすればその時点で消える。
- 開始と終了は、お知らせの公開日時と同じく、タイムゾーンの無い timestamp に日本時間の値で保存し、現在時刻も日本時間で求める。開始と終了の両方があるときは、終了が開始より後でなければ保存できない。
- 表示の条件を満たすアラートは、すべて表示する。管理画面と共有リンクのプレビューには表示しない。プレビューに表示すると、確認中の下書きの一部に見えるためである。
- 並び順は、admin が管理画面の上下のボタンで決め、公開サイトも同じ順に上から表示する。新しく作ったアラートは、いちばん上に入る。次に書くのは新しいものなので、下に入ると画面の外で開くためである。
- 読者が閉じたアラートは、そのページを開いているあいだだけ閉じたままになる。

## やっていないこと

- 記事とお知らせのバージョン・下書き・共有リンク。読者に見せずに書き進める改訂は、バージョンのある記事の次のバージョンで書く。
- HTML を書かせて許可リストで無害化すること。HTML を解釈しなければ、出せる要素は markdown で書けるものに限られる。
- 記事の目次の自動生成と、バージョン一覧の自動表示。見出しの URL で足りる。
