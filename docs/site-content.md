# サイトコンテンツ

記事 (document)・お知らせ (news)・アラート (alert)。research 系とは別の規則で動く — 版も pin も下書きも
公開表現も持たず、公開検索の対象にもならない。編集には `manage-site-content` が要る
([auth.md](auth.md))。記事が参照する画像と PDF は `common/` の箱 ([files.md](files.md))。

## 画面と記事の境い目

**本文を持つものは記事で admin が直し、持たないものは画面でコードが持つ。** 提供・利用・問い合わせの
入口はボタンと短い文だけなので route が持つ。トップは枠が route、本文が `home` 記事。**画面の部品は
component で持ち、本文の書式に持ち込まない** — 混ぜると markdown にレイアウト用の拡張記法と生 HTML が
入る。**グローバルナビとフッタもコードの定数** (`app/public/navigation.ts`) で DB に持たない。指す先が
実在することは test が守る。

## 持ち方

- **locale ごとに本文と公開状態を持つ。** 版が無いので「公開の単位は版」は当てはまらず、公開されて
  いない言語は**もう一方に倒れずに 404** になる
- **本文は markdown 文字列。** CommonMark と GFM の表を許し、生 HTML は持たない。描くのは server
  (`app/public/markdown.server.ts`) で、生 HTML を parse しないので出せる要素の集合は markdown が表せる
  集合で決まる (PBT で守る)。research 系の文 ([data-model.md](data-model.md)) と規則が 2 系統あるが、
  公開表現・検索・API のどれとも交わらない
- **保存は本文そのものを書き換える。** 下書きの器を持たず、公開中の記事なら保存した時点で公開ページが
  変わる。読まれないまま書き進めたい改稿は、版を持つ記事で次の版を書く (下)
- **保存の時点で本文を parse し、生 HTML と許さないリンクの行き先を弾く。** 弾いたら保存全体を止め、
  locale・種類・行番号を返す (その行の文字は返さない)。描画側は黙って落とすので、書いた人が気づける
  場所がここしかない
- **保存は revision で照合する。** 影響行数が 0 なら 409
- **確認を挟むのは削除と slug の変更だけ。** 公開と公開停止は 1 つのボタンで往復できる。削除は記事
  (お知らせ) そのものだけで、言語ごとの本文は削除しない — 読ませたくない言語は公開停止で足りる
- **公開は画面にある本文を書いてから公開する。** 「保存を忘れたので 1 つ前が出た」が起きない

**但し書きは GitHub の alert の記法** (`> [!NOTE]` など 5 種) で書き、画面の注記と同じ器で描く。名乗らない
`>` は引用のまま。**見出しは語から作った id を持ち**、アドレスで節を指せる。id を作る規則は 1 つ
(`app/public/heading-id.ts`) で、同じ語の見出しにだけ連番が付く — 番号で振ると、節を足しただけで共有
済みのアドレスが別の節を指す。

## slug と版

**slug は admin が打つ識別子で、アドレス (`/{slug}`) は読者が開く URL。** slug は `/` を含められる。
検査は 3 つ — 形、route が持つアドレスとの衝突 (`app/public/urls.ts` の `SCREEN_PATHS`)、記事と系列の
両方での重複。DB の制約 1 本では守れないので保存側が両方を見て弾き、test が守る。**外部が焼き込んだ
slug を変えると参照が切れる**ので、変更は確認を挟む。

**ガイドラインのように版を持つ記事は、版ごとに独立した記事で、slug は `{slug}/version/{n}`。** 版なしの
slug は本文を持たず、いまの版を指す行 (`document_series`) になる。

- **記事は本文を持つか指し先を持つかのどちらか一方。** 本文の原本は 1 か所で、写しを作らない
- **版なしの slug は恒久的に応答し続け、redirect しない。** 外部の submission metadata が焼き込んで
  いて、引用する人が版付きのアドレスを写すと次の改定で古い版を指すことになる。公開状態は指し先のもので、
  指し先がその言語で公開されていなければ 404 になるので、管理画面が不備として出す
- **指し先は NOT NULL で、指されている版は単独で削除できない。** 系列を畳むときは指し先の行と配下の
  全版を 1 操作で削除する
- **張り替えは admin の手の操作。** 版の公開に連動して自動では動かない
- **版を初めて切る操作は「移す」** — いまの本文を `{slug}/version/{n}` へ rename し、空いた slug で
  指し先の行を作る。**版番号は admin が決め** (本文の `Ver.` と揃えるため)、版の slug は打ち直せない
- **版を持つのをやめる操作は持たない。** 戻すと版のアドレスが 404 になるか本文が 2 つに割れる

## お知らせ

**お知らせは identity + locale ごとの本文 + 公開日時。** 公開日時は identity に 1 つで、一覧の並びそのもの
であり、公開側に出るかも決める。

- **作成時は公開日時を持たない。** 作った瞬間の時刻を入れると、決めた日付に見える
- **公開側に出るのは「公開日時 ≤ いま」かつ「その言語が公開中」。** 未来の日時は予約公開で、時刻が
  来れば何もしなくても出る。言語の状態は 公開中 / 公開予定 / 未公開 の 3 つ
- **公開中の言語があるあいだ、公開日時は空にできない。** 空にすると全言語が公開側から消えるのに状態は
  公開中のまま残る
- **公開日時はタイムゾーンを持たない timestamp に JST の値で持ち、「いま」も JST で読む**
  (`now() at time zone 'Asia/Tokyo'`)。判定は server の時計の置き方に依らない。読者に出すのは日付まで
- **お知らせの検索は公開検索とは別の部分一致**で、打たれた語をそのまま探す (LIKE の `%` `_` は
  エスケープする)

## アラート

**全ページの上部に出る 1 文。on / off だけを持ち、期間を持たない。** ja / en の対を 1 つ持つ。

- **立っているアラートは必ず両方の言語を持つ。** 全ページに出るので、片方しか無いと読めない箱を
  渡すことになる。admin は両方そろうまで表示にできず、移行は立っているものの空いた側を手で書いた訳で
  埋め、埋められなければ止まる。描く側が片言語のときにもう一方を出すのは防御で、そうと断る
- **表示の切り替えと本文の保存は、片方がもう片方を動かさない**
- **立っているものは全部出す。** 出さないのは管理画面と共有リンクの preview だけ (確かめている下書きの
  一部に読めるため)。読者が閉じられるのは開いているページのあいだだけ

## 意図的にやっていないこと

| やらないこと | 理由 |
|---|---|
| 版・下書き・共有リンク | 版が無いので比べる相手が無く、同じ記事を並行して書いた実績も無い。読まれずに書き進める改稿は系列の次の版で書く |
| 言語ごとの本文の削除 | 公開停止で足りる |
| 生 HTML と許可リストの sanitize | 生 HTML を parse しなければ、出せる集合が markdown の集合そのものになる |
| navigation のテーブル | admin が編集する UI を持たない |
| アラートの期間指定 | 持つと表示の判定が 2 本立てになる |
| 記事の目次の自動生成・版の一覧の自動表示 | 見出しのアドレスで足りる |
