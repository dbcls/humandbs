# 記事・お知らせ・アラート

記事 (ガイドラインや利用規約などの読み物)、お知らせ、全ページの上部に表示するアラートの決まりをまとめる。語の意味は [concepts.md](concepts.md) にある。これらは研究とは別の決まりで動き、研究のバージョン・ID の割り当て・下書き・公開用の表示データのどれも使わず、公開検索の対象にもならない。編集には `manage-site-content` の権限が要る ([auth.md](auth.md))。記事から参照する画像と PDF は `common/` のフォルダに置く ([files.md](files.md))。

## 画面と記事の分け方

どの文章を admin が記事として編集し、どの文章をコードに書くかの決まりである。

- 本文のあるページは記事にして admin が編集し、本文の無いページは画面としてコードに書く。データの提供・利用・問い合わせの入口はボタンと短い文だけなので画面に書く。トップページは枠を画面に書き、本文を `home` という slug の記事にする。
- 画面の部品は React のコンポーネントとして書き、記事の本文には入れない。本文に部品を入れると、markdown にレイアウト用の拡張記法と HTML が混ざるためである。
- グローバルナビとフッタはコードの定数 (`app/public/navigation.ts`) で定義し、DB には置かない。admin が編集する画面が無いためである。リンク先が実在することはテストで確かめている。

## 本文の持ち方

記事とお知らせの本文は、言語ごとの markdown の文字列として保存する。

- 本文と公開状態は言語ごとにある。公開していない言語のページは 404 になり、もう一方の言語にはフォールバックしない。
- 書式は CommonMark と GFM の表で、HTML は書けない。描画はサーバー (`app/public/markdown.server.ts`) で行い、HTML を解釈しないので、ページに出る要素は markdown で書けるものに限られる。このことは PBT で確かめている。研究の記述の書式 ([data-model.md](data-model.md)) とは別の決まりだが、公開用の表示データ・検索・API のどれとも関わらない。
- 保存は本文そのものを書き換える。下書きは無く、公開中の記事は保存した時点で公開ページが変わる。読者に見せずに書き進めたい改訂は、バージョンのある記事の次のバージョンとして書く (下の「slug とバージョン」)。
- 保存するときに本文を解析し、HTML と許可しないリンク先があれば保存全体を止めて、言語・種類・行番号を返す (その行の文字列は返さない)。描画では黙って落とすので、書いた人が気付けるのはこの時点だけである。
- 保存では更新番号 ([concepts.md](concepts.md)) を照合し、一致しなければ 409 を返す。
- 公開のボタンは、画面にある本文を保存してから公開する。保存し忘れて 1 つ前の本文が公開される、ということが起きないためである。公開と公開停止は確認なしで何度でも切り替えられる。
- 確認を挟むのは削除と slug の変更だけである。削除は記事やお知らせ全体に対して行い、言語ごとの本文は削除できない。読ませたくない言語は公開停止にすればよいためである。
- 但し書きは GitHub の alert の記法 (`> [!NOTE]` など 5 種類) で書き、画面の注記と同じ見た目で表示する。種類を指定しない `>` は引用のままである。
- 見出しには見出しの文字列から作った id が付き、URL で節を指定できる。id の規則は `app/public/heading-id.ts` の 1 つだけで、同じ文字列の見出しにだけ連番を付ける。見出しに番号で id を振ると、節を足しただけで共有済みの URL が別の節を指してしまうためである。

## slug とバージョン

slug は admin が入力する記事の識別子で、記事の URL は `/{slug}` になる。

- slug には `/` を含められる。保存のときに、形、画面の URL との衝突 (`app/public/urls.ts` の `SCREEN_PATHS` と、言語の `ja` `en`)、記事とバージョンのある記事の両方での重複を検査する。重複は 2 つのテーブルにまたがり DB の制約 1 つでは守れないので、保存する処理で両方を確かめ、テストで確かめている。
- slug を変えると外部からのリンクが切れるので、変更の前に確認を挟む。

### バージョンのある記事

ガイドラインのように改訂を残す記事は、バージョンごとに独立した記事にし、slug を `{slug}/version/{n}` にする。バージョンの付かない `{slug}` には本文が無く、今のバージョンを指す行 (`document_series`) になる。

- 1 つの記事の行は、本文か、今のバージョンの指定かのどちらか一方である。本文は 1 か所だけにあり、コピーを作らない。
- バージョンの付かない URL はずっと 200 を返し、リダイレクトしない。外部のデータ提供の metadata がこの URL を書き込んでおり、引用する人がバージョン付きの URL をコピーすると、次の改訂で古いバージョンを指してしまうためである。公開状態は指しているバージョンのものに従い、その言語で公開されていなければ 404 になるので、管理画面で警告する。
- 今のバージョンの指定は必須で、指されているバージョンは単独では削除できない。バージョンのある記事をやめるときは、指定の行と全バージョンを 1 つの操作で削除する。
- 今のバージョンの切り替えは admin が手で行う。バージョンを公開しても自動では切り替わらない。
- 記事に初めてバージョンを付ける操作では、今の本文を `{slug}/version/{n}` に移し、空いた `{slug}` に指定の行を作る。バージョン番号は admin が決める。本文に書かれた `Ver.` と揃えるためである。バージョンの slug は後から変えられない。
- バージョンのある記事をバージョンの無い記事に戻す操作は無い。戻すとバージョンの URL が 404 になるか、本文が 2 つに分かれるためである。

## お知らせ

お知らせは、言語ごとの本文と、お知らせ 1 件に 1 つの公開日時からなる。公開日時は一覧の並び順であり、公開サイトに表示するかどうかも決める。

- 作った時点では公開日時は空である。作った時刻を入れると、その日付を選んだように見えるためである。公開日時が空のお知らせは公開できない。
- 公開サイトに表示されるのは、公開日時が現在以前で、かつその言語が公開中のものである。未来の日時にすると予約公開になり、その時刻になれば操作なしで表示される。言語ごとの状態は「公開中」「公開予定」「未公開」の 3 つである。
- 公開中の言語があるあいだは、公開日時を空にできない。空にすると公開サイトからは消えるのに、状態は公開中のまま残るためである。
- 公開日時はタイムゾーンの無い timestamp に日本時間の値で保存し、現在時刻も日本時間で求める (`now() at time zone 'Asia/Tokyo'`)。判定がサーバーの時計の設定に左右されないためである。読者に表示するのは日付までである。
- 公開サイトのお知らせの検索は公開検索とは別で、題名と本文を入力した文字列の部分一致で探す。LIKE の `%` `_` はエスケープする。

## アラート

アラートは全ページの上部に表示する短い文で、表示と非表示の切り替えだけがあり、期間は指定できない。本文は日本語と英語の組で書く。

- 表示中のアラートには必ず両方の言語の本文がある。全ページに表示されるので、片方の言語が無いと読めない読者が出るためである。片方が空のうちは表示にできない。描画でもう一方の言語を代わりに使うのは、この決まりが破れたときのための防御である。
- 本文の保存は表示状態を変えない。表示にする操作は画面にある本文を保存してから表示する。誰も読んでいない文面で表示されることを防ぐためである。
- 表示中のアラートはすべて表示する。管理画面と共有リンクのプレビューには表示しない。プレビューに表示すると、確認中の下書きの一部に見えるためである。
- 読者が閉じたアラートは、そのページを開いているあいだだけ閉じたままになる。

## やっていないこと

- 記事とお知らせのバージョン・下書き・共有リンク。読者に見せずに書き進める改訂は、バージョンのある記事の次のバージョンで書く。
- 言語ごとの本文の削除。公開停止で足りる。
- HTML を書かせて許可リストで無害化すること。HTML を解釈しなければ、出せる要素は markdown で書けるものに限られる。
- ナビゲーションのテーブル。admin が編集する画面が無い。
- アラートの期間指定。表示の判定が 2 通りになる。
- 記事の目次の自動生成と、バージョン一覧の自動表示。見出しの URL で足りる。
