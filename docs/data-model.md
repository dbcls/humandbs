# データモデル

research 系 (研究・版・下書き・データセット) を何の形で持ち、どの不変条件を守るか。テーブルと型の
定義はコード (`app/db/schema/`、`app/content/types.ts`) が持ち、ここには写さない。サイトコンテンツは
[site-content.md](site-content.md)、ファイルは [files.md](files.md)。

**Postgres が唯一の store で、編集中のものと公開済みのものを両方持つ。** 派生値 (検索用の行・外部
キャッシュ) は計算の側が SSOT で、いつでも作り直せる。

## content と行

**content は JSONB で持つ。** 版の content、下書きの content、下書きが持つデータセットのエントリ
(experiment を含む) のどれも。**値の型は編集と公開で同じで、器の割り方だけが違う** — 下書きは本文と
データセットを別の行に割り (保存は 1 データセットずつ走る)、版は 1 つの content に畳む (公開は年に
数えるほど)。型が同じなので公開は値のコピーで済む。

**公開分の読み取りは畳んだ content から引かない。** JSONB は TOAST に落ちると部分読み出しができず、
データセット 1 件のために版まるごとを展開することになる。公開分は検索用の行が本文ごと持つ。

**値スロットを列に割らない。** どのスロットが埋まるか (翻訳対・数値・語彙値) はキーの型で決まるので、
列に割ると NULL 許容の列が並んで整合を schema で保証できない。

行にするのは content ではないものだけ — 検索用の行 (集計と索引)、pin 台帳 (一意性を DB の制約で
守る)、catalog と語彙 (参照整合性)、外部キャッシュ (取り込みが書く)、event・コメント・job (追記される)。
**experiment は行にしない。** データセットの content の中の順序つきの要素で、identity はその要素の
代理キー。集計は検索用の行が公開分だけ別に持つ。

## identity と label

**内部の同一性と、外に見せる名前を混ぜない。** research と dataset は抽象的な identity を持ち、
**研究 ID (hum ラベル)・データセット ID・公開版番号はそこに後から pin する label**。label が無くても
作れ、label が変わっても参照が壊れない。管理画面のアドレスも identity で指す。

- **研究 ID とデータセット ID は `label_pin` 台帳で、種別と文字列について全体で一意。** 版番号は
  research の中でだけ一意なので、版の行そのものが持つ
- **可視性は公開状態にある版の集合で判定し、番号の大小で判定しない。** 番号には欠番がありうる
- **pin を外した label は再利用できる。** 研究 ID は申請管理システムに人が打つ自由文字列が起点で、
  typo の訂正が日常の操作になるため。例外は NHA ID (下)
- **1 つの identity に複数の label を pin でき、primary は 1 つ。** 残りは secondary で、旧い ID への
  外部参照を解決し続けるためにある。primary の一意は部分 unique index が守る
- **pin した時点で台帳に載り、公開を待たない。** 同じ accession を 2 つの下書きが pin しようとすると
  2 つ目が弾かれるので、公開時に identity を寄せる処理は要らない。下書きが作ったデータセットは下書きと
  運命を共にし、下書きを削除すれば pin も消える

**ポータルが発行するデータセット ID (NHA ID) は `NHA` + 6 桁 (`NHA000001`) のポータル全体の通し
番号で、再利用しない。** admin は綴りを選べず発行を頼むだけで、この形の文字列を手で pin することは
できない。pin を外しても、データセットごと消えても番号は二度と出ない — 外に貼られたリンクが黙って
別のデータセットを指さないため。次の番号は台帳と証跡 (`event`) の両方に残る最大の番号の次で、番号は
研究も版も運ばない。この形より前にポータルが付けた id は研究の hum ラベルで始まる
(`hum0014.v1.freq.v1`)。**移行はそれらに NHA ID を発行して primary にし、旧 id は secondary に残す。**
番号は初めて公開された順 (同じ日は hum 番号の順) で、一度も公開されていないものが後ろに続く。

**データセット ID から読むのは「ポータルが発行したものか」の 1 点だけ**で、primary の綴りが `NHA` +
6 桁に完全一致するか `hum` で始まるかで決める。secondary は見ない (移行が旧 id を secondary に残すので)、
primary が未 pin の間は外部として扱う。この 1 点がファイル選択を持てるかを決める ([files.md](files.md))。
版番号・トークンなど、それ以外の構造には意味を読み込まない。

## research / dataset / experiment

```
Research (identity)            <- research ID pinned in the ledger
+-- ResearchVersion            <- published; the number is a label
|     content                     body + description of every dataset it carried
+-- ResearchDraft              <- unpublished working copy; several allowed
|     content / note / dataset entries / replaces (optional)
+-- Dataset (identity)         <- dataset ID pinned in the ledger
      +-- Experiment           <- ordered element inside the dataset description
```

**データセットも experiment も版を持たない。** 実体 (アーカイブに登録されたデータ) は不変で、変わるのは
記述の訂正なので、訂正は公開中の版の更新で行う ([publishing.md](publishing.md))。**版は配下の記述ごと
畳んで持つ**が、公開ページが描くのは版のデータセットの一覧までで、各データセットの記述は検索用の行が
持つ最新のもの。過去の版のページはそう断る。

**データセットは 1 つの research に属し (composition)、その存在は research のもので、版や下書きが
選ぶものではない。** research が持つのは公開済みのデータセットと、どれかの下書きが作ってまだ公開して
いないもの。下書きが持つのは順 (`datasetIds`) と記述だけで、「載せる / 載せない」の選択は無い。
**削除は research から消す操作で、公開を待たずに効く** — 検索用の行ごと消えるので公開ページからその場で
消え、過去の版の content に記述は残っても行が無いので版のページには出ない。削除は証跡に残る。

**関連論文が名指すのは所有ではなく引用。** その research のデータセットは identity で、それ以外
(他の研究のもの、ポータルに無い accession) は書かれた ID の文字列で持ち、描く時点で台帳を引く。

| 判定 | 根拠 |
|---|---|
| データセットが公開されているか | 最新の公開版の content に載っていて、データセットの行がまだある |
| 版のページにデータセットが出るか | その版の content に載っていて、行がまだある |
| experiment が公開画面に出るか | 属するデータセットがその版に出ている |

## 言語と値の状態

**公開の単位は research の版であって言語ではない。** 版は ja / en を一体で持ち、片言語が未翻訳のまま
公開できる (英語版の無い研究が実在する)。代わりに公開ゲートが未翻訳を列挙する。

**field は 3 種に分かれ、分類は content の型が持つ** — 言語を持たない単一値 (数値・語彙値・accession・
論文タイトル)、言語ごとに表記がある翻訳対 (本文・機関名・研究課題名)、言語ごとに別のリソースを指す値
(URL だけ)。**単一値から翻訳対への拡張は機械的に行える**ので、迷う field は単一値に寄せてよい。
**両言語に同じ値をコピーしてはいけない** — 導出が翻訳済みと判定する。

値は 4 通りに見える。

| 見え方 | 意味 | 公開画面 | 検索・facet | preview |
|---|---|---|---|---|
| 値あり | | 出す | 載せる | 出す |
| 空 | まだ誰も触っていない | 出さない | 載せない | 出さない |
| 未確定 (unknown) | 値があるはずだが確定していない | 出さない | 載せない | 状態を出す |
| 該当なし | 値が無いことが確定している | 該当なしと表示 | 載せない | 状態を出す |

- **空は状態ではなく「値ありで中身が空」。** 必須の検査は空を見て、未確定は curator が明示的に立てる
  「提供者に聞いている」の印になる
- **未確定は公開前に潰す対象で、該当なしは確定した情報。** 公開ゲートが列挙するのは前者だけ
- **状態は言語ごとに持ち、置き場は値の中の 1 か所だけ。** 片方の言語だけが確定していない値が実在する
- **未翻訳は状態ではなく値から導出する** — 翻訳対で両言語が値を持ち、片方だけが空のとき。状態が食い
  違う (ja に値、en が未確定) なら未確定として数え、1 つの欠けがゲートに 2 度出ない
- **該当なしの表示文字列は値として持たない。** 描画側が作る

**表示する言語を選ぶのは `app/i18n/locale.ts`** で、欲しい言語の状態が先に答える。該当なしと未確定は
もう一方へ倒れない (未確定を埋めると preview から問いが消える)。空の翻訳対はもう一方へ倒れて未翻訳を
添える。URL は倒れない (別のリソースへ読者を送ることになる)。

## 値と文

**書式を持つのは文だけで、境界は catalog のキーの型が決める。** 値 (accession・語彙・数値・疾患・
名前の類) は書式を持たず、リンクや単位は描く側が型から作る。

**文は行と span の木で持つ** — 行の列、span は文字列か文字列と URL の対。見出し・表・箇条書き・強調・
生 HTML はどれも入らない。許す集合が型そのものになり (保存時の検査と表示時の sanitize の二重管理が
消える)、ポータルと同じ origin での stored XSS の経路も消える。残るリンクの URL は描く時点で scheme を
検査する。**出力は 3 方向** (`app/content/richtext.ts`) — 画面は木を描き、plain text は JSON API と
全文検索が使い、markdown は編集画面に返す。**HTML 文字列を作る経路は持たない。**

**入力は markdown で受け、保存の時点で木に落とす。** 木が持てない記法は書かれた文字のまま残し、撥ねも
消しもしない (効いていないことは編集画面の隣の公開ページが見せる)。**単一の改行は行の区切り。**
一度保存を通った文は、編集画面に出して保存し直しても同じ木になる。

**一覧の要約 (`listingSummary`) は詳細から導出しない。** 研究一覧の解析手法・データの種類・参加者は
curator が書く — 詳細は experiment ごとの語彙で、要約は研究 1 件の分類語や足し合わせた表記なので、
導出した既定値を置くと上書きした値と区別が付かなくなる。**提供者の列だけは例外で、空なら詳細の研究
代表者名を読み**、書けばそちらが出る。名前を 1 つも持たない要素は保存が落とす。

**数値のキーは数を 1 つではなく列で持つ。** 1 つのセルに部位ごとの数が並ぶデータが多く、1 つしか
持てないと同じ事実が文と数値の 2 か所に住む。各数は「何の数か」(label) と「但し書き」(note) を任意で
持ち、label を語彙にするのはゲノム領域だけ。**幅のある値は下限 `value` と任意の上限 `high`** で持ち、
どちらも正準単位の値。打たれた単位の値 (`inputValue` / `inputUnit` / `inputHigh`) も残し、画面は
そちらを出す。**換算は `app/content/units.ts` の 1 か所だけ**で、データ量も配列長も 1000 刻み (SI)。
正準単位を持たないキー (数えるもの) は書かれた単位がそのまま単位になる。

## catalog と語彙

データセットと experiment の値スロットのキーは catalog (`content_key`) が持つ。キーは付く先
(dataset / experiment)・表示ラベル (ja/en)・値の型・表示順を持つ。

- **rename は表示ラベルの変更で、データに伝播しない。** 表示順も catalog が持つ
- **キーの追加は明示的な操作。** 打った文字列が catalog に載る経路を持たない (キーの揺れはそこから
  生まれた)。編集画面からもデータ提供申請の取り込みからもキーと語彙値は作られない
- **キーの型が facet を決める。** 語彙・疾患の型は常に facet になり、数値の型は facet のカテゴリを
  持つキー (対象者数とリード長) だけが絞り込みの軸になる。軸かどうかはカテゴリの有無で表し、別の列を
  持たない。公開日と更新日は例外で、キーではないが絞り込みに出る
- **キーの code と語彙値の code はアドレスに出る** (`?q=platform:hiseq-2500`) ので、英語ラベルから
  機械が作り、admin に打たせない (`app/admin/catalog.ts` の `codeFrom`)。組み込みの検索 field と同じ
  綴りは持てない。ICD10 だけは code が標準のコードそのもの
- **語彙値のラベルは en 必須・ja 任意。** ja が空でも未翻訳に数えない

**admin が触るのは実データが持ち込むものだけ。** 値の集合がポータルの仕様として閉じているもの
(アクセス制限・性別などの排他的な分類、`scope=dataset` のキー、facet のカテゴリ) は移行が入れて編集口を
持たず、ICD10 は外部標準が決めているので読むだけ。閉じていても DB に残す — 検索用の行が語彙値の id を
参照しているため。

- **使われているキーと語彙値は削除できない。** 公開・下書きのどちらかの content が値を持つか指していれば
  使用中
- **使われている語彙値を畳むのは統合** — 指している値を全部行き先へ書き換えてから元を消す。同じ語彙の
  中でだけ畳め、**過去の版の content も書き換える** (語彙値は記述ではなく記述が指す先なので)。語彙値に
  「選べない」状態は持たない
- **catalog を書き換えたら検索用の行を作り直す。** 例外はキーの並べ替えだけで、その判断は書き込みを
  束ねる 1 か所に置く

**語彙は原則フラットで、階層を持つのは ICD10 だけ** — 3 桁分類を根、4 桁をその子とする 2 層。
facet が数えるのは根だけになる。**製品を指す語彙値は会社名を `maker` 列で別に持つ。** 親子にすると
絞り込みパネルに会社名が並ぶ。ラベルは会社名を含んだ全体のままで、分けるのは描くときだけ。
**1 つの語彙値は 1 つのものを指す。** 表示順 (`position`) は編集フォームの候補と一覧のセルが読み、
絞り込みパネルは件数順で読まない。

### 疾患と ICD10

**疾患の値は、語彙値への参照の並び (0 個以上) と呼称 (ja/en) でできている。** 識別子を 1 つも持たない
値が正しい状態 — 分類に載っていない疾患が実データにある。**呼称は値が持ち、見出し語は語彙値が持つ** —
同じコードが研究ごとに違う集団の定義として書かれるので、呼称を語彙に寄せると潰れる。表示は
「呼称があれば呼称、無ければ見出し語」。**1 つの値が複数の体系の語彙値を指せる**ので、体系を足しても
値の形は動かない。

- **コードは 3 桁と 4 桁だけを持つ。** 移行も申請からの下書きも同じ正規化 (`app/icd10/codes.ts`) を
  通し、語彙に当たるまで末尾を削る。3 桁を 4 桁へ広げない (書き手が選ばなかった細分を補わない)
- **分類の本体が語彙そのもの。** `npm run icd10:import` が 3 桁と 4 桁の全コードを語彙 set `icd10` に
  入れ、別の辞書は持たない。語彙値は読むだけで、再取り込みは code で突き合わせて上書きする (id は
  変わらない)。英語は WHO ICD-10 2019、日本語は e-Stat の基本分類で、版が違って片方しか無いコードは
  日本語を英語の側にも置く
- **識別子を持たない値は facet の行を作らない**が、呼称が全文に入るので検索窓からは引ける

## 公開表現

`app/content/public.ts`。**公開表現は content から純関数で作り、経路を 1 本に保つ。** 公開ページも
共有リンクの preview も編集画面の隣の公開ページも同じ関数を通り、違いは未確定を残すかどうかの引数
だけ。公開ページの経路にこの引数は届かない。

**公開表現は落とすことしかしない。** field 名も構造も値の表現も変えないので、返り値の型は content の型
そのもの (content ⊃ 公開表現)。落とすのは、未確定のスロット (preview では残す — 聞きたい欄を提供者に
見せるため)、catalog が公開しないと言うキーと catalog が知らないキーのスロット、箱の list に無い
ファイル選択。**入力は content・catalog・外部キャッシュ・箱の list の 4 つで、関数は外部を自分で
叩かない。** データセットの日付だけはここで 1 つに解決し、下流のどこにも判断させない (「日付」)。

## 検索用の行

**何が公開されているかの判定をここ 1 つに閉じる。** 公開画面・JSON API・公開検索は、対象の集合も本文も
この行からしか引かない。**行は公開の操作でしか生まれない**ので、編集中の値がここに現れる経路が無い。
中身は content (公開表現ではない — 隠れたキーも admin の「まだ使われているか」の対象として要る)、
全文検索の列を持つ行 (`search_doc`)、語彙 facet の行、数値 facet の行。

- **公開・取り下げ・pin の付け外し・キャッシュの更新と同じトランザクションで作り直す。** 「反映されて
  いない」状態が存在しない
- **行が消える経路は「公開分を作り直す」の 1 つ。** 取り下げも削除も専用の処理を持たない
- **導出は 1 つの関数** (`app/search/rebuild.server.ts`) で、範囲は research 単位か全件。全件の作り直しを
  常用の手段として持ち、2 度作り直しても同じ行になる
- **research の行は配下の公開データセットの値の和集合を持つ。** 研究一覧で 2 つの facet を選ぶと、別々の
  データセットが満たしていてもその研究は当たる
- **語彙値の表示ラベルは焼かず join で引く。** ICD10 のロールアップは祖先の id の列で効かせ、集計は根で
  数える

**全文は公開表現から作る。** 公開表現に出ない文字で行が当たることが構造的に起きない。語彙値の code と
両言語のラベル、疾患の呼称、pin 台帳の label は足す。画面に文字として出ない値 (identity・判別子・
リンクの行き先・換算前の入力・ファイル選択) と、行を見分けない正準単位は外す。**ファイル名は入れない** —
名前の原本は箱の側にあり、入れると作り直しが S3 の可用性に縛られる。**facet の行だけは content から
作る** — catalog が公開ページに出さないキーこそが facet の source になりうる。

**索引は PGroonga の n-gram** (`TokenNgram`、`NormalizerNFKC150`)。accession の語中一致と日本語の部分
一致の両方が要るので形態素解析を採らない。全文の列は ja と en を連結した生成列で、全文の述語は
`WITH ... AS MATERIALIZED` に閉じ込める (プランナが nested loop の内側で再評価するのを防ぐ)。

## 外部キャッシュ

外部 master の値は Postgres のキャッシュテーブルに置き、読み手はそこだけを見る。

| source | 上流 | 用途 |
|---|---|---|
| `cau` 制限公開データの利用者 | JGA 申請管理システム DB | 公開表現 |
| `hum-accession` 研究 ID ↔ accession、JGAD → JGAS | 同上 | 公開ゲートの検算、データセットのページ、DDBJ Search への供給 |
| `jgad-date` JGAD の日付 | 同上 | 公開表現 |
| `archive-date` DRA / GEA / MetaboBank / BioProject の日付 | DDBJ Search | 公開表現 |

- **上流が止まっても公開ページは動く。** 失っても再取得できるので backup の対象外
- **入れてよいのは、そのまま公開ページに出る値だけ。** 申請の中身 (連絡先・住所・申請書の本文) は
  持ち込まない。照合のためのキー (案件番号) だけが例外で、公開表現にも API にも出ない
- **CAU は content ではない**ので翻訳状態を持たず、未翻訳にも数えない。1 行は 1 利用課題で人に丸めない。
  国名はポータルが ISO 3166 の日英の名前に寄せ、州は米国・カナダ・オーストラリアだけ添える
- **研究 ID と accession の対応の master は上流**で、ポータルの pin は master ではない
- **キャッシュが持つのは公開済みの accession だけ。** 下書きを作る経路はキャッシュを読まず、その場で
  上流を引く
- **更新の単位は source の 4 つで、独立に失敗する。** 失敗した source は前回値を残し、成功した source
  だけを全置換して同じトランザクションで検索用の行を作り直す。今回返らなかった行は消える。source ごとに
  最終試行・最終成功・件数・直近の失敗理由を持ち、`/admin` が出す
- **申請管理システム DB への接続は read-only を強制し、接続の無い環境ではその 3 つを skip する**

## 日付

**日付は admin が設定するものとして持つ。** 取り下げて出し直すことも同じ番号で更新することもあるので、
操作の記録をそのまま日付にしない。書式は `YYYY-MM-DD`、暦日は JST で切り、言語を持たない。

| 日付 | 決め方 |
|---|---|
| 版の公開日 | 公開の操作で今日を既定に入れ、admin が変えられる |
| 研究の初公開日 / 最終公開日 | 公開版の公開日から導出する |
| `JGAD…` の公開日 / 更新日 | 申請管理システムで公開状態が live になった最初と最後の日 |
| DRA などの公開日 / 更新日 | DDBJ Search が答える 2 つの日付のまま |
| NHA ID のデータセット | そのデータセットを初めて載せた版の公開日を公開の時点で書く。更新日も同じ値 |

**行の `updated_at` は日付の源ではない。** 版の `updated_at` は公開した時刻で、語彙の統合で content が
書き換わっても動かない。サイトコンテンツの表の `updated_at` は変更のたびに書く。**上流が master の日付は content に持たない。** 出所を 2 つにしないため。上流の日付をポータル側で
補正もしない。**NHA ID のデータセットは日付を 1 つしか持たない** — 版管理しないので「更新」と呼べる
出来事が無い。一度入った値は後の公開が触らない。

## 持たないもの

| 持たないもの | 理由 |
|---|---|
| データセットの履歴 / experiment の版 | 記述の訂正は履歴ではない。pin する対象が 1 段増える |
| experiment の行 | content の中の要素で足り、集計は検索用の行が引き受ける |
| `versionIds` / `latestVersion` のような二重管理 | 台帳と版の行から導出できる |
| 文の中の見出し・表・箇条書き・強調・生 HTML | 実データでほぼ使われておらず、持たなければ許す集合が型そのものになる |
| 申請の中身 (氏名・連絡先・住所) | 個人情報を抱えない。要るときは上流を直読みし、キャッシュしない |
