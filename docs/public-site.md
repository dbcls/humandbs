# 公開サイト

読者がログインせずに開く画面について、URL・言語・公開範囲・研究とデータセットのページ・検索と絞り込みの意味・書き出し・カート・検索エンジンへの見せ方の決まりをまとめる。語の意味は [concepts.md](concepts.md) にある。画面の見た目は `app/routes/` と部品のコードにあり、ここには書かない。機械向けの JSON は [public-api.md](public-api.md) で、同じ公開範囲を別の形で返す。記事とお知らせは [site-content.md](site-content.md) にある。

## URL

URL の形は旧ポータルと同じにしている。外部には HTML ページとファイルの URL が書き込まれており、形を変えても得るものが無いためである。

- 到達できることを保証するのは、研究のページ (`/research/{研究 ID}` と、バージョンを指定する `/research/{研究 ID}/v{n}`)、研究 ID だけの `/{研究 ID}`、記事の `/{slug}` である。DDBJ Search は `/{研究 ID}` でリンクを作り、外部のデータ提供の metadata はガイドラインの slug を書き込んでいるためである。
- ファイルの URL は保証しない。形は変えないが、公開するかどうかは admin が切り替える ([files.md](files.md))。
- 一覧 (`/research` と `/dataset`) は公開検索そのもので、検索・並び順・件数・ページはすべてクエリで表す。URL の一覧は `app/routes.ts` にある。
- 記事の URL はすべてのパスを受ける route (`app/routes/document.tsx`) が受け、記事を探す前に研究 ID と旧ポータルの URL (`-v{n}` `-latest` `-release` 付き) を解決する。画面の URL (`app/public/urls.ts` の `SCREEN_PATHS`) と同じ slug の記事は作れない。
- リダイレクトはサーバーで返す。JavaScript を実行しないクライアントでもリダイレクトされるようにするためである。
- secondary の ID ([concepts.md](concepts.md) の「ID の割り当て」) で開くと、primary の ID の URL へリダイレクトする。古いデータセット ID と訂正前の研究 ID は、記事の本文や申請書に書かれていて書き換えられないためである。大文字と小文字だけが違う表記も、その表記どおりの ID が無く 1 つに決まるなら、primary の ID の URL へリダイレクトする。
- バージョンは `v` と先頭に 0 の付かない番号の 1 通りの表記だけを受ける。`v01` は 404 になる。1 つのページの URL を 1 つにするためである。
- 公開されていないものと存在しない ID は、どちらも同じ 404 を返す。区別できると、未公開の研究があることが外に分かってしまうためである。

## 言語

日本語の URL には言語の prefix を付けず、英語の URL は `/en` の下に置く。

- 日本語に prefix を付けると、既に外部に書き込まれた URL のすべてにリダイレクトが挟まる。`/ja/…` は prefix の無い URL へリダイレクトし、1 つのページの URL を 1 つにする。
- `/ja/` のあとのパスは読者が書けるので、リダイレクト先はログイン後の戻り先と同じ検査を通し、サイト内のパスに限る ([auth.md](auth.md))。`/ja//example.com` はデコードすると `//example.com` になり、別のホストを指すためである。サイトの外を指すものはトップページへ移る。
- 言語は URL だけで決め、cookie も `Accept-Language` も見ない。誰が開いても同じページが表示されるようにするためである。言語の切り替えは、今見ているページの別の言語の URL へ、クエリを付けたまま移る。
- 研究とデータセットで翻訳の無い値にもう一方の言語を使うときは、ページの上部に 1 度だけ表示する。欄ごとにマークを付けると、英語がまったく無いページがマークだらけになるためである。記事とお知らせはフォールバックせず 404 になる。
- クエリの表記は `normalizeQuery` で 1 通りに揃える。`,` `:` `(` `)` はクエリの中で符号化してもしなくてもよい文字なので、同じ URL がブラウザとサーバーで違う文字列になり、揃えないと hydration の結果が食い違うためである。
- 管理画面は日本語だけで、言語の prefix は無い。`/en/admin/…` は存在しない。扱う値は日本語と英語の両方である。

## 公開範囲

研究とデータセットの公開範囲は、検索用の行 (`search_doc`、[data-model.md](data-model.md)) だけから決める。

- 一覧、研究とバージョンのページ、データセットのページ、カートの行、書き出し、JSON API のすべてが同じ行を読む。取り下げたバージョンと削除したデータセットは、行が消えた時点でどこにも表示されなくなる。
- バージョンのページに並ぶデータセットの一覧はそのバージョンのもので、各データセットの内容は最新のものである。過去のバージョンのページでは、そのことを表示する。削除したデータセットは並ばない。
- リリース情報の「追加されたデータセット」は、隣り合う公開中のバージョンどうしの差である。取り下げたバージョンは比較に使わない。読者が開けないバージョンとの差を見せないためである。
- 関連論文が他の研究のデータセットを指定しているときは、公開されているものだけをリンクにする。ID の割り当て表に無い ID は、書かれた文字列のまま表示する。制限公開データの利用者一覧のデータセット ID も、公開されているものだけをリンクにする。申請管理システムは、あとで公開をやめたデータセットの利用も記録に残すためである。

## 研究とデータセットのページ

研究とデータセットのページに何をどう並べるかの決まりである。

- 制限公開データの利用者一覧の節は、利用者が 0 件でも表示する。0 件であることが、まだ誰も利用していないという情報になるためである。ただし、データセットが無いバージョンと、すべてのデータセットが非制限公開のバージョンでは表示しない。非制限公開のデータには利用申請が要らず、この一覧に載る利用者がいないためである。
- データセットのページには secondary の ID を「Secondary ID」として表示する。古い ID で開いた読者が、同じデータセットだと確かめられるようにするためである。研究のページのデータセットの表には表示しない。
- データセットのページには、DDBJ Search に entry のあるデータセット (JGAD と、`app/upstream/archive.ts` の接頭辞の ID) に「DDBJ Search」の項目を表示し、その entry を別のタブで開くリンクにする。登録の詳細はアーカイブにあり、ポータルには無いためである。ポータルが発行した NHA ID のデータセットには表示しない。
- データセットのページの上の欄には、データの種類などと並べて総データ量とファイル形式を表示する。ファイル形式は語彙の表示名のチップで、リンクにしない。どちらもデータセットのファイルから出す値で ([catalog.md](catalog.md) の「キーが無いもの」)、admin は入力しない。
  - NHA の総データ量は、非制限公開ファイルの節と同じ研究ごとの prefix の一覧から、紐づけたファイルの大きさを足す。ファイルストアから応答が無いときは総データ量の項目を表示しない。NHA のファイル形式は紐づけたファイルの名前から出すので、ファイルストアから応答が無くても表示する。
  - アーカイブのデータセットは、取得元にファイルが無いときに 2 つとも項目ごと表示しない。
  - 0 と表示しないのは、ファイルが無いことと区別できないためである。
- 解析手法の値のうち、`材料と対象者`・`試料説明` の文から読み取った短い分類は、その文の下に項目名と値のチップで並べる。`材料と対象者` の下は健康状態・対象者数・対象者数の数え方・コホート・対象集団・性別・年齢層、`試料説明` の下は組織・腫瘍 / 非腫瘍で、対象者数と数え方は 1 つのチップ (`対象者数 96 (人数)`) にする。絞り込みのために型を付けた値は文と同じ内容なので、行として並べると同じことを 2 回読ませるためである。文が無い解析手法でも、項目名 (`材料と対象者`) だけの行の下にチップを並べ、行は最初のチップの項目の位置に置く。文の有無でチップの見た目を変えないためである。疾患・細胞株・測定と解析の値 (実験方法・プラットフォームなど)・数値は、文に無いことを含むか長いため、行のまま表示する。チップはリンクにしない。
- 選択肢の項目 (データの種類と、解析手法の試薬キット・プラットフォームなど) に値が複数あるときは、1 行に 1 つ並べる。一覧の表のデータの種類の欄も同じである。試薬キットやプラットフォームの名前は空白を含むので、読点でつなぐと 1 つの値がどこで終わるかが読み取りにくいためである。チップの中の値だけは、チップを 1 行に収めるために「、」(英語のページは `, `) でつなぐ。

### 非制限公開ファイルの節

非制限公開ファイルの節は、公開の bucket にある研究ごとの prefix の一覧である ([files.md](files.md) の「2 つの bucket と研究ごとの prefix」)。

- データセットのページでは、そのうちデータセットに紐づけたものだけを並べる。各行にはファイルのラベル ([files.md](files.md) の「ラベル」) を添える。ファイルストアから応答が無ければ節ごと表示しない。ページの他の部分をファイルストアの可用性に左右させないためである。
- 節のページは `?files=` で表し、1 ページの件数は 20・50・100 から `?fileRows=` で選ぶ (既定の 20 は URL に書かない)。一覧と違って「すべて」は無い。1 万件を超える研究があり、まとめて取得するには URL の一覧のダウンロードがあるためである。
- ページ送りと件数の選択はスクロールの位置を変えず、ブラウザの履歴を置き換える。節はページの途中にあるので、先頭に戻すと読んでいた表を探し直すことになり、履歴を積むと戻るボタンで前の画面に戻るまでに節のページを 1 つずつたどることになるためである。
- 節の見出しの行の「URL の一覧のダウンロード」は、節のすべてのファイルの URL を 1 行に 1 つ並べたテキスト (`/research/{研究 ID}/files.txt`、`/dataset/{データセット ID}/files.txt`) である。`wget -i` などでまとめて取得するためのもので、zip にまとめて配らないのは、研究のファイルが数百 GB になるためである。ファイルストアから応答が無いときは空の一覧ではなく 503 を返す。空の一覧は、ファイルの無い研究と区別できないためである。
- 表の各行の「URL のコピー」は、そのファイルの URL をコピーする。URL の一覧と同じく、ポータルの公開のアドレスの完全な URL である。
- URL の一覧とコピーは共有リンクのプレビューには無い。ファイルがまだ公開されていないためである。

### 研究の内容のリンク

研究の内容の書式付きテキストは構造のまま描画し、HTML の文字列は作らない。リンク先は描画の時点で検査する。

- リンクにするのは `http` `https` `mailto`、このサイトの中の絶対パス、ページ内の `#…` だけで、それ以外は文字列として表示する。研究の内容は保存のときにリンク先を検査しないので、ここが唯一の検査になる。
- 検査するのは文字列の先頭ではなく、ブラウザと同じ規則で解決したリンク先である。ブラウザはタブと改行を取り除き、`\` を `/` として扱うので、`/\host` は別のホストを指す。制御文字か `\` を含むリンク先はリンクにしない (`app/content/richtext.ts`)。

## 検索式

一覧は公開検索そのもので、研究の一覧は研究の行を、データセットの一覧はデータセットの行を検索する。バージョンの行は検索しない。同じ研究がバージョンの数だけ並んでしまうためである。

### 検索窓

検索窓に入力するのはキーワードで、検索式ではない。項目の条件は URL と絞り込みから指定する。

- 空白で区切るとすべてを含むもの、カンマで区切るとどれかを含むもの、`"..."` で囲むとその並びのままのものを探す。
- 研究 ID とデータセット ID は、secondary の ID でも引ける。論文や申請書に書かれた古い ID で探せるようにするためである。
- JGAD のデータセットとその研究は、データセットのページに表示する JGAS の ID でも引ける。JGAD の無い JGAS はどのページにも表示しないので引けない。
- JGA の ID (JGAS・JGAD・JGAC・JGAP) は、数字の先頭に 0 を足して 6 桁より長くした表記でも引ける。`JGAS00000000197` は `JGAS000197` として探す。JGA の登録データと DDBJ Search には数字 11 桁の表記もあり、それで探す人がいるためである。数字が 6 桁より短い語 (`JGAS0001`) は、途中まで入力した語としてそのまま探す。`?q=` の語と `id:` の値でも同じで、JSON API の検索にも適用される。
- 検索窓の送信は `k` パラメータで送られ、そこから作った検索式を `?q=` に書いた URL へリダイレクトする。1 つの検索が 1 つの URL になり、共有でき、JavaScript が無くても動くようにするためである。記号を含む語 (`NGS(Exome)`) は引用符で囲んで 1 語として扱う。

### `?q=` の検索式

`?q=` は検索式で、解釈は `app/search/dsl.ts` の 1 か所で行う。JSON API も同じ処理を通る。

- 絞り込みの条件は `項目のコード:語彙の値のコード` (`platform:hiseq-2500`) と書く。ID や表示名ではなくコードを使うのは、表示名を変えても URL の意味が変わらないようにするためである。
- 項目を指定しない語と `title:` の値は部分一致で探す (`genom` は genome にも当たる)。末尾の `*` は外して探すので、`canc*` と `canc` は同じ結果になる。`*` で前方一致を指定できるのは `id:` だけで (`id:hum00*`)、`*` の前に 2 文字以上が要る。
- `-` と `+` は語の一部として探す。`-cancer` は cancer を含まないものではなく、「-cancer」を含むものを探す。遺伝子名 (`HIF-1`) などを書いたまま探せるようにするためで、除外は `NOT` で書く。
- 範囲は `key:[下限 TO 上限]` と書き、片側だけなら `*` を使う (`read-length:[100 TO *]`)。両端が空なら条件ごと無くなる。
- ICD10 のコードは、点の有無と大文字小文字を区別せずに照合する。3 桁のコードは配下の 4 桁のコードにも当たり、4 桁のコードはそのコードだけに当たる。他の語彙の値のコードも大文字小文字を区別しない。
- 値は DB が受け付けられる形だけを解釈する。日付は実在する `YYYY-MM-DD` で年は 0001 から 9999 まで、数は先頭に 0 の付かない 10 進数だけである (`0x10` や `1e3` は解釈しない)。それ以外は解釈できない検索式になる。
- 解釈できない `?q=` では、結果を表示せずに解釈できなかったことを表示する。
- 適用中の条件は、検索窓に入力した語も含めて 1 行に並べ、1 つずつ外せる。この並びは `?q=` の検索式から作るので、並びに無い条件が適用されていることは起きない。「すべて解除」は検索窓も空にする。

## 絞り込み

絞り込みの状態は URL に載る。値を選ぶことと外すことは同じリンクで、絞り込みの部品には状態が無い。範囲の指定は GET の form で送り、URL へのリダイレクトで返す。どちらも並び順と件数 (`?sort=` `?order=` `?size=`) を引き継ぐ。

- 各値の件数は、その絞り込み項目自身の条件だけを外した集合で数える。全条件で数えると、1 つ選んだ時点で同じ項目の他の値が 0 件になり、複数を選べなくなるためである。
- 0 件の値は表示しないが、選んでいる値は 0 件でも表示する。外す手段を無くさないためである。値が 1 つも無くなっても、項目の見出しは残す。
- 項目の並びは、日付の範囲 (公開日・更新日) が先で、そのあとは絞り込みのカテゴリ ([concepts.md](concepts.md)) と項目定義の順である。値の並びは件数の多い順である。範囲の項目には件数を表示しない。
- 研究の一覧での絞り込みは、「配下のどれかのデータセットが条件を満たす」という意味である。2 つの条件をそれぞれ別のデータセットが満たしていても、その研究は当たる。
- ICD10 は 3 桁のコードだけを並べ、4 桁のコードは 3 桁に丸めて数える。同じ 3 桁の下に複数のコードがある疾患は 1 回だけ数える。
- 日付の「直近 1 / 5 / 10 年」は、絶対の日付の下限として URL に載せ、上限は付けない。相対のまま載せると、同じ URL の意味が日ごとに変わるためである。
- 値の一覧を絞る入力欄、項目の開閉、絞り込み欄を閉じたかどうかは URL に載せない。検索結果を変えないためである。範囲の入力だけは JavaScript が要り、それ以外は JavaScript が無くても使える。

## 並び順と件数

一覧の並び順とページ分けの決まりである。

- 並び順は更新日・公開日・ID の 3 つで、既定はどちらの一覧でも更新日の新しい順である。既定と違う向きのときだけ `?order=` を付け、並び順の項目を選び直すと向きはその項目の既定に戻る。同じ値の行の順は日付と ID で固定する。順が揺れると、ページをめくったときに同じ行が 2 回表示されるためである。
- 関連度の並び順は無い。スコアは全文検索の語を含む検索にしか定まらないので、絞り込んだだけで並び順の選択肢が変わってしまうためである。
- 日付の無い行は、向きにかかわらず最後に並べる。
- 1 ページの件数は 20・50・100・すべて から選び (`?size=`、すべては `?size=all`、既定の 20 は URL に書かない)、解釈できない `?page=` は 1 ページ目として扱う。admin の一覧も同じ選択肢である。件数を選ぶと 1 ページ目に戻る。検索窓、並び替え、ページ送り、絞り込み、言語の切り替えは、どれも件数を引き継ぐ。JSON API は 20 件で固定である。
- 0 件でも一覧の画面のままで、表と絞り込みを残す。条件を緩めた検索や入力方法の案内は表示しない。外し方の数だけ検索することになり、案内しないと決めた検索式の文法を見せることになるためである。

## 書き出し

一覧に表示している検索の結果を、`/research/export` と `/dataset/export` からファイルとクリップボードに書き出せる。

- 書き出すのは全件で、表示しているページだけではない。列は画面の表からカートの列を除いたものである。
- 形式はタブ区切りで、引用符で囲まない。カンマは 1 つのセルに複数の値を並べるのに使うためである。値の中のタブと改行は空白にする。
- ファイルは BOM で始め、クリップボードへのコピーには付けない。BOM が無いと、表計算ソフトが UTF-8 として読まないためである。
- 表計算ソフトが数式として扱う文字 (`=` `+` `-` `@` など) で始まる値には `'` を前に付ける。表計算ソフトで開かれることを前提にした形式なので、数式として評価されないようにするところまでを書き出しの責任とする。機械で処理する場合は JSON API を使う。

## カート

制限公開データの利用申請は JGA の申請システムで行う。ポータルのカートは、申請書に書くデータセットの accession を集めるためのもので、`/cart` から JSON 1 つとして取り出せる。

- カートの中身はブラウザの `localStorage` にだけ保存する。サーバーには保存せず、アカウントとも結び付けない。ブラウザを閉じても残るので、1 回の操作で空にできるようにしている (共有端末で前の人の中身が残るため)。
- カートに入れられるのは JGAD のデータセットだけである。非制限公開のデータには申請が要らず、ポータルが割り当てた ID は申請システムでは使えないためである。
- カートに入れられるのは 500 件までである。押すと 500 件を超えるときは 1 件も入れず、上限を知らせる。表の行は accession を並べたアドレスで取るので、件数が多いとアドレスの長さの上限 (8 KB) を超えて表を表示できなくなるためである。研究の行のボタンが一部だけを入れることはしない。
- カートの中身は URL に載せない。行は `/cart/rows` に accession を送り、サーバーが検索用の行から作る。取り下げられたものは行にならず、送った accession は応答にも含めて返す。
- 研究の行のカートボタンは、その研究の JGAD のデータセットをまとめて扱う。押すとまだ入っていないものを入れ、すべて入っていればカートから外す。

## 検索エンジンとリンクのプレビュー

公開ページは、人が読むほかに、検索エンジンとチャットのリンクのプレビューにも読まれる。データを探す人が Google Dataset Search などからデータセットを見つけられるようにするためである。

- 研究とデータセットのページには、schema.org の `Dataset` を JSON-LD で埋め込む。研究は題目・研究の目的・研究 ID・バージョン番号とその公開日・提供者・助成の機関・関連論文・配下のデータセットを、データセットは ID・データの種類・解析手法・アクセス制限・公開日と更新日・総データ量・ファイル形式・所属する研究・非制限公開のファイルを書く。書くのはページに表示している値だけで、言語はページの言語である。未確定の値と該当なしの値は書かない。
- 研究とデータセットのページには、説明文 (meta description) と OGP を付ける。研究の説明文は研究の目的の先頭、データセットの説明文はデータの種類・解析手法・アクセス制限を並べたものである。検索結果とリンクのプレビューに表示される。
- バージョンのページ (`/research/{研究 ID}/v{n}`) には、説明文と OGP だけを付け、`og:url` はそのバージョンの URL にする。JSON-LD は付けない。付けると同じ研究が最新のページと各バージョンのページで別の `Dataset` として検索エンジンに読まれてしまい、sitemap にバージョンのページを並べない理由と同じ問題になるためである。
- 両方の言語が必ずあるページ (研究・データセット・一覧・画面) は、日本語と英語のページを互いに alternate (`hreflang`) で示し、既定を日本語にする。記事とお知らせは、片方の言語だけで公開していることがあるので、ページでは示さず sitemap で示す。
- `/sitemap.xml` に、トップ・一覧・公開中の研究とデータセット・公開中の記事とお知らせのページを、公開している言語ごとに並べる。最終更新日と、同じページの別の言語を添える。バージョンのページは並べない。最新の内容は研究のページにあるためである。robots.txt が sitemap の場所を示す。
- `.env` の `HUMANDBS_NOINDEX` を `true` にした配置は、すべてのページに noindex を付け、robots.txt で API (`/api/`) と API の説明のページが読むファイル (`/swagger-ui/`) のほかのクロールを拒否し、`/sitemap.xml` を 404 にする。staging には本番と同じ内容があるので、検索結果に本番と並んで出ないようにするためである。API と説明のページはプログラムが読むためのものなので、robots.txt に従う agent も読めるようにする。

## やっていないこと

- ICD10 のコードの入力欄と、疾患名の入力補完。疾患の呼称には表記の揺れがあり、候補が乱れる。全文検索と絞り込みで足りる。
- ID を入力したときの、完全一致した結果を別の欄に分ける表示。全文検索の結果として並べる。研究 ID だけの URL はリダイレクトで受ける。
- 絞り込みの「不明」。未確定と該当なしは、集計にも検索にも含めない。
- Excel 形式の書き出し。表計算ソフトはタブ区切りを読める。
- 本番での robots.txt によるクロールの拒否。公開ページは読まれるために公開している。未公開のものはトークンが無ければ読めず、応答に `noindex` を付けている。
- citation の meta (`citation_*`)。論文を索引するためのもので、ポータルのページは論文ではない。
- ページ遷移中のスケルトン表示。表示すると画面がちらつく。
