# 編集

admin が研究の内容を下書きとして書き、レビューを受けるまでの決まりをまとめる。下書きを公開してバージョンにする流れは [publishing.md](publishing.md)、記事とお知らせの編集は [site-content.md](site-content.md)、誰がどの操作をできるかは [auth.md](auth.md) にある。編集するのは admin だけである。提供者 (データ提供者と、その確認を頼まれた人) はアカウントを使わず、共有リンクからプレビューを読んでコメントを書く。

## 下書き

下書きは、研究の未公開の作業コピーである。公開した内容はバージョンとして別に保存されるので、下書きを履歴としては使わない。

- 1 つの研究に下書きを複数作れる。同じ研究の下書きは、admin が付ける下書き名で見分ける。
- 下書きには、研究の内容、admin だけが読むメモ、下書きの中で書いたデータセットの内容、その下書きで作成したデータセットを置く。データセットの内容を下書きごとに分けるのは、並行する 2 つの下書きで、同じデータセットを別の内容で書けるようにするためである。
- 下書きに値を入れる方法は、フォームに入力することと、取り込むことの 2 つだけである。公開ページに直接書き込む方法は無い。バージョンのコピー、申請からの研究の作成、公開中のバージョンの更新では、取り込み元の値をそのまま入れた下書きを作る。結果は、空の下書きにすべてを取り込んだのと同じになる。どこからコピーしたかは記録せず、取り込み元は取り込みのたびに選ぶ。
- 保存のときに必須項目の検査はしない。未確定の項目を残したまま保存して共有するのが、普通の作業の状態だからである。検査は公開のときだけ行う。
- 下書きが変わるのは、明示的に保存したときだけである。自動保存も元に戻す機能も無い。入力の途中で下書きが変わると、レビューの最中に共有リンクのプレビューが変わってしまうためである。
- 公開すると下書きは消える。同じ内容がバージョンと下書きの両方に残ると、どちらが正しいのか決められないためである。続きを書くときは、バージョンから新しい下書きを作る。

### 下書き名

下書き名は、同じ研究の下書きを admin が見分けるための名前で、研究の内容とは別に保存する。

- 下書きができたとき (作成・バージョンのコピー・申請からの研究の作成・取り下げ) の下書き名は「v{公開中のバージョンの最大の番号 + 1} 予定」である。バージョンの無い研究では「v1 予定」になる。admin は、研究の内容の編集画面の上部の入力欄で下書き名を変えられる。下書き名は空にできない。
- 下書き名はバージョン番号とは関係しない。下書きにはバージョン番号が無く、番号は公開のときに決まる。そのため、別の下書きを先に公開すると、下書き名の番号と公開の番号はずれる。
- 下書き名は admin の画面にだけ表示し、共有リンクのプレビューには表示しない。研究の画面の表では、バージョンの行の番号と同じ列に下書き名を表示する。公開中のバージョンの更新の下書きには下書き名が無く、元のバージョンの番号で示す。

### 公開中のバージョンの更新

公開中のバージョンを直す操作を「更新」と呼ぶ。更新のあいだも、そのバージョンは公開されたままである。

- admin がバージョンの「編集」を押すと、そのバージョンの内容をコピーした下書きが作られる。admin は、更新中の内容をこの下書きに書く。画面では、この下書きを下書きの一覧に並べず、元のバージョンを「更新中」と表示する。
- 1 つのバージョンにつき、更新の下書きは 1 つだけ作れる。更新中のバージョンは取り下げられないので、取り下げたいときは先に更新を中止する。
- 更新を公開すると、同じ番号のバージョンの内容が入れ替わる。直しているあいだ公開ページから消す方式は採らない。読者から見ると、取り下げと区別が付かないためである。

## 同時編集と保存

複数の admin が同じ下書きを同時に開いてもよい。ロックはせず、保存するときに、相手の変更と衝突していないかを確かめる。

### 更新番号による照合

下書きと、下書きごとのデータセットの内容には、それぞれ更新番号 (保存のたびに 1 増える整数、コード上は `revision`) がある。保存では、画面を開いたときの更新番号と今の更新番号を比べる。

- 研究の内容は下書きの更新番号で、データセットの内容 (解析手法を含む) はそのデータセットの内容の更新番号で照合する。1 つの研究に 200 を超えるデータセットが付くことがあり、1 か所の衝突で全体を保存できなくなるのを避けるためである。
- データセットの追加・削除・並べ替えは研究の内容を変えるので、下書きの更新番号で照合する。
- 行の書き換えは `WHERE id = ? AND revision = ?` で行い、一致する行が無ければ 409 を返す。データセットの内容を初めて保存するときは「無ければ挿入する」で行い、挿入できなかった保存が 409 になる。
- 複数の行を書き換える保存では、1 つのトランザクションで全部を照合し、1 つでも一致しなければ全体を取り消す。
- 下書きの削除でも更新番号を照合する。画面を開いたあとに誰かが編集した下書きは、削除できない。
- 更新番号に PostgreSQL の `xmin` は使わない。VACUUM FREEZE で値が変わるためである。
- 下書きへの書き込みは、公開の処理も含めて、すべて `app/admin/drafts.server.ts` の関数を通す。既存の行を変える関数は、どれも更新番号を必須の引数に取る。DB のトリガでは照合を強制できない (照合の条件を書き忘れた書き換えでも、更新番号を 1 増やせば正しく見えてしまう) ので、関数の引数の形で強制している。
- 共有リンクの設定と下書き名の変更では、更新番号を照合しない。どちらも研究の内容の変更ではないので、照合すると、共有を切り替えたり下書き名を変えたりしただけで、編集中の人の保存が 409 になってしまう。

### 衝突と入力の検査

- 保存が 409 になった画面では、相手が変えた箇所を表示し、自分が入力した値は消さない。ページを自動で読み直すこともしない。
- 差分は、画面を開いたときの内容と今の内容から、画面側で計算する。変わった項目は、取り込みと同じ比較のダイアログ (この画面の入力・別の場所で保存された値・保存する値) で、保存する値を決める。ダイアログは、衝突のバナーの「比較と取り込み」で開く。変わった欄の「取り込み」からは、その項目の位置で開く。相手の値を無条件に採用する操作は無い。同じ欄に 2 つの取り込み方があると迷うためである。
  - 保存する値の初期値は、画面を開いてから自分が変えていない項目は相手の値、自分が変えた項目は自分の値である。要素の一覧は要素ごとに決める。どちらかが足した要素は残す。一方が消した要素は、もう一方が変えていなければ消す。
  - この画面で書けない値 (研究の内容のデータセットの並び、データセットの公開日) は、相手が変えていれば相手の値にする。別の画面で作成・並べ替えたデータセットを、この画面の保存で元に戻さないためである。
  - 決めた値はフォームに入り、サーバーには通常の保存で送る。保存で送る更新番号は、409 の応答で受け取った今の番号である。
- 項目の場所を表す文字列 (パス) は `app/admin/paths.ts` の 1 種類だけを使う。コメントの付け先、衝突の差分、取り込みの差分、プレビューの「変更あり」のバッジが同じ表記を使い、配列の要素は位置ではなく要素の ID で指す。並べ替えで指す先がずれないようにするためである。
- 自分が何も変えていないときに、差分に含まれるパスを全部相手の値にすると、差分は空になる。差分が空になることは型では保証できないので、テストで確かめている。
- 形の合わない送信には 400 を、更新番号の不一致には 409 を返す。項目定義に無いキー、型の違う値、別の語彙の値は、フォームからは送られない入力なので 400 にする。
- 項目の状態を「未確定」などに切り替えても、入力途中の値は画面に残る。保存の時点で状態が値のある状態でなければ、入力途中の値は保存しない。
- 状態を切り替えた項目には、入力欄の代わりに状態を表示する。該当なしは、公開ページと同じ `N/A` と表示する。要素の一覧の表では、未確定の値のセルには何も表示せず、行の最初のセルの「未確定」のバッジで示す。同じ行に同じ語を 2 度表示しないためである。
- 「未翻訳」は利用者が選ぶ状態ではなく、値から自動的に決まる ([data-model.md](data-model.md))。
- 数値欄が空のときは、その項目の値を保存しない。数値には「空の値」が無いためである。

## 編集画面と公開ページ

編集画面では、フォームの隣に、その下書きの公開ページを表示する。

- 公開ページの表示には、公開サイトやプレビューと同じ関数を使う。表示の方法を増やさないためである。
- フォームの要素の一覧 (提供者・研究プロジェクト情報・助成金情報・関連論文・一覧の行の研究代表者) の表も、セルを公開ページの同じ表と同じ部品で描く。該当なしは `N/A`、URL と DOI はリンク、データセット ID はアイコン付きになる。フォームの表と公開ページの表が違って見えると、公開したときの見え方をフォームで確かめられないためである。違うのは未確定の値のセルだけである。未確定の値のセルには何も表示せず、行の最初のセルのバッジで示す ([衝突と入力の検査](#衝突と入力の検査))。
- フォームの欄は、どれも公開ページか一覧の行のどこかに表示される。公開ページに表示しない値 (ORCID、メールアドレス、住所) は、研究の内容に入れない。
- 公開ページと一覧の行の値を押すと、フォームのその項目へ移って入力欄を強調する。英語の公開ページの値を押したときは、その項目の英語の入力欄へ移る。逆に、フォームの項目にカーソルがあるあいだは、公開ページと一覧の行の対応する値に、フォームの入力欄の強調と同じ色を付け、対応する値をペインの中央に寄せる。2 つのペインを行き来しても、どこを書いているかを見失わないためである。
  - 公開前の確認で、未確定の値・未翻訳の項目の場所の一覧から編集画面を開いたときも、その項目の入力欄 (未確定・未翻訳の言語のほう) へ移る。
  - 未確定・該当なしにした項目には入力欄が無いので、押されている状態のボタン (押すと解除して入力欄に戻る) へ移って強調する。
  - 一覧の行で押して移れるのは、フォームで書く列 (研究題目・解析手法・データの種類・参加者・提供者) だけである。ID・プラットフォーム・アクセス制限・日付からは移れない。提供者の列には、一覧の行の提供者を書いていないときに、研究代表者の名前を表示する。提供者の列を押すと、研究代表者の名前を表示しているときも、一覧の行の提供者へ移る。
  - 一覧の行の項目は、行の列と同じ順にフォームに並べる。
- 未確定の欄や空の節も、見出しと場所を残して表示する。下書きを埋める人が、どこを埋めればよいか分かるようにするためである。
- データセットの項目のキーは項目定義から選ぶ。編集画面で新しいキーを作ることはできない。
- 総データ量とファイル形式には入力欄が無い。どちらもデータセットのファイルから出す値で ([catalog.md](catalog.md) の「キーが無いもの」)、隣の公開ページには表示する。NHA では、ファイルの紐づけを変えると公開ページの値も変わる。まだ値の無いときの表示は、下の「共有リンク」のプレビューと同じである。
- 選択肢の項目のうち値を 1 つしか選べない項目は、選んだ値を入力欄の中に表示し、別の値を選ぶと置き換わる。値を複数選べる項目は、選んだ値をチップで並べ、入力欄 (「選択肢の追加」) で足す。選ぶ前に、入力欄の形で 1 つか複数かが分かるようにするためである。
- 解析手法の項目には、項目名の横に、解析手法の表と同じ型のバッジ (選択肢・数値・疾患) を表示する。単位は付けない (数値の入力欄の横に単位がある)。自由文の項目にはバッジを付けない。受け付ける記法 (「リンクと改行」) の表示で、自由文の項目だと分かるためである。
- 数値の欄には、行ごとに Prefix と Suffix の入力欄 (言語ごと、`Prefix ja` など) をいつも表示する。数値だけの行にも、あとから書き足せるようにするためである。前後の空白も値の一部として保存し、空白だけの欄は空として扱う。
- 語彙の欄は、語彙の大きさにかかわらず同じ形である。入力した文字列をサーバーに送り、候補を受け取る。
- 疾患の欄には、ICD10 のコードを入力しても、選んでもよい。分類に無いコードには、末尾を削った上位のコードを候補に表示する。疾患の呼称の欄には候補を表示しない。選んだ疾患は、公開サイトの絞り込みと同じく、ICD10 のコードと見出し語で表示する。
  - コードの入力欄の下の「範囲で追加」を押すと、コードの入力欄が下限と上限の入力欄に替わり、ボタンは「1 つずつ追加」になる。もう一度押すと、コードの入力欄に戻る。下限と上限に同じ桁数 (3 桁か 4 桁) のコードを入力すると、範囲 ([catalog.md](catalog.md) の「疾患 (ICD10)」) にあるコードのうち、まだ選んでいないものの数を追加のボタンに表示し、押すとまとめて追加する。下限か上限がコードの形でないとき、桁数が違うとき、上限が下限より小さいときは、追加のボタンを押せず、理由を表示する。`C00-C80` を、約 70 個のコードを 1 つずつ選ばずに入力できるようにするためである。
  - 範囲で追加したコードも、チップは 1 つのコードに 1 つ表示し、1 つずつ削除する。範囲の中の 1 つだけを外せるようにするためである。公開ページの表示では範囲にまとめる ([public-site.md](public-site.md) の「研究とデータセットのページ」)。

## 取り込み

取り込みは、他の内容と今の下書きを比べ、違う項目ごとに、入れる値を人が決める操作である。

- 取り込み元は 3 種類ある。この研究の公開済みバージョン、同じ研究の他の下書き、データ提供申請の枝番である。取り込み先の下書き自身は取り込み元に選べず、サーバーも拒否する。
- 取り込み元は、下書きと同じ形に変換してから比べ、違う項目だけを表示する。各項目は「現在の下書き」「取り込み元」「保存する値」の 3 行で表示する。保存する値は自由に書き換えられる。どちらでもない値を書くことがあるので、2 つから選ぶだけの形にはしない。
- 保存する値の初期値は、取り込み元の値にする。ただし、取り込み元が空の項目は、下書きの値を初期値にする。取り込み元が空であることは、「空にせよ」という意味ではないためである。
- 配列は、要素ごとに残すかどうかを選ぶ。初期値では、両方の要素を残す。
- データセットの一覧と並び順は取り込まない。どのデータセットを公開するかは、研究側で決めるためである。
- 取り込みを始める前に、下書きを保存させる。取り込みの確定は、通常の保存と同じ検査と更新番号の照合を通る。
- 公開のときに、取り込み元の値を自動で混ぜることはしない。提供者がプレビューで確認した内容を、そのまま公開するためである。

## 申請から研究を作る

研究の内容は申請書に、データセットの ID は申請管理システムや DDBJ Search に既にある。手で入力し直さずに、申請書・申請管理システム・DDBJ Search の値を読んで下書きを作れる。

- 入力は 3 種類ある。
  - J-DS の承認済みの枝番からは、研究の内容と登録済みの JGAD のデータセットを作る。値は、申請管理システムから取得したキャッシュから読む。
  - JGAD からは、データセット 1 件を作る。値は、申請管理システムから取得したキャッシュから読む。
  - DRA の submission からは、データセット 1 件を作る。値は、DDBJ Search から読む。
- 入力の単位は J-DS の枝番である。枝番 1 つが登録 1 回に当たり、研究 ID が付くのも承認された枝番である。承認のあとからデータセットが追加されるので、同じ枝番から何度でも取り込める。
- 申請管理システムの値は、承認済みのデータ提供申請と JGAD の登録内容のキャッシュ ([upstream.md](upstream.md) の「取得元とキャッシュ」) から読み、申請管理システムには接続しない。申請管理システムが止まっていても下書きを作れるようにするためである。前回の取得のあとに承認された枝番と登録された JGAD は、次の取得のあとに作れる。DRA の submission は、DDBJ Search をその都度読む。
- 値は、確認画面と作成でそれぞれ読む。画面からは「何を作るか」だけを送る。
- 下書きに入れるのは、公開ページに表示する値だけである。研究題目・目的・方法・対象と、研究代表者の氏名と所属を入れ、連絡先・研究分担者・関連論文は入れない。
- データセットは 1 accession につき 1 件作る。解析手法は、JGAD からは 1 件、DRA の submission からはライブラリの strategy ごとに 1 件作る。この研究に既に登録済みのデータセットは作らない。
- 語彙の値は、コードで照合し、コードで見つからなければ英語の表示名で照合する。新しい語彙の値も項目定義のキーも作らない。入力された文字列がそのまま加わると、表記揺れが生まれるためである。疾患はコードだけを入れ、呼称は admin が書く。
- 申請に書かれていた値が選択肢に無くても、作成は止めない。1 つも照合できなかった欄は未確定にし、作成した admin の名前で、その欄にコメント (「申請・登録情報の値「…」は選択肢に無いため、反映していません。」) を残す。申請に値が無い欄は未確定にせず、空のままにする。
- データセットの ID は作成と同時に割り当てる。そのため、この操作には `edit-content` と `manage-labels` の両方の権限が要る。研究 ID は、外部システム側に既にあるときだけ割り当てる。研究 ID と J-DS の対応の正本は申請管理システムであり、ポータルからは書き込まない。
- 取得できなかったものがあれば、一覧で示した上で作成させる。下書きは後から削除できるためである。申請管理システムの値を一度も取得していない環境でもボタンは表示し、取得していないことを画面に表示する。

## レビュー (共有リンクとコメント)

レビューでは、admin が提供者に共有リンクを渡し、提供者がプレビューを読んでコメントを書く。

- 共有リンクは下書きごとに 1 つで、リンクを知っている人は誰でもプレビューを読んでコメントを書ける。人ごとのリンクは作らない。誰が読んだかは、コメントに書かれた名前で分かる。
- 承認の状態は無い。レビューは状態ではなく作業である。「レビュー中は編集できない」とすると、コメントを受けて直す作業そのものが止まってしまうためである。
- 提供者は、コメントを書き終えたときと、修正を確認して直すところが無くなったときに、それぞれボタンを押す。押すたびに記録が残り、admin の画面に表示される。ボタンを押すことは承認ではなく、公開するかどうかは admin が決める。「確認してください」という連絡は人がメールで送り、システムからメールは送らない。
- 共有リンクから書かれたコメントと、提供者が押したボタンは、admin 向けに Slack に知らせる ([publishing.md](publishing.md) の「Slack への通知」)。

### 共有リンク

- 共有は「共有中」と「共有停止」の 2 つの状態で、既定では期限が無い。期限を設定すると、その日の終わり (日本時間) まで有効になる。
- 共有を止めてから再開すると、同じ URL がまた使える。漏れたリンクを無効にするには、URL を再発行する。
- トークンの検証は、ページではなくデータを取得する処理で行う。停止中・期限切れ・再発行前のトークンには、存在しないリンクと同じ 404 を返し、下書きがあることを知らせない。
- 応答に `X-Robots-Tag: noindex, nofollow` と `Referrer-Policy: no-referrer` を付ける。ログイン不要の URL で未公開の内容を見せるので、検索エンジンと Referer からの漏れを防ぐためである。
- プレビューは、公開ページと同じ部品と同じ表示データで描く。違いは次の 3 つである。
  - 未確定の欄は、提供者への問い合わせ (「ご教示ください」) として表示する。
  - admin が欄に書いた未解決のコメントは、「ご確認ください」とコメントの本文を表示する ([コメント](#コメント))。
  - 公開されてから入る値は、「公開後に自動で入ります」と表示する。
- 公開されてから入る値は、データセットのページの総データ量・ファイル形式・公開日・更新日・JGA Study である。アーカイブのデータセットの値は、アーカイブが公開すると取得元から入る。NHA の公開日と更新日は、ポータルで公開すると入る。
  - 値があれば、プレビューにも表示する (JGA で公開済みの JGAD など)。値がまだ無ければ、項目を残して、灰色の破線の枠線に時計のアイコンを付けた小さなバッジで示す。公開ページのように項目ごと消すと、提供者に書き忘れと読まれるためである。
  - このバッジは、問い合わせとは色と大きさを変える。提供者に何かを求めるものではないためである。
  - NHA の総データ量とファイル形式は、紐づけたファイルからすぐに出るので、このバッジを表示しない。JGA Study は JGAD にだけ表示する。
- 公開済みバージョンがあれば、プレビューと編集画面の公開ページでは、比較先 (最新の公開バージョン、更新の下書きなら更新元のバージョン) と違う箇所に「変更あり」のバッジを付ける。フォーム側には付けない。取り込んだあとに書き直した欄に、いつまでも「違う」と表示され続けるためである。
- 問い合わせ (「ご教示ください」) のバッジと、比較先と違う箇所 (「変更あり」) のバッジは、ほかのバッジより一回り大きく、破線の枠線と薄い背景色で表示する。赤は問い合わせ、accent は変更で、形は同じにする。どちらも提供者がページの中から探すものなので、値や見出しに並ぶほかのバッジと見分けられるようにするためである。
- 「変更あり」は、押すと変更の前後を比べるダイアログを開く。公開前の確認の変更点の件数 (「6 項目の変更」「データセットの並び順の変更」) も同じバッジで、押すと、変わった項目ごとに同じ比較を並べたダイアログを開く。

### コメント

- コメントの付け先は、研究の内容またはデータセットの欄と、下書き全体である。文中の範囲を指定するコメントは無く、文中の一部を指すときは、コメントの本文に引用する。admin だけのメモは別の付け先で、共有リンクからは読めず、書けない。
- 付け先の欄が研究の内容に実在するかは、サーバーで確かめる。共有リンクから書けるのは、その下書きに含まれるデータセットまでである。
- 共有リンクで読めるコメントは、表示しているページの付け先のコメントに絞る。それ以外のコメントは、データ取得の結果にも含めない。SSR の HTML に埋め込まれるデータは、リンクを知っている人なら誰でも読めるためである。
- 返信の機能は無く、同じ場所のコメントは書かれた順に並ぶ。解決は、コメントごとに人が付ける。付け先の値を編集しても、自動では解決しない。
- admin が研究の内容またはデータセットの欄に書いた未解決のコメントは、提供者に確認を求めるものとして扱う。値を書いたうえで確かめてほしいこと (論文から取った値、検体数が合わないことなど) を、値を未確定にせずに伝えるためである。
  - プレビューと編集画面の公開ページでは、その欄の項目名の下に 1 行を追加し、「ご確認ください」とコメントの本文を表示する。表示は、問い合わせと同じ赤の破線の枠線と薄い背景色にする。吹き出しのボタンの件数だけでは、何を求められているかが提供者に分からないためである。解決を付けると表示されなくなる。
  - 確認を求めるかどうかをコメントごとに選ぶ設定は無い。admin どうしのやり取りは、admin だけのメモに書く。下書き全体へのコメントは欄を指さないので、「ご確認ください」にならない。
  - admin が書いたかどうかは、表示する時点で、コメントを書いたアカウントが admin かどうかで決める。admin から外したアカウントのコメントは「ご確認ください」にならない。
- 解決と削除ができるのは、`edit-content` 権限のある admin だけである。削除は元に戻せない。提供者は自分のコメントでも削除できない。名前は自己申告で、本人であることを確かめられないためである。
- コメントの削除は確認を挟まない。消えるのは、削除を押す直前に読んだ 1 件だけであり、コメントのダイアログの上に確認のダイアログを重ねないためである。
- 名前は必須である。ログインしていれば、アカウントの名前を使う。ログインしていなければ、入力した名前の後ろに `(anonymous)` を付けて表示する。
- コメントは下書きに属する。下書きが消えると一緒に消え、共有の期限が切れても消えない。

## 場所の呼び方

研究の内容とデータセットの中の場所を並べる画面では、場所を同じ名前で呼ぶ。場所を並べる画面は、次のとおりである。

- 未解決のコメントを場所ごとに並べる画面 (研究の内容とデータセットの編集画面のダイアログ、レビューと共有、公開前の確認)
- 公開前の確認の変更点のダイアログ
- 「公開前に確かめるもの」にある、未確定の値・未翻訳の項目の場所の一覧
- 編集画面で保存が衝突したときに、変わった項目を並べるバナー

場所の名前は、次のように作る。

- 名前は、編集画面の公開ページのペインで、その場所に行き着くまでの見出しを、大きい方から ` / ` でつないだものである。先頭は研究の hum ID かデータセット ID である。例: `hum0034 / 研究概要 / 目的`、`JGAD000001 / 解析手法 1 (RNA-seq) / プラットフォーム`。
- 表の行になる要素 (提供者、研究プロジェクト、助成金、関連論文) は、`行2 (日本医療研究開発…)` のように、1 から数えた行の番号と、表の 1 列目の値の先頭 10 文字で呼ぶ。1 列目が空なら `行2 (未入力)` である。番号を付けるのは、値だけでは同じ機関の助成金を見分けられないためである。
- 解析手法は、データセットのページで上から数えた番号と、名前の先頭 10 文字で、`解析手法 2 (WES)` と呼ぶ。名前が空なら `解析手法 2 (未入力)` である。番号を付けるのは、1 つのデータセットに同じ名前の解析手法が並ぶことがあるためである。名前そのものへのコメントは `JGAD000001 / 解析手法 2 (WES)` になる。
- ID が未発行なら、研究は `研究 (ID 未発行)` と呼ぶ。データセットは、研究のデータセットの表と同じ番号で `データセット ID 3 (ID 未発行)` と呼ぶ。
- コメントのあとで行・解析手法・データセットが削除されていれば、削除された部分は `削除済み`・`解析手法 (削除済み)`・`データセット (削除済み)` になる。コメントは付け先が消えても残るためである。

## やっていないこと

- 編集のロックと、同じ下書きを開いている人の表示。衝突は保存時の照合と差分表示で扱う。開いている人の数は遅れて表示されるので、判断に使えない。
- JavaScript を使わない編集フォーム。状態の切り替え、並べ替え、409 のときの値の採用は、どれも画面内の操作である。
- 書式付きテキストの文中の一部に色を付けて、確かめてほしい箇所を示すこと。書式付きテキストには強調を入れない ([data-model.md](data-model.md) の「書式付きテキスト」)。色を付けた文字は、消し忘れるとそのまま公開される。確かめてほしいことは、その欄へのコメントに書く ([コメント](#コメント))。
