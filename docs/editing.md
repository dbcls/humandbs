# 編集

研究の記述を書く側の不変条件 — 下書き、保存と同時編集、取り込み、申請からの下書き、レビュー。下書きを
版にする側は [publishing.md](publishing.md)、記事とお知らせは [site-content.md](site-content.md)、
誰が何を許されるかは [auth.md](auth.md)。

編集は admin が下書きに対して行う。データ提供者やレビュアは共有リンクから preview を読んでコメントを
書くだけで、アカウントも権限も持たない。

## 下書き

**1 つの研究に下書きを複数持てる。** 下書きは未公開の作業コピーで、履歴ではない。持つのは研究の
content、admin だけのメモ、記述を書いたデータセットのエントリ、その下書きが作ったデータセットの
identity、そして公開中の版を更新する下書きだけが持つ「更新する版」。エントリを下書きごとに持つのは、
並行する 2 つの下書きが同じデータセットを別の内容で持てるようにするため。

- **保存に完全性の制約を置かない。** 未確定を抱えたまま保存して共有するのが普通の作業状態で、検査は
  公開のときだけ行う
- **下書きは版の番号を覚えず、どこからコピーしたかも覚えない。** 番号は公開のときに決める。取り込む
  源はその都度選ぶ
- **下書きは名前 (label) を持たない。** 同じ研究の下書きは更新日時で見分ける
- **巻き戻し (undo) と autosave を持たない。** 下書きを動かすのは明示の保存だけ — 打鍵の途中が下書きに
  なると、共有リンクの preview がレビューの最中に動く
- **公開は下書きを消費する。** 同じ内容が版と下書きの両方にあると、どちらが正かを言えない。続きを書く
  ときは版から新しい下書きを作る

**公開中の版を直すのは「更新」で、版はそのあいだも公開されたまま。** 版の「編集」は、その版の内容を
持つ下書きを裏で作る。**更新は版の状態で、下書きは器** — 画面はこの下書きを下書きとして並べず、版が
「更新中」と言う。版 1 つに更新の下書きは 1 つで、更新中の版は取り下げられない (先に更新を中止する)。
通すと同じ番号の版が入れ替わる ([publishing.md](publishing.md))。取り下げて直す形や、直すあいだ公開
ページから消える形は採らない — 読者には取り下げと同じに見える。

**下書きに値が入る道は、打つことと取り込むことの 2 つ。** 版のコピー・申請からの研究の作成・公開版の
更新は、どれも「空の下書きを作って取り込む」の短縮で、経路が増えているのではない。公開ページへ直に
書く経路は持たない。

## 保存の単位と同時編集

**研究の content とデータセットは別々に保存し、それぞれが自分の revision で照合される。** 研究の content
は下書きの revision、データセットの記述 (experiment を含む) はエントリの revision。1 研究が 200 を
超えるデータセットを持つことがあり、1 つの衝突が全部の衝突になるのは正しくない。experiment は自分の
revision を持たない。データセットの作成・削除・並び替えは下書きの revision で照合する。

**排他しない。** 他の人を read-only にせず、開いている人も数えない。正しさは保存時の楽観照合で担保する。

- **更新は `WHERE id = ? AND revision = ?` で、影響行数が 0 なら 409。** エントリの初回作成は「無ければ
  挿入」で、挿入されなかった側が 409
- **複数行にまたがる保存は 1 トランザクションで全部照合し、1 つでも外れたら全体を戻す**
- **revision に `xmin` を使わない。** VACUUM FREEZE で変わる
- **下書きへの書き込みは `app/admin/drafts.server.ts` 1 つに閉じ、既存の行を変える関数はどれも
  revision を必須引数に取る。** トリガでは守れない — 述語を忘れた更新も revision を増やせば通る。公開も
  ここを通る。例外は共有の設定で、content ではないので照合しない (照合すると共有を切り替えただけで
  開いている編集画面の保存が 409 になる)
- **409 では相手が変えた箇所を出し、手元の入力は捨てない。自動 reload はしない。** 差分は画面の側で
  「開いたときの content」と「いまの content」から取り、欄ごとに相手の値を拾える
- **場所を指す語彙は path 1 本** (`app/admin/paths.ts`)。コメントの宛先・衝突の差分・取り込みの差・
  preview の印が同じ綴りで書かれ、配列の要素は位置ではなく identity で指す。**差分が挙げた path を
  全部取り込むと差分が空になる** — 型では結べないので test で守る
- **形の合わない payload は 400、revision の食い違いは 409。** catalog が知らないキー・型の食い違い・
  別の語彙の値・外部アーカイブのデータセットのファイル選択は、どれもフォームが出さない入力なので 400
- **下書きの削除も revision を取る。** 開いてから誰かが編集した下書きは捨てさせない

**打ちかけの値は状態を変えても消えない。** 「未確定」を押した欄の入力は画面に残り、保存の時点で状態が
値以外なら捨てられる。**未翻訳は操作しない** — 値から導出される ([data-model.md](data-model.md))。
**空の数値欄はスロットごと保存しない。** 数値に「中身が空の値」は無い。

## 編集フォームと公開ページ

**フォームの欄はどれも公開ページか一覧の行に対応する場所を持つ。** 公開ページに出さない値
(ORCID・メールアドレス・所在地) は content に持たない。

**編集画面はフォームの隣に公開ページを描く。** 描くのは公開ページ・preview と同じ純関数で、描く経路を
増やさない。**空の欄も空の節も場所を持つ** — 公開表現は未確定を空にするだけで欄を消さず、ページは空の
節も見出しを立てるので、下書きを埋める作業が指す先を失わない。

**データセットのキーは catalog から選ぶ。** その場で新しいキーを作る経路は持たない。**語彙の欄は語彙の
大きさによらず同じ形** — 候補は打った文字を server に送って返ってきたものを出す。**疾患の欄**はコードを
打っても選んでもよく、正規化を通し、分類に無いコードは削った先の候補を出す。呼称には候補を出さない
(記事に書かれた名前をそのまま入れる欄なので)。

## 取り込み

**下書きは自分のコピーだけを持ち、誰の派生かを覚えない。** 公開は新しい版を作る操作なので、別の下書きが
先に公開されてもこの下書きの持ち物は動かず、衝突として検出するものも無い。**代わりに取り込む源をその都度
選び、値を並べて人が決める。**

- **源は 3 種類で、道は 1 つ** — この研究の公開版、同じ研究の他の下書き、データ提供申請の枝番。
  取り込みは研究の内容の画面からだけ入り、データセットの記述もその流れで入れる。取り込み先の下書き
  自身は源にならない (server も断る)
- **源は下書きと同じ形に直してから比べ、違う項目だけを並べる。** 項目ごとに「現在の下書き」「源」
  「最終的な値」の 3 段で、最終的な値は書ける欄 — どちらでもない第 3 の値を書くことがあるので、
  「どちらを採るか」を選ばせる形にしない。初期値は源の値で、源が空けているところは下書きの値
- **配列は要素ごとに残すかを選ぶ。** 初期値は両方とも残す側
- **取り込まないもの** — データセットの並びとファイルの選択。どのデータセットを公開するかは研究が
  決め、選べるファイルは箱の中身が決める
- **確定は保存で、通常の保存と同じ検査と照合を通る。** 入る前に下書きを保存させるので、面が
  「現在の下書き」として見せるものは保存済みの値と食い違わない
- **編集フォームは取り込みの操作を持たない。** 源との差は preview の印が言う (「公開版との差」)
- **公開は源を自動では混ぜない。** 提供者が preview で見た姿がそのまま公開されることが約束で、公開時に
  merge すると承認された姿と違うものが出る

## 申請から下書きを作る

研究の記述は申請書に、データセットの identity は上流に既にある。**上流から引いた値で埋めた下書きを
作る経路を持ち、手で打ち直すところから始めない。**

| 入力 | 出所 | 作るもの |
|---|---|---|
| J-DS の承認枝番 | 申請管理システム DB | 研究 content と、登録された JGAD のデータセット |
| JGAD | 申請管理システム DB | データセット 1 件 |
| DRA の submission | DDBJ Search | データセット 1 件 |

- **入力の単位は J-DS の枝番。** 枝番 1 本が登録 1 回に対応し、研究 ID が付くのも承認枝番。同じ枝番を
  何度でも取り込め (承認の後からデータセットが付く)、下書きはどの枝番から取り込んだかを覚えない
- **上流のキャッシュを経由せず、その場で上流を引く。** キャッシュは公開済みしか持たない。確認の画面と
  作成で 2 回引き、画面が送るのは何を作るかの指示だけ
- **入るのは、そのまま公開ページに出る値だけ。** 研究題目・目的・方法・対象と、提供者 (研究代表者の
  氏名と所属)。連絡先・研究分担者・関連論文は入れない
- **データセットは 1 accession = 1 件で、experiment を 1 件持つ。** 研究に登録済みのデータセットは
  作らない (同じ label の pin は断られる)。申請からの研究の作成はデータセットを選ばせず全部作る
- **語彙は code で、当たらなければ英語ラベルで引き当て、語彙値を作らない。** 申請が言ったのに選択肢に
  当たらなかった値は、その欄のコメントに作った curator の名前で残し、1 つも当たらなかった欄は未確定で
  作る。上流が黙っているだけの欄には未確定を立てない
- **疾患はコードだけを作り、呼称は curator が書く。** 正規化で落ちたコードもコメントに残る
- **データセットの label は作ると同時に pin する**ので、この操作は `edit-content` と `manage-labels`
  の両方を要る。研究 ID は上流が持っているときだけ pin する。研究 ID ↔ J-DS の master は申請管理
  システムで、ポータルからは書けない
- **部分的に取れなかったものは列挙した上で作らせる。** 下書きは捨てられる。接続の無い環境では画面が
  そう言い、入口は消さない

## レビュー

**下書きごとに共有リンクを 1 本持ち、リンクを知っている人全員が preview を読んでコメントできる。
人ごとのリンクは持たない。** 相手にはデータ提供者を含む。**承認の状態 (review status) は持たない** —
レビューは状態ではなく活動で、「レビュー中は編集できない」はコメントを受けて直す作業そのものを止める。

**流れは 2 往復で、連絡は system の外。** 提供者はコメントを書き終えたら 1 つ目の印を、事務局の修正を
読んで直すところが無ければ 2 つ目の印を押す。「確認して」の連絡は人がメールで送り、system は印を記録して
admin に見せるだけ (メール送信基盤が無い)。印は承認権限ではなく、公開するかどうかは admin が決める。
印は押すたびに記録する。

**共有リンク** (`/preview/:token`、データセットは `/preview/:token/dataset/:datasetId`)

- **共有の状態は 2 値 (共有 / 共有停止) で、期限は既定で無期限。** 期限を置くと、その日の終わり (JST)
  まで有効。トークンは下書きの列で、止めてから戻すと同じリンクが使える。**再発行**は漏れたリンクを
  止めるためのもの
- **トークンの検証は server のデータ取得経路に置く。** 停止・期限切れ・再発行前のトークンはどれも
  存在しないリンクと同じ 404 で答え、下書きの存在を漏らさない
- **応答に `X-Robots-Tag: noindex` と `Referrer-Policy: no-referrer` を付ける。** 無認証の URL で未公開の
  content を配るので、クローラと Referer からの漏れを塞ぐ
- **preview は公開ページそのもの** — 同じ公開表現・同じ部品で、違うのは未確定を残す引数だけ。未確定は
  提供者への依頼 (「ご教示ください」) として出る。アラートは出さない
- **ダウンロード一覧は非公開の箱も合成して見せ、非公開の行はリンクにしない**

**コメント**

- **宛先は欄 (研究の content かデータセットの path) と、下書き全体。** テキスト範囲のアンカーは持たない。
  admin だけのメモは別の宛先で、共有リンクからは読めず書けない
- **投稿された宛先が content に実在するかを server が確かめる。** 共有リンクから書けるのは、その版が
  載せるデータセットまで
- **読み取りも描いているページの宛先に絞り、描かないものは loader の戻り値にも載せない。** SSR の水和
  JSON はリンクを持つ誰でも読める
- **返信を持たない。** 1 つの場所のコメントは書かれた順に平らに並ぶ。**解決はコメント 1 件ごとに手で
  付け**、編集されたことで自動では解決しない
- **解決と削除は `edit-content` を持つ admin だけ。** 削除は確認を挟まず、復元も持たない。閲覧者は
  自分のものでも削除できない (自己申告の名前には本人性が無い)
- **名前は必須。** サインイン済みなら本名、未サインインなら自己申告の名前を sessionStorage に置き、
  後ろに `(anonymous)` を付けて出す。閲覧者の印を押した名前も同じ長さの上限を持つ
- **コメントと共有リンクは下書き単位。** 下書きを削除すると一緒に消え、共有の期限が切れても残る

**公開版との差** — preview と編集画面の公開ページは、比較の相手 (最新の公開版、更新の下書きなら更新
する版) と違う場所に印を付け、押すと相手の値を出す。公開版が無ければ印は出ない。フォームの側には印を
置かない (取り込んだ後に書き直した欄が「違う」と言い続けるため)。**印を付ける場所と、view が値を覚えて
いる場所は同じ集合** — 型では結べないので test で守る。

## 意図的にやっていないこと

| やらないこと | 理由 |
|---|---|
| 悲観ロック・開いている人の表示 | 衝突は保存の照合と差分が受け持つ。開いている人の数は遅れて出て、当てにならない |
| autosave・下書きの巻き戻し | 下書きを動かすのは明示の保存だけ。409 の入力はフォームに残る |
| 公開時の自動 merge / 源の値を自動で入れること | 承認された姿と違うものが出る |
| 承認ワークフロー | レビューは状態ではなく活動 |
| コメントの返信・テキスト範囲のアンカー・通知 | 欄単位の宛先で足り、メール送信基盤が無い |
| 人ごとの共有リンク | 誰に渡ったかは返ってきたコメントの署名で分かる |
| 取り込みで語彙値やキーを作ること | 打った文字列が catalog に載ることがキーの揺れを生んできた |
| 編集フォームを JS 無しで動かすこと | 状態の切り替え・並べ替え・409 の取り込みがどれも画面の中の操作 |
