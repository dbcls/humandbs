# 項目定義と語彙

データセットと解析手法の値を並べるキー (項目定義) と、選択肢の値 (語彙)、疾患 (ICD10) の決まりをまとめる。語の意味は [concepts.md](concepts.md) の「項目定義と語彙」、値を研究の内容にどう保存するかは [data-model.md](data-model.md)、公開サイトの絞り込みでの使われ方は [public-site.md](public-site.md) の「絞り込み」にある。

## 項目定義

データセットと解析手法の値のキーは、項目定義 (`content_key`) で決める。キーには、付く先 (データセットか解析手法か)、日本語と英語の表示名、値の型、表示順がある。

- キーの名前の変更は表示名の変更で、研究の内容は変わらない。研究の内容はキーを ID で指すためである。
- キーの追加は明示的な操作である。入力した文字列がそのまま項目定義に加わる経路は無い。編集画面からも、データ提供申請の取り込みからも、キーと語彙の値は作られない。入力された文字列がそのまま加わると、表記揺れが生まれるためである。
- admin が画面で追加・削除できるのは、解析手法の自由記述のキーだけである。名前の変更と並べ替えは、解析手法のキーなら型によらずできる。データセットのキーと、型が語彙・数値・疾患のキーの追加・削除・型の変更は、開発の作業である。これらのキーは絞り込みになり、集計と入力欄が必要になるためである。
- 語彙と疾患の型のキーは常に絞り込みの項目になり、数値の型のキーは絞り込みのカテゴリ ([concepts.md](concepts.md)) が設定されたものだけが絞り込みの項目になる。絞り込みに使うかどうかはカテゴリの有無で表し、別の列は無い。
- 公開日・更新日とファイル形式はキーではないが、絞り込みに出る。ファイル形式は語彙 `file-type` の値で絞り込み、検索式では `file-type:fastq` と書き、カテゴリ「データ」の先頭に並べる。
- キーと語彙の値の code は検索の URL に出る (`?q=platform:hiseq-2500`)。そのため英語の表示名から機械的に作り、admin には入力させない (`app/admin/catalog.ts` の `codeFrom`)。同じ code があれば末尾に番号を付ける。組み込みの検索フィールドと同じ文字列は使えない。ICD10 だけは、code が規格のコードそのものである。
- 使われているキーと語彙の値は削除できない。公開中のデータセットか下書きの内容が、そのキーに値があるか、その語彙の値を指していれば、使われているとする。
- 項目定義や語彙を書き換えたら、検索用の行を全部作り直す。どの変更が行に反映されるかを操作ごとに判断すると、判断を誤った操作だけが反映されなくなるためである。例外はキーの並べ替えだけで、この判断は項目定義の書き込みをまとめた 1 か所に置く。

### キーが無いもの

データセットのファイルや ID から決まる値には、キーを置かない。

- データセットそのものが accession になるアーカイブ (JGA、DRA、GEA、MetaboBank) と、ポータルが発行する NHA ID の accession のキーは無い。データセット ID がその accession で、データセットのページが DDBJ Search の entry へのリンクを表示する ([public-site.md](public-site.md)) ため、キーに同じ ID を書いても重なるだけである。ポータルにデータセットの無いアーカイブ (GEO、jPOST、INSDC、EGA) の accession と、JGA が加工したデータのデータセット ID のキーはある。
- データセットの総データ量とファイル形式のキーは無い。どちらもデータセットのファイルから出す値で、JGAD・DRA・GEA・MetaboBank は取得元のファイル ([upstream.md](upstream.md) の「データセットのファイルの大きさと形式」)、NHA はファイルの選択 ([files.md](files.md) の「データセットとファイルの対応」) から作る。人が計算して書いた値は、データの追加で古くなり、形式や内訳の書き方も研究ごとに揃わないためである。

### キーの名前

キーの名前は公開ページの表の見出しで、型のあるキーでは絞り込みの項目の名前でもある。名前は次のように書く。

- 見出しは単数形で書く。値が複数あることは見出しで言わない。
- 単位は入れない (`Read length (bp)` ではなく `Read length`)。数値は入力された単位のまま表示するため (`73 TB`)、見出しに単位を書くと値と食い違う。
- 「〜の別」「〜の単位」は使わず、値を表す名詞で書く。有無を表すキーは「〜の有無」とする。
- 括弧は半角で、前後に半角の空白を置く (`カバレッジ (深度)`)。
- 型のあるキーの英語は文頭だけ大文字にし、略称と固有名詞の表記はそのまま残す (`Disease (ICD-10)`)。自由記述のキーはアーカイブ名を含むことがあるため (`Gene Expression Omnibus Accession`)、この規則を当てない。
- 日本語と英語は同じものを指す。
- このうち括弧・単位・「〜の別」と、型のあるキーの英語の大文字は、キーの追加と名前の変更のときにサーバーが確かめてエラーにする (`app/admin/catalog.ts` の `keyLabelProblem`)。

## 語彙

語彙は選択肢の値の集まりで (`vocabulary_set` と `vocabulary_term`)、1 つの語彙は 1 つのキーに属する。

- 語彙の値の表示名は、英語が必須で日本語は任意である。日本語が空でも未翻訳に数えない。同じ語彙の中でも、日本語で書かれるかどうかが値ごとに違うためである。
- 語彙には原則として階層が無く、階層があるのは ICD10 だけである。
- 製品を指す語彙の値は、会社名を `maker` 列に分けて置く。会社名を親にすると、絞り込みの一覧に会社名が並んでしまう。表示名は会社名を含んだ全体のままで、分けて使うのは表示するときだけである。
- 1 つの語彙の値は 1 つのものを指す。
- 表示順 (`position`) は編集フォームの候補と一覧のセルで使い、絞り込みの一覧は件数の順に並べる。
- 公開サイトと JSON API は、項目定義と語彙の値をアプリの process の中に保持し、変更があったときだけ読み直す。変更は DB の trigger が `NOTIFY` で知らせ、アプリは要求のたびにそれまでの通知を受け取ってから保持しているものを使うので、admin の編集も `tools` での ICD10 の取り込みも、commit のあとの要求には必ず反映される。ICD10 だけで値が 1 万を超え、要求のたびに読むと応答の時間の多くを占めるためである。通知を受ける接続が切れているあいだは保持せず、要求のたびに読む。

### 画面から編集できる語彙

admin が編集するのは、データとともに増える語彙 (プラットフォーム、組織など) だけである。

- 値の集合がポータルの仕様として決まっている語彙 (公開区分、性別などの排他的な分類)、ICD10、ファイル形式は、画面から編集できない (`app/admin/catalog.ts` の `SETTLED_VOCABULARIES`)。ICD10 の見出し語は外部の規格で、ファイル形式はファイルの拡張子で決まるためである。編集できない語彙も DB に置く。検索用の行が語彙の値の ID を参照するためである。
- 利用ポリシーの語彙 (`policies`) の値にだけ、記事 ([site-content.md](site-content.md)) を 1 つ指定できる。公開ページは、その値の表示名を、ポリシーの本文を書いた記事へのリンクにする。ほかの語彙の値には指定できず、画面にも指定の項目を表示しない。組織やプラットフォームの値には指す記事が無いためである。記事は slug ではなく記事の ID で指すので、slug を変えてもリンクは切れない。記事を削除すると指定が外れる。
- 使われている語彙の値を整理するときは統合を使う。指している値を全部統合先へ書き換えてから、元の値を消す。統合できるのは同じ語彙の中だけである。
- 統合では、過去のバージョンの内容も書き換える。語彙の値は研究の内容そのものではなく、研究の内容が指す先だからである。公開中のバージョンの内容が変わるのは、この操作のときだけである ([publishing.md](publishing.md) の「バージョン番号」)。統合は操作の記録に残す ([publishing.md](publishing.md) の「操作の記録」)。語彙の値に「選べない」状態は無い。

## 疾患 (ICD10)

疾患の値は、語彙の値への参照の列 (0 個以上) と、呼称 (日本語と英語) でできている。

- 参照が 1 つも無い値は正しい状態である。分類に載っていない疾患が実データにあるためである。
- 呼称は値に、見出し語は語彙の値に置く。同じコードが研究ごとに違う集団の定義として書かれるので、呼称を語彙に寄せると区別が失われるためである。表示は、呼称があれば呼称、無ければ見出し語である。
- 1 つの値は複数の分類の語彙の値を指せる。分類を足しても値の形は変わらない。
- 分類は 3 桁の分類を根、4 桁をその子とする 2 層である。絞り込みの件数は根で数える。
- コードは 3 桁と 4 桁だけを使う。移行も申請からの下書きの作成も、同じ正規化 (`app/icd10/codes.ts`) を通し、語彙にあるコードになるまで末尾を削る。3 桁を 4 桁へ広げることはしない。書いた人が選ばなかった細分を補わないためである。
- 分類そのものが語彙である。`npm run icd10:import` が 3 桁と 4 桁の全コードを語彙 `icd10` に入れ、別の辞書は置かない。再取り込みは code で照合して上書きし、語彙の値の ID は変わらない。
- 英語の見出し語は WHO の ICD-10 (Version 2019)、日本語は e-Stat の基本分類から取る。日本語にしか見出し語が無いコードは、英語の欄にも日本語の見出し語を置く (英語は必須のため)。英語にしか無いコードは日本語の欄を空にし、表示するときに英語の見出し語を使う。
- 参照が無い値は絞り込みの行を作らない。ただし呼称は全文検索に入るので、キーワードでは見つかる。
