# 公開 API

公開データを機械で取得するための JSON API について、外部に保証していることをまとめる。エンドポイントとパラメータの一覧は `/api/openapi.json` (Swagger UI は `/api/docs`) にあり、ここには OpenAPI では表しきれない決まりだけを書く。語の意味は [concepts.md](concepts.md) にある。

## 目的

この API は、公開データを再利用する人が機械的に取得できるようにするためにある。範囲もこの目的から決めている。

- 提供するのは、研究とデータセットの個別取得、検索、NDJSON による一括取得、DDBJ Search への対応関係の提供である。
- ポータルの画面はこの API を使わない。
- 作法は [ddbj-search-api](https://ddbj.nig.ac.jp/search/api/docs) に揃える。同じ組織が同じ利用者に向けて公開している API なので、RFC 7807 のエラー、CORS の全許可、NDJSON の Content-Type、空でも必ずある配列を揃えている。
- 認証は無い。公開済みのものだけを返すので、守る対象が無いためである。すべて `GET` で独自のヘッダを求めないので、preflight も起きない。
- 返す範囲は検索用の行 (`search_doc`、[data-model.md](data-model.md)) だけから決める。個別取得・検索・一括取得のどれも同じで、公開サイトと同じ範囲になる ([public-site.md](public-site.md))。

## 応答の形

個別取得、検索結果の 1 件、一括取得の 1 行は、同じ関数 (`app/api/view.ts`) で作る同じ形である。

- 応答の型の正本は `app/api/schema.ts` の schema で、OpenAPI の定義も同じ schema から作る。実行時の検証はせず、変換の関数が schema に合うことをコンパイラで確かめる。要約用の別の形は作らない。
- 日本語と英語の値を両方返し、URL で言語を選ばない。翻訳の無い値をもう一方の言語で埋めない。誰も訳として書いていない値を、訳として返すことになるためである。
- 値があればその値を返し、空の値と未確定の値はキーごと返さず、該当なしは `null` を返す。公開用の表示データの段階で未確定は空として扱うので、API ではこの 2 つを区別できない。
- 配列は空でも必ず返す。
- 数値の項目は、値が 1 つでも数値の配列 (`numbers`) で返す。入力された単位ではなく標準の単位に換算して返す。要素の形は OpenAPI の定義にある。
- 文章はプレーンテキストで返す。構造のまま返すと、応答が研究の内容 (content) の型に依存するためである。文章中のリンク先は失われるが、機械が使う参照 (accession、データセット ID、語彙、ファイル、URL) は型の決まった項目として返す。
- 内部の ID (uuid、配列の要素の ID、語彙の値の ID) は返さない。語彙の値はコードと両言語の表示名で返し、そのコードはそのまま `?q=` に書ける。
- 疾患は識別子の並びと呼称で返す。識別子が空の値もあるので、ICD10 のコードがあることを前提にできない。
- 項目の値は項目定義の表示順で返す。
- 研究の応答には、配下のデータセットを ID の並びだけで含める。データセットを埋め込むと、同じ情報が 2 か所に出るためである。研究には独自の更新日が無く、公開中のバージョンの一覧の最後がそれに当たる。
- 公開区分などの語彙の英語の表示名 (`Unrestricted-access`、`Controlled-access (Type I)` など) は、API の値にも公開サイトの絞り込みの値にも出るので、ポータルがこれまで公開してきた表記のまま変えない。

## 検索と一括取得

検索は公開サイトの一覧と同じ検索式で行い、全件が必要なときは一括取得を使う。

- `?q=` は公開サイトの URL と同じ検索式で、解釈する処理も同じ 1 つ (`app/search/dsl.ts`) である。API のために別の検索の経路を作らない。文法は OpenAPI の定義に、値の解釈は [public-site.md](public-site.md) の「検索式」にある。
- 検索式で指定できる項目は `/api/fields` が返す。ID・題名・日付の組み込みの項目と、型が語彙・数値・疾患の項目だけで、それ以外の項目の値は全文検索の対象に含まれる。返す値は公開中のデータに実際にあるものだけで、ここから取った値で検索すれば必ず何かが当たる。階層のある語彙は最上位に丸める。
- 1 ページは 20 件で固定し、公開サイトの `?size=` は受けない。全件は一括取得で取れるためである。
- 絞り込みの件数の集計は返さない。集計は画面の部品のためのもので、返すと呼び出しのたびに検索が増えるためである。
- 並び順は公開サイトと同じ 3 つの項目と向きで、関連度の並び順は無い。
- 一括取得は NDJSON で返す (`/api/research.jsonl` と `/api/dataset.jsonl`)。全件を 1 つの配列にすると、受け取る側が全体をメモリに載せることになるためである。

## 互換性の保証

外部に保証するのは URL に到達できることだけで、同じ URL が同じ内容を返し続けることは保証しない。

- 公開中のバージョンは同じ番号のまま更新できる ([publishing.md](publishing.md)) ので、内容が変わらないことは保証できない。内容の訂正を外から検出する値も無い。応答の日付は、アーカイブから取得したデータセットの日付と、admin が決めるバージョンの公開日である。
- 公開されていないものと存在しない ID は、どちらも同じ 404 を返す。エラーの `detail` は種類ごとに決まった文で、指定された ID を含めない。
- secondary の ID ([concepts.md](concepts.md) の「ID の割り当て」) で指定しても、リダイレクトせずにそのまま返す。応答の `id` と `url` は primary の ID なので、どれが primary の ID かは本文から分かる。大文字と小文字だけが違う表記も同じ扱いで、表記どおりの ID が先に当たり、無ければ大文字小文字を区別せずに 1 つだけ当たるものを使う (公開サイトと同じ解決)。
- バージョンは公開サイトの URL と同じ表記 (`v` と先頭に 0 の付かない番号) でだけ指定できる。`v01` や `V1` は 404 になる。
- ファイルの URL とラベル ([files.md](files.md) の「ラベル」) は保証しない。どちらも研究の公開を通らずに変わるので、同じバージョンの応答でも変わる。ラベルもほかの値と同じく両言語で返し、書かれていない言語はキーごと返さない。ファイルストアから応答が無ければ、ファイルの一覧を空として返す。関係の無いサービスの可用性で JSON の形を変えないためである。

## エラー

エラーは RFC 7807 の problem details (`application/problem+json`) で返し、`type` は `https://humandbs.dbcls.jp/problems/{slug}` である。

- 404 は公開されているものが無いとき、422 はパラメータを解釈できないとき (`?q=`・並び順・ページ番号・accession の種類) に返す。
- 400 は使わない。拒否する理由はどれもパラメータの形の問題で、業務上の決まりに反するものが無いためである。

## DDBJ Search への提供

JGA の accession と研究 ID の対応を `/api/dblink` 以下で返す。形は ddbj-search-api の DBLinks API をそのまま使う。受け取る DDBJ Search 側に `Xref` 型も `humandbs` という種類も既にあるためである。

- 対応の取得元は、申請管理システムのキャッシュ (`hum-accession`) である。対応の正本は申請管理システムで、ポータルの ID の割り当ては正本ではないので、キャッシュに無い対応は返さない。
- ポータルで公開している研究の対応だけを返す。未公開の研究の対応を返すと、DDBJ Search に 404 のリンクが表示されるうえ、未公開の研究 ID を外から列挙できてしまうためである。
- 返すのは primary の研究 ID である。リンク先は `/{研究 ID}` で、ずっと 200 を返す。
- 該当が無いときは 200 と空の一覧を返す。これにより、未公開の研究があることも分からない。

## OpenAPI

OpenAPI の定義は、エンドポイントの配列 1 か所 (`app/api/endpoints.ts`) から route の登録と一緒に作る。

- URL を 2 か所に書かないので、route と定義がずれない。
- Swagger UI の script と stylesheet はこのサイトから配信する。CDN に置くと、ページが第三者の可用性に左右されるためである。Swagger UI のバージョンは `package-lock.json` で決まる。
- `/api/docs` はサイトのページではなく、ヘッダも言語も無い HTML である。

## やっていないこと

- ページの件数を変えるパラメータ。全件は一括取得で取れる。
- 絞り込みの件数の集計。集計は画面の部品のためのもので、絞り込み自体は `?q=` で指定できる。
- 書き込みの API。編集はサーバー側の処理で行い、書き込みの API を必要とする利用者もいない。
- 申請管理システムを中継する API。サービスアカウントが必要になり、1 人 1 アカウントの決まり ([auth.md](auth.md)) と衝突する。
- バージョンの一覧の API。研究の応答にバージョンの一覧が含まれる。
- 一覧の表の提供者の列を返すこと。表の見せ方のためのもので、提供者の情報は研究の応答に含まれる。
- `X-Request-ID`。照合するリクエストログの仕組みが無い。
