# JSON API

公開データを機械が取るための面。**endpoint とパラメータの一覧は `/api/openapi.json` が持ち** (Swagger UI は
`/api/docs`)、ここには document で表しきれない規約と不変条件だけを書く。

## 何のためにあるか

**画面はこの API を使わない。** 存在理由は再利用者が機械的に取れることだけで、範囲もそこから決まる —
個別取得、検索、一括取得 (NDJSON)、DDBJ Search への relation の供給。

**作法は [ddbj-search-api](https://ddbj.nig.ac.jp/search/api/docs) に合わせる。** 同じ組織が同じ利用者層に
出している API なので、RFC 7807 のエラー、CORS の全許可、NDJSON の Content-Type、空でも必ずある配列を
揃えてある。

**認証を持たない。** 公開済みだけを返すので守る対象が無い。すべて `GET` で独自の header を要求しないので、
preflight も起きない。

## 何を公開と言うか

**集合は検索用の行からしか引かない** ([data-model.md](data-model.md))。個別取得も検索も一括も同じ。

- **公開されていないものと存在しない label は同じ 404。** detail は種類ごとの固定の文で、label を
  書き返さない
- **secondary の label は redirect せず、そのまま答える。** 応答の `id` と `url` は primary のものなので、
  いま有効な label は本文から分かる。**大小文字の違う綴りも同じ扱い** — 綴りどおりの label が先に当たり、
  無ければ大小文字を無視して 1 つだけ当たるものを採る (画面と同じ解決)
- **版は画面のアドレスと同じ綴り (`v` + 先頭に 0 を持たない番号) でしか指せない。** `v01` や `V1` は 404

## 応答の形

**個別取得・検索の 1 件・一括の 1 行は同じ投影** (`app/api/view.ts`) で、「どこまでが要約か」の線を
別に持たない。**応答の schema が型の SSOT** (`app/api/schema.ts`) で、OpenAPI document も同じ schema から
出る。実行時の検証は持たない — 投影は全域関数で、コンパイラが schema に照らして確かめる。

- **ja と en を両方載せ、アドレスに言語を持たない。未翻訳をもう一方で埋めない** — 誰も訳だと言って
  いない値を訳として返すことになる
- **値あり → 値、空と未確定 → キーごと無い、該当なし → `null`。** 公開表現が未確定を空に倒すので、
  API に届く時点で 2 つは区別されない
- **配列は空でも必ずある**
- **数値のキーは数の配列** (`numbers`) を返し、1 つしか持たないキーも要素 1 つの配列。各要素は正準単位の
  `value` と `unit`、幅のある値の上限 `high` (幅でなければ `null`)、あるときだけ `label` と `note`。
  打たれた単位ではなく正準単位で返す
- **文は plain text。** 木をそのまま出すと応答が content の形に縛られる。文の中のリンクは行き先が
  落ちるが、機械が使う参照 (accession・データセット ID・語彙・ファイル・URL) は型付きの field にある
- **内部の identity (uuid・要素の id・語彙値の id) は出さない。** 語彙値は code と両言語のラベルで返し、
  その code はそのまま `?q=` に書ける
- **疾患は識別子の並びと呼称を返す。** 識別子が空の値があるので、ICD10 のコードを前提にできない
- **値スロットは catalog の表示順**
- **研究は配下のデータセットを ID の列だけで持つ。** 埋め込むと同じ情報が 2 か所に出る。研究は自分の
  「更新日」を持たず、公開版の一覧の最後がそれになる

## 検索と一括

- **`?q=` は画面のアドレスと同じ検索式で、受け口も 1 本** (`app/search/dsl.ts`)。API のために 2 本目の
  クエリ経路を作らない。文法は OpenAPI document が持ち、値の読み方は画面と同じ
  ([public-site.md](public-site.md) の「検索式」)
- **何を名指せるかは `/api/fields` が答える。** 独立した列 (`id` `title` `date_published`
  `date_modified`) と、型が vocabulary / number / disease のキーだけで、それ以外のキーの値は全文に溶けて
  いる。**挙げる値は公開集合が実際に持っているもの**で、ここから取った値は必ず何かに当たる。階層の
  語彙は根に丸める
- **1 ページ 20 件の固定。** 画面の `?size=` は読まない — 全件は一括取得がある
- **facet の集計は返さない。** パネルという画面の部品で、呼び出しごとにクエリが増える
- **並びは画面と同じ 3 つのキーと向き。** 関連度は持たない
- **一括は NDJSON** (`/api/research.jsonl` `/api/dataset.jsonl`)。全件を 1 つの配列にすると読み手が全部を
  メモリに載せることになる

## 何を約束するか

**約束するのは URL の到達性だけで、内容の不変は約束しない。** 公開中の版は同じ番号で更新できるので
([publishing.md](publishing.md))、同じ URL が同じ内容を返し続けることは保証できない。訂正を外から検出する
値も持たない — 応答の日付は、アーカイブ由来のデータセットの日付と admin が決める版の公開日。

**ファイルの URL は約束しない。** store が答えなければ箱は空として返す — 無関係な系の可用性で JSON の
形を変えない。

## エラー

**RFC 7807 の problem details** (`application/problem+json`)。`type` は
`https://humandbs.dbcls.jp/problems/{slug}`。404 は公開されているものが無いとき、422 はパラメータが
読めないとき (読めない `?q=`、使えない `sort`、先頭に 0 を持たない 9 桁までの 10 進でないページ、扱わない accession type)。**400 は使わない** —
拒む理由はどれもパラメータの形で、業務規則の違反にあたるものが無い。

## DDBJ Search への relation の供給

JGA accession ↔ 研究 ID の対応を返す (`/api/dblink` 以下)。**面は ddbj-search-api の DBLinks API を
そのまま採る** — 受け手が同じ道具立てで、`Xref` 型も `humandbs` という type も向こうにある。

- **source は上流のキャッシュ (`hum-accession`)。** 対応の master は申請管理システムで、ポータルの pin は
  master ではないので、キャッシュに無い対応は返さない
- **ポータルで公開されている研究の対応だけを返す。** 返すと DDBJ Search に 404 のリンクが出るうえ、
  未公開の研究 ID が外から列挙できる。この API に「公開済みだけ」の例外は無い
- **報告するのは primary の研究 ID。** リンク先は `/{研究 ID}` で、恒久的に応答する
- **該当が無いときは 200 と空の一覧。** これ自体が存在の秘匿になる

## OpenAPI document

**endpoint の配列 1 か所 (`app/api/endpoints.ts`) から route の登録と document の両方を出す。** アドレスが
2 か所に書かれないので、route と document がずれない。**Swagger UI の script と stylesheet はこの origin から
出す** — CDN に置くとページが第三者の可用性に乗る。版は `package-lock.json` が決める。`/api/docs` は
サイトの一部ではなく、ヘッダも言語も持たない素の HTML。

## 意図的にやっていないこと

| やらないこと | 理由 |
|---|---|
| ページの大きさを変えるパラメータ | 全件は一括取得がある |
| facet の集計を返すこと | 画面の部品。絞り込み自体は `?q=` で効く |
| 書き込みの面 | 編集は server の実行点で行う。受益者が特定できていない |
| 申請管理システムを包む endpoint | service account が「1 人 1 アカウント」と衝突する ([auth.md](auth.md)) |
| 版の一覧の endpoint | 研究の応答に版の一覧が載る |
| 一覧の提供者の列を返すこと | 表の見せ方で、研究の答えではない。提供者情報は研究に載っている |
| `X-Request-ID` | 突き合わせるリクエストログの仕組みが無い |
