# 公開

draft を版にする操作と、それを取り消す操作。書く側は [editing.md](editing.md)、モデルの側の不変条件は
[data-model.md](data-model.md)、誰が何を許されるかは [auth.md](auth.md)。

## 公開前の確認の画面 (`…/draft/:draftId/publish`)

公開の入口はこの 1 枚で、読むための画面として作る。**直すのは元の画面に戻ってやる** — 唯一の例外が
ラベルの pin で、それは公開を止めているものであり、編集ではなく 1 つの値を入れる操作だから。

**押す前に知りたいことを、知りたい順に並べる**: 何が変わるか → 公開できない理由 → レビュー → 確認事項 →
公開。見出しは名詞で、どの節も「何のための節か」を説明の 1 文で言う。押すものは最後の節にだけ立ち、読む
ものが先に来る。pin とファイルの公開はそれぞれの節の中の自分の form で送り、公開の form には入れない
(form は入れ子にできない)。

- **変更点** — 比べる相手 (公開中の最新の版、更新なら更新する版) を説明の文で言い、研究の記述が何項目
  変わるかと、記述が変わるデータセット・新しく公開されるデータセットを並べる。**データセットは研究の
  データセットの表と同じ行** (ID・データの種類・アクセス制限・公開日) で出す — ID が未発行でもデータの
  種類で見分けられる。新しく公開されるものは印で言う。研究の記述の変更は、研究の内容の画面 (隣に公開
  ページを並べる) への道で読ませる。**答えるのはこの版がどうなるかだけ** — 記述は版の中にあるので、他の
  版には何も起きない
- **公開できない理由** — 公開ゲートが止めるもの (下の「公開ゲート」) があるときだけ立つ。**行ごとに対象を
  名指し** (研究か、どのデータセットか。データセットは上と同じ表の行)、その場で ID を割り当てる欄を持つ。
  提案する ID は行ごとに別の番号にする — 同じ番号を 2 行に出すと、片方を割り当てた時点でもう片方が断られる
- **レビュー** — 共有リンクの状態、未解決のコメントの数、閲覧者の印 (「コメントを書き終えた」「修正の
  必要は無い」を誰がいつ押したか)。**公開は止めない** — 公開するかどうかは admin の判断で ([editing.md](editing.md)
  の「レビュー」)、この節はその判断の材料。**未解決のコメントは研究の内容の画面と同じ面で開き** ([admin-ui.md](admin-ui.md)
  の「コメントの面」)、その場で読んで解決できる — 判断のために別の画面へ移らせない。一覧の下にレビューと共有の画面への道を
  置く
- **確認事項** — 列挙して通す検査。種類ごとにまとめ、その中を「どの画面で直せるか」で並べ、下に確認の
  チェックを 1 つ置く。12 件を 12 行並べる代わりに「未確定の値 12」と出して、そこから編集画面へ行く。
  未公開のファイルはこの節の中で「まとめて公開」できる
- **公開** — 版番号と公開日、押すと何が起きるかの 1 文、押すもの。新しい版なら**空いている番号を 1 つ
  打つ**形で、既定は発行済みの最大 + 1。公開中の番号は画面が並べて言い、打っても弾かれる。公開日の既定は
  今日。**更新の draft (下の「版番号」) では番号を聞かない** — 更新する版の番号をそのまま継ぎ、公開日の
  既定もその版のもの。**押せないときは、押せない理由をボタンが言う** (止めるものがある、更新で変わるものが
  無い)。確認のチェックが無い送信は server が断り、画面の上に答える。**更新で変わるものが何も無いときは押せない** — 記述も公開日も公開中の版と同じなら、更新しても
  公開ページは何も変わらない。server も同じ更新を断る

## 版番号

**版を切るのは編集者の明示的な操作**で、内容の変化から自動判定しない。**版番号は公開時に決める** — 公開の
確認画面で、公開中の版が持っていない番号を 1 つ打つ。既定は公開中の最大 + 1。取り下げで空いた番号も、
その先の番号も選べる。これは採番の規則であって、番号の連続性は保証しない。**draft は版の番号を覚えない** —
下書きは下書きで、どの版から来たかも、どの番号で出るかも持たない。

**公開中の版を直すのは更新。** 版の行の「編集」は、その版の内容を持つ draft を裏で作って開く。**版は
そのまま公開されている** — 直しているあいだも公開ページと検索は元の姿を返し、draft の保存は draft しか
動かさない。直し終えたら公開前の確認の画面で「vN を更新する」を通し、その draft が同じ番号の版になる。
**更新は版の状態で、draft は器にすぎない。** 画面はこの draft を下書きとして出さず、版の行が「更新中」と
言う — 続きを開くのも、やめる (draft を破棄する) のも、その行の操作。**更新中の版は取り下げられない**
(先に更新をやめる)。したがって draft が版を失うことは無く、draft は自分がどの版の更新かを持ち、版 1 つに
1 つ。版の行の「下書きの作成」は別の道で、版を指さない draft (新しい版の元) を作る。

**公開中の版の番号は打てない。** 同じ番号で出す道は更新だけで、更新は draft を消費し、前の版の
行を消し、同じ番号の版の行を作るところまでを 1 つのトランザクションで終える。版が 2 つの姿を持つ瞬間も、
公開ページから消える瞬間も無い。

**中では版の行を書き換えない。** 公開は常に新しい行を作る操作で、行の content が UPDATE される経路を
どこにも持たない。更新も行の UPDATE ではなく、前の行を消して同じ番号の行を作る操作 (前の内容は残らない)。
取り下げは版の行を draft の行に移す操作で、どちらも書き換えではない。

**公開は 1 つのトランザクションで終わる。** 記述を書き、番号を付け、証跡を書き、draft を消費し、
検索用の行をその research のぶんだけ作り直す。**「公開したがまだ検索に出ていない」という状態は存在
しない。**

**公開する dataset の範囲は「公開済みの dataset + この draft が作った dataset」を draft の順で。** 版に
載せる・載せないの選択は無く、順が名指していない dataset は末尾に付く ([data-model.md](data-model.md) の
「research / experiment / dataset」)。**記述は、draft が書いたものがあればそれ、無ければ公開中のもの** —
更新する版、なければそれを載せている最新の版の記述をそのまま引き継ぐ。編集画面が書いていない dataset を
公開中の記述で見せているのと同じ読み方で、書いていないものを空として公開すると、何も直していない draft の
公開が公開済みの dataset の記述を消すことになる。公開前の確認の変更点も同じ読み方で数えるので、書いていない
dataset は変更に出ない。**公開された記述がどこにも無く、draft も書いていない dataset** (この draft が作って
まだ書いていないもの) だけが、ゲートを通した上で空の記述として公開される — 一覧にあるのに存在しない
dataset を作らないため。

## 公開ゲート

検査は 2 種類に分かれる。

**公開を止める検査。** ラベルと関連の構造が揃っていないものは公開できない。確認では超えられない。

- research に hum ラベルが pin されている
- その版が持つ全 dataset に dataset id が pin されている

**列挙して通す検査。** 内容の未完成と上流との食い違いは公開を止めない。未解決を並べて admin が明示的に
通す形にし、**通した記録は証跡に残す** (件数の内訳だけを残す — どの field だったかは、その公開が書いた
版の content から読める)。

- 未確定 (unknown) とマークされた値
- 翻訳対 field の未翻訳
- content が空の dataset
- dataset が選択したファイルのうち非公開のもの
- hum ラベルと dataset id の対応が、JGA 申請管理システム由来のキャッシュと合わないもの

**「別の公開がこの dataset を変えた」は検査しない。** 記述は版の中にあり、他の公開はこの draft の持ち物を
書き換えないので、踏まれるものが無い。他の版との違いを見たいときは編集画面で比べる
([editing.md](editing.md))。

**状態は言語ごとに立つ**ので ([data-model.md](data-model.md) の「値の状態」)、未確定の列挙は
(field, 言語) の単位になる。未翻訳は「両方の言語が値を持ち、片方だけが空」のときだけ立ち、状態が
食い違うときは未確定として数える。**同じ 1 つの欠けが 2 行になることはない。**

**ファイルの列挙は「まとめて公開する」の入口を兼ねる。** ファイルの公開は research の公開とは独立した
操作で、切り替えは実バイトコピーの job になる。列挙されたものをその場でまとめて公開に倒せる形にし、
公開操作そのものは待たせない。**列挙が消えるのは job が終わってからで、公開は待たずに通せる** —
ファイルの在籍は版とは別の軸なので、切り替えの完了を公開の条件にすると数分の待ちが公開に入り込む。
選択を持たない dataset と本文中の URL からの参照は検査の対象外で、そこは突き合わせない。

**上流との検算の対象は JGAD / JGAS に限る。** 申請管理システムが hum と JGAD / JGAS の対応の master
なので、そこに無い対応を pin しているのは疑わしい状態であり、不在も食い違いと同じく列挙する。上流には
typo や版違いでの食い違いの実績があるので、**上流を公開を止める側に置かない。**

**ゲートは画面と公開操作の両方で走る。** 画面が出すのは助言で、通してよいかを決めるのは書き込み側 —
draft の行を掴んだまま検査するので、画面を見てからの数秒に何が起きても判断が古くならない。

## ラベルを pin する

hum ラベルは research の画面で、dataset id はその dataset を書く画面で管理する。どちらも pin した
時点で効き、draft の保存も公開も待たない。公開前の確認の画面から打てるのは、まだ pin されていないものを 1 つ
入れることだけ。

- **pin した時点で台帳に載る** ([data-model.md](data-model.md) の「identity と label」)
- **primary にすると、それまで primary だったラベルは secondary になる。** 旧いラベルが解決し続けるのが
  複数持てることの目的なので、付け替えは消すことではない
- **既に使われているラベルは弾く。** primary と secondary を合わせて一意
- **外部アーカイブに登録しない dataset には `hum{NNNN}-NHA{nnn}` を提案する。** 提案なので書き換えて
  よいが、**`hum` で始まることだけは守る** — その 1 点がポータル発行かどうかの判定になる
  ([data-model.md](data-model.md) の「identity と label」)。番号はその hum の中の通し番号で、飛んでも困らない
- **pin を外した dataset は、その時点で公開版の一覧から落ちる。** 落とすのは検索用の行で、版の content は
  書き換えない — 版が載せた姿は当時の事実であり、いま何が見えるかは検索用の行が決める
- **版番号は台帳に載らない。** research の中でしか一意でないので、版の行そのものが持つ

## 取り下げ

**取り下げは版から番号を外して draft に戻す操作。** 専用の状態を持たない。番号は空き番号になり、内容は
draft として編集できる状態に戻る。**更新中の版は取り下げられない** — 先に更新をやめる (「版番号」)。

**UI 上は単に見えなくなる。** 可視性は検索用の行から決まるので、取り下げは「公開分を作り直したらそこに
居ない」の結果として起きる。

**出ていた姿を凍らせて残す器は持たない。** 取り下げた版の内容はそのまま draft の内容になり、直せば
上書きされる。取り下げは「もう出していない」と言う操作なので、出ていた姿を保存する理由が無い。何が
起きたかは証跡が持つ。

## 破棄と削除

| 操作 | データ | 外から見た挙動 |
|---|---|---|
| draft の破棄 | 関連ごと消える。draft が新規に作った dataset identity も消える | 元から見えていない |
| draft の公開 | draft は消える。作った dataset は版に載って残る | 版として見えるようになる |
| dataset の削除 | 行が消える。pin・エントリ・検索用の行も消える。版の content は当時のまま | 公開ページと一覧からその場で消える。過去の版の一覧では名前だけになる |
| 版の取り下げ | 版の行が draft になる。番号は外れて空く | 見えなくなる。直して出し直せる |
| 版の更新 | draft は消え、前の版の行も消えて、同じ番号の版の行が 1 つ残る | 同じアドレスが直った内容を返す |
| research の削除 | 配下の dataset / experiment ごと消える。hum ラベルと dataset id の pin も外れる。event は残る | 見えなくなる。どちらのラベルも再 pin できる |

**公開は draft を消費し、取り下げは版を消費する。** 同じ内容が版と draft の両方にあると、どちらが正かを
言えなくなる。どちらの向きも行が移るだけで、増えも減りもしない。**更新は両方を消費する** — draft と
前の版が消えて、版が 1 つ残る。

draft の破棄で消えるのは、draft 本体・dataset のエントリ・コメント・共有リンク・その
draft が新規に追加した dataset の identity。既存の dataset に対する編集はエントリが消えるだけで、
identity も pin も動かない。

## 証跡

**公開・更新・取り下げ・研究と dataset の削除・pin 操作・ファイルの公開状態の切り替えと削除・
サイトコンテンツの公開と非公開・admin の付け外しを append-only の event として記録する。** pin 台帳が「いまどうなっているか」を
持ち、event が「そこに至った操作」を持つ。公開ゲートを通した記録もここに入る。ファイルを含めるのは、
公開状態の master が S3 側にあって Postgres に履歴が残らないため。**ファイルの upload は記録しない** —
記録するのは公開されているものを変えた操作で、upload は非公開の箱に入るだけになる。**例外は `common/`
の箱**で、公開 bucket 固定なので置いた時点で公開されているものが変わる。draft の破棄も記録する —
draft 本体は何も残さずに消えるので、消えたことを言えるのが event だけになる。**catalog と語彙は
記録しない** — 定義であって、公開されているものではない。

**取り下げを記録するのは、それが唯一の痕跡になるから。** 版の行は draft に移って消えるので、「v2 が
いつ取り下げられたか」に答えられるのが event だけになる。

**1 回の公開が書く event は 1 つではない。** 版に 1 つ、記述が実際に変わった dataset ごとに 1 つ、ゲートを
通したなら 1 つ。dataset を別に書くのは、identity が版をまたいで続くから — 「この dataset の記述はいつ
何によって変わったか」に、版を横断して答えられる形にしておく。**更新も同じ形で、版の 1 つが
更新の event になる。** 前の行に取り下げの event は書かない — 消えたのは行であって、公開が止まった
わけではない。

- **event は subject に外部キーを張らない。** research を削除しても、そこに至った操作の記録は残る
- **append-only は DB のロールで担保する。** schema を作る owner と、アプリが繋ぐ role を分け、アプリ側に
  event への UPDATE と DELETE を与えない。アプリ側の規律にもトリガにも頼らない — トリガを迂回できる権限が
  あれば、トリガ自身の記録も直せる。**副産物としてアプリはどのテーブルも TRUNCATE できない**ので、DB を
  空にする経路は owner に閉じる
- **記録は変更と同じトランザクションで書く。** 何も変えなかった操作は何も記録しない
- **ログインは記録しない。** 記録するのは公開されているものを変えた操作で、主体は event ごとに焼かれる
- **DB への直接の SQL を緊急避難の経路として残すなら、その分は event に載らないことを前提にする**

## 意図的にやっていないこと

| やらないこと | 理由 |
|---|---|
| 公開時に相手の変更を自動で混ぜること | draft は共有リンクが見せている姿そのもの。混ぜると承認された姿と違うものが出る |
| 版の行を書き換えること | 公開は常に新しい行を作り、取り下げは行を draft へ移す。読まれている行が変わる経路を持たない |
| 版を直しているあいだ、その版を公開から外すこと | 直している数日のあいだ公開ページと検索から消えるのは、読者には取り下げと同じに見える。直すのは更新の draft の側で、版は更新の瞬間まで元の姿のまま |
| 取り下げ・更新で消えた版の内容を残すこと | 版は「いま出ている姿」であって履歴ではない。何がいつ取り下げられ、更新されたかは証跡が持つ |
| 版番号の連続性を保証すること | 採番は導く規則で、可視性は版の行の集合から決まる。連続性に依存する判定を作らない |
| 公開の予約 | いま公開するかしないかの操作だけを持つ。日付は版の属性であって実行の引き金ではない |
| 取り下げた版に「取り下げ済み」と表示すること | 旧 Joomla では痕跡なく消えていた。内容は draft として残るが、外から見える形は変えない |
| 上流の食い違いで公開を止めること | 上流に typo の実績があり、上流が誤っている間ポータルが公開できなくなる |
