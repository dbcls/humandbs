# 公開

下書きを版にする操作と、それを取り消す操作。書く側は [editing.md](editing.md)、モデルの不変条件は
[data-model.md](data-model.md)。

## 版番号

**版を切るのは admin の明示的な操作で、内容の変化から自動判定しない。** 番号は公開のときに決める —
公開中の版が持っていない番号を 1 つ打ち、既定は発行済みの最大 + 1。取り下げで空いた番号も選べる。
**番号の連続性は保証しない**し、それに依存する判定も作らない。

**公開中の版の番号は打てない。同じ番号で出す道は更新だけ。** 更新は下書きを消費し、前の版の行を消して
同じ番号の版の行を作るところまでを 1 つのトランザクションで終える。版が 2 つの姿を持つ瞬間も、公開
ページから消える瞬間も無い。記述も公開日もデータセットの順も公開中の版と同じ更新は断る。

**版の行を書き換えない。** 公開は常に新しい行を作り、更新は前の行を消して作り直し、取り下げは版の行を
下書きの行に移す。読まれている行の content が UPDATE される経路はどこにも無い。

**公開は 1 つのトランザクションで終わる。** 記述を書き、番号を付け、証跡を書き、下書きを消費し、その
研究の検索用の行を作り直す。**公開は研究ごとに直列になる** — 研究の行・そのデータセット・その label の
pin を掴んでから進むので、同じ番号の公開が 2 つ同時に来ると後の方は番号が使えないと断られる。

**公開するデータセットは「公開済み + この下書きが作ったもの」を下書きの順で。** 記述は、下書きが書いた
ものがあればそれ、無ければ公開中のものを引き継ぐ — 書いていないものを空として公開すると、何も直して
いない下書きの公開が公開済みの記述を消すことになる。公開された記述がどこにも無く下書きも書いていない
もの (この下書きが作ってまだ書いていないもの) だけが空の記述で公開される。

**公開日は予約ではない。** 版に書く日付で、未来の日付でも押した時点で公開される。

## 公開ゲート

検査は 2 種類。**ゲートは画面と公開操作の両方で走り、判断するのは書き込み側** — 下書きの行を掴んだ
まま検査するので、画面を見てからの数秒に何が起きても判断が古くならない。

**公開を止める検査** — label の構造が揃っていないもの。確認では超えられない。

- 研究に研究 ID が pin されている
- その版が持つ全データセットにデータセット ID が pin されている

**列挙して通す検査** — 内容の未完成と上流との食い違い。admin が確認して通し、**通した記録 (件数の内訳)
を証跡に残す。**

- 未確定の値 (欄と言語の単位。未翻訳と同じ欠けを 2 度数えない)
- 翻訳対の未翻訳
- 記述が空のデータセット
- データセットが選んだファイルのうち未公開のもの (その場でまとめて公開に倒せる。job の完了は待たない)
- 研究 ID とデータセット ID の対応が、申請管理システム由来のキャッシュと合わないもの (JGAD / JGAS だけ)

**上流との食い違いで公開を止めない。** 上流には typo の実績があり、上流が誤っているあいだポータルが
公開できなくなる。**レビューの状態も公開を止めない** — 共有・未解決のコメント・閲覧者の印は判断の材料で、
公開するかは admin が決める。**「別の公開がこのデータセットを変えた」は検査しない** — 記述は版の中に
あり、他の公開はこの下書きの持ち物を書き換えない。

## label を pin する

研究 ID は研究の画面で、データセット ID はそのデータセットの画面で管理し、公開前の確認の画面からは
未 pin のものに 1 つ入れることだけができる。どちらも pin した時点で効き、保存も公開も待たない。

- **primary を付け替えると、前の primary は secondary になる。** 旧い label が解決し続けることが、
  複数持てることの目的
- **既に使われている label は弾く。** primary と secondary を合わせて一意
- **外部アーカイブに登録しないデータセットには NHA ID を発行する。** 欄に打てるのは外部アーカイブの
  accession だけで、発行は次の番号を欄に出すだけ。確定は割り当ての操作で、その時点で番号を読み直す
- **pin を外したデータセットは、その時点で公開版の一覧から落ちる。** 版の content は書き換えない
- **公開の箱にファイルがあるか切り替えが終わっていない研究 ID は外せない** ([files.md](files.md))。
  研究の画面はその「解除」を押せない形にして理由を出す

## 取り下げと削除

**取り下げは版から番号を外して下書きに戻す操作。** 専用の状態も「取り下げ済み」の表示も持たない。
可視性は検索用の行から決まるので、外から見ると単に見えなくなる。取り下げた版の内容はそのまま下書きの
内容になり、出ていた姿を凍らせて残す器は持たない。何が起きたかは証跡が持つ。

| 操作 | データ | 外から見た挙動 |
|---|---|---|
| 下書きの削除 | 下書き・エントリ・コメント・共有リンク・下書きが作ったデータセットが消える | 元から見えていない |
| 下書きの公開 | 下書きは消え、作ったデータセットは版に載って残る | 版として見える |
| 版の更新 | 下書きと前の版の行が消え、同じ番号の版が 1 つ残る | 同じアドレスが直った内容を返す |
| 版の取り下げ | 版の行が下書きになり、番号が空く | 見えなくなる |
| データセットの削除 | 行・pin・エントリ・そのデータセットに付いたコメント (どの下書きのものも) が消え、研究の検索用の行を同じトランザクションで作り直す。版の content は当時のまま | 公開ページと一覧からその場で消える |
| 研究の削除 | 配下ごと消え、label の pin も外れる。event は残る。箱にファイルが残るあいだは断り、研究の画面も押せない形にする ([files.md](files.md)) | 見えなくなる。label は再 pin できる |

**公開は下書きを消費し、取り下げは版を消費し、更新は両方を消費する。** どの向きも行が移るだけで、同じ
内容が 2 か所に残らない。

## 証跡

**公開されているものを変えた操作を append-only の event として記録する** — 公開・更新・取り下げ・
研究とデータセットの削除・label の pin・ファイルの公開状態の切り替えと削除・`common/` の upload・
サイトコンテンツの公開状態・admin の付け外し・下書きの削除・ゲートを通したこと。pin 台帳が
「いまどうなっているか」を、event が「そこに至った操作」を持つ。ファイルを含めるのは、公開状態の master
が S3 にあって Postgres に履歴が残らないため。

- **記録しないもの** — ログイン、研究の箱への upload (非公開の箱に入るだけ)、catalog と語彙 (定義で
  あって公開されているものではない)
- **1 回の公開は複数の event を書く** — 版に 1 つ、記述が変わったデータセットごとに 1 つ、ゲートを
  通したなら 1 つ。データセットの記述がいつ何で変わったかを版を横断して答えられるようにする
- **event は subject に外部キーを張らない。** 研究を削除しても記録は残る
- **記録は変更と同じトランザクションで書く。** 何も変えなかった操作は何も記録しない
- **append-only は DB の role で担保する。** schema の owner とアプリが繋ぐ role を分け、アプリには
  event の UPDATE と DELETE を与えない。副産物としてアプリはどの表も TRUNCATE できない
- **DB に直接 SQL を打った分は event に載らない。** それを前提にする

## 意図的にやっていないこと

| やらないこと | 理由 |
|---|---|
| 公開の予約 | 日付は版の属性であって実行の引き金ではない |
| 版を直すあいだ公開から外すこと | 読者には取り下げと同じに見える |
| 取り下げ・更新で消えた版の内容を残すこと | 版は「いま出ている姿」で履歴ではない。何が起きたかは証跡が持つ |
| 取り下げた版に「取り下げ済み」と表示すること | 外から見える形は変えない |
| 版番号の連続性の保証 | 可視性は版の行の集合から決まる |
| 上流の食い違いで公開を止めること | 上流が誤っているあいだ公開できなくなる |
