# 用語

この repo の docs とコードで使う語の意味と、語どうしの関係をまとめる。決まりはリンク先の doc にあり、この文書には意味だけを書く。画面に表示する文言 (日本語と英語) の正本は `app/i18n/messages.ts` であり、この文書では訳語を決めない。API と絞り込みに出る英語の値 (`Unrestricted-access` など) を変えないという保証は [public-api.md](public-api.md) にある。

## 研究とバージョンと下書き

ポータルが扱う単位は研究である。研究の内容は、公開したバージョンと未公開の下書きに分けて保存する。

### 研究

研究は、1 つの研究課題と、その研究課題に属するデータセットの集まりである。コード上は `research` で、`research` の行には ID も内容も保存しない。内容はバージョンと下書きに、研究 ID は ID の割り当て表に保存する。admin は、研究 ID が決まる前に研究を作れる。申請が承認される前から、admin が研究の内容を書き始め、ファイルをアップロードすることがあるためである。

### 研究とデータセットの実体

研究とデータセットの行 (`research`、`dataset`) を実体と呼ぶ。コード上は identity と呼ぶ。実体は、外から見える ID とは別に、ポータルの中だけで研究とデータセットを識別するものである。ID を直しても、実体を指す参照 (管理画面の URL、下書き、非公開のファイル) はそのまま使える。研究 ID は、人が JGA 申請管理システム (以下、申請管理システム) に入力する文字列で、入力の誤りの訂正が日常的に起きる。そのため、実体と ID を分けている ([data-model.md](data-model.md) の「実体と ID」)。

### バージョン

バージョンは、公開した時点の研究の内容である。コード上は `research_version` で、研究の内容と、そのバージョンに載せた全データセットの内容を 1 つにまとめて保存する。バージョン番号は研究の中で一意で、公開のときに決まる。バージョンの行があることが「公開中」を意味する。admin がバージョンを取り下げると、バージョンは下書きに戻る ([publishing.md](publishing.md))。

### 下書き

下書きは、研究の未公開の作業コピーである。コード上は `research_draft` で、1 つの研究に複数作れる。admin が下書きを公開すると、下書きは消えてバージョンになる ([editing.md](editing.md))。

### 公開中のバージョンの更新

公開中のバージョンの更新は、公開中のバージョンを、番号を変えずに直す操作である。admin は、直す内容を、そのバージョンから作った下書きに書く。admin がその下書きを公開すると、その下書きは同じ番号のバージョンと入れ替わる。コード上は、下書きの `replacesVersionId` が更新元のバージョンを指す ([editing.md](editing.md) の「公開中のバージョンの更新」)。

## データセットと解析手法

データセットは、研究に属するデータの単位である。解析手法は、データセットの中でデータの作り方を書く要素である。

### データセット

データセットは、アーカイブに登録された 1 まとまりのデータである。コード上は `dataset` で、1 つの研究だけに属する。データセットにバージョンは無く、データセットの内容の訂正は研究のバージョンの更新で行う。データセットの内容は、バージョンの中と、下書きごとの行 (`draft_dataset_entry`) に保存する ([data-model.md](data-model.md) の「研究の内容の保存形式」)。

### 解析手法

解析手法は、データセットの中で、プラットフォームや試料などデータの作り方をまとめた 1 件の要素である。コード上は `experiment` で、画面では「解析手法」と表示する。解析手法は、データセットの内容の中に順序付きで並ぶ要素で、独立した行は無い。

### 公開区分

公開区分は、データセットを誰が使えるかの区分で、非制限公開・制限公開 (Type I)・制限公開 (Type II) の 3 つである。公開区分は、データセットの項目の 1 つ (語彙 `access-criteria`) の値として、データセットの内容に入る。公開区分の値の追加や言い換えは、画面からできない。

## ID

外から参照される ID は、研究とデータセットの実体に後から割り当てる。

### 研究 ID

研究 ID は `hum` と 4 桁の数字 (`hum0014`) である。コード上は hum ラベル (label の種類 `hum`) と呼ぶ。

### データセット ID

データセット ID は 3 種類あり、どれも同じ割り当て表で管理する。

- JGAD は、JGA に登録された制限公開のデータセットの ID である。ポータルは、JGAD を申請管理システムから読む。
- NHA ID は、ポータルが発行するデータセット ID で、`NHA` と 6 桁の通し番号 (`NHA000001`) である。発行の決まりは [data-model.md](data-model.md) の「NHA ID」にある。
- 外部 accession は、DRA など他のアーカイブの ID である。ポータルは、外部 accession の日付や登録内容を DDBJ Search から読む。

### ID の割り当て

ID を実体に付けることを、コード上は pin と呼ぶ。付けた ID はコード上は label と呼び、`label_pin` の行として保存する。研究 ID とデータセット ID は、この 1 つの表 (ID の割り当て表) で管理する。バージョン番号も外から見える番号だが、研究の中でだけ一意なので、ID の割り当て表ではなくバージョンの行に保存する。

1 つの実体に複数の ID を付けられる。そのうち 1 つが primary の ID で、残りが secondary の ID である。primary と secondary は、画面のバッジに表示する語である。公開ページの URL と表示には primary の ID を使う。secondary の ID は、古い ID で参照されても同じ実体にたどり着けるように残す。一意性と再利用の決まりは [data-model.md](data-model.md) の「実体と ID」、割り当ての操作は [publishing.md](publishing.md) の「ID の割り当て」、公開ページでの扱いは [public-site.md](public-site.md) の「URL」にある。

### データ提供申請と枝番

データ提供申請は、申請管理システムに出される申請で、`J-DS` から始まる番号が付く。1 つの申請の書類は、枝番 (`J-DS000136-010` の末尾) ごとに分かれる。承認された枝番 1 つが、登録 1 回に当たる。ポータルは、承認済みの枝番から下書きを作り、値を取り込む ([editing.md](editing.md) の「申請から研究を作る」)。ポータルは申請管理システムを読むだけで、書き込まない。研究 ID と J-DS の対応の正本も申請管理システムにある。

## 研究の内容と項目

研究の内容とデータセットの内容は、決まった型の JSON として保存する。

### 研究の内容とデータセットの内容

研究の内容とデータセットの内容は、公開ページに表示する値の集まりである。コード上は `content` (JSONB の列) で、画面の語は「研究の内容」である。型は `app/content/types.ts` にあり、バージョンと下書きで同じ型を使う ([data-model.md](data-model.md) の「研究の内容の保存形式」)。

### 公開用の表示データ

公開用の表示データは、研究の内容から公開してよい値だけを残したものである。型は研究の内容と同じである。公開ページ・プレビュー・全文検索には、公開用の表示データを使う ([data-model.md](data-model.md) の「公開用の表示データ」)。

### 項目定義と語彙

データセットと解析手法には、決まったキーの下に値を並べる。キーの一覧を項目定義と呼ぶ。コード上は `content_key` (catalog) で、画面では key と表示する。決まりは [catalog.md](catalog.md) にある。

- キーには型がある。型が語彙か疾患のキーと、型が数値で絞り込みのカテゴリを設定したキーは、公開サイトの絞り込みの項目になる。それ以外のキーは自由記述である。
- 絞り込みのカテゴリ (`facet_category`) は、公開サイトの絞り込みの項目をまとめる見出しである。カテゴリと、どの項目をどのカテゴリに入れるかは開発の作業で決め、管理画面からは変えない。管理画面で変えられるのは、データとともに増える語彙の値だけである。
- 語彙は、選択肢の値の集まりである (`vocabulary_set` と `vocabulary_term`)。研究の内容は語彙の値を ID で参照するので、語彙の値の表示名を変えても、研究の内容を書き換えずに済む。

### 値の状態

項目の値には、値がある状態のほかに「未確定」と「該当なし」の状態がある。コード上は `unknown` と `not-applicable` である。状態は、日本語と英語で別々に決める。保存の形と表示の決まりは [data-model.md](data-model.md) の「値の状態 (未確定・該当なし・未翻訳)」にある。

- 未確定は、値があるはずだがまだ決まっていないことを表す。プレビューでは、未確定の値を提供者への問い合わせ (「ご教示ください」) として表示する。公開前の確認では、未確定の値を一覧に表示する。
- 該当なしは、値が無いと確定していることを表す。公開ページには `N/A` と表示する。
- 空は状態ではなく、「値があって中身が空」である。まだ誰も書いていない欄は、空に当たる。
- 未翻訳は保存する状態ではない。翻訳の組で片方の言語だけが空のときに、値から未翻訳と決まる。

### 更新番号

更新番号は、保存のたびに 1 増える整数である。下書きと、下書きごとのデータセットの内容に、それぞれ付く。コード上は `revision` である。アプリは、同時に編集した人の変更を上書きしないように、保存のときに更新番号を照合する ([editing.md](editing.md) の「同時編集と保存」)。

## 公開とレビュー

下書きは、提供者のレビューと公開前の確認を経てバージョンになる。

### 共有リンクとプレビュー

共有リンクは、下書き 1 つにつき 1 つの、ログインせずに読める URL である。共有リンクを開くと、プレビュー (公開したときと同じ見た目の下書き) が表示される。共有リンクを開いた人は、プレビューの各欄にコメントを書ける ([editing.md](editing.md) の「レビュー (共有リンクとコメント)」)。

### 公開前の確認

公開前の確認は、公開の操作の前に下書きを検査する手順である。ID が揃っていない下書きは公開できない。未確定・未翻訳・申請管理システムとの食い違いは、アプリが一覧に表示し、admin が確認した上で公開する ([publishing.md](publishing.md) の「公開前の確認」)。

### 検索用の行

検索用の行は、公開中の研究・バージョン・データセットごとに作る行である (`search_doc` など)。公開ページ・検索・JSON API のどれでも、アプリは公開中の研究・バージョン・データセットを検索用の行から読む ([data-model.md](data-model.md) の「検索用の行」)。

## 記事・お知らせ・アラート

研究とは別に、ポータルには記事・お知らせ・アラートがある。記事・お知らせ・アラートのどれにも、研究のバージョン・下書き・ID の割り当てを使わない ([site-content.md](site-content.md))。

- 記事は、URL が slug で決まるページ (ガイドラインなど) で、コード上は `document` である。改訂を残したい記事は、バージョンごとに別の記事として作る。この形の記事を「バージョンのある記事」と呼ぶ。記事のバージョンは slug の末尾の番号で、研究のバージョンとは別のものである。
- お知らせは、日付の付いた告知で、コード上は `news` である。
- アラートは、全ページの上部に表示する 1 文で、コード上は `alert` である。アラートはお知らせとは別のものなので、画面でも「お知らせ」とは呼ばない。

## ファイル

データファイルは、DB ではなくファイルストアに保存する。ファイルの公開と非公開の切り替えは、ジョブで行う ([files.md](files.md))。

### 研究ごとの prefix

研究ごとの prefix は、ファイルストアの bucket の中で、1 つの研究のファイルをまとめる key の先頭部分である。非公開の bucket (`private`) の prefix は研究の実体の ID で作り、公開の bucket (`files`) の prefix は研究 ID で作る。prefix を扱うコードは `app/files/prefix.ts` にある ([files.md](files.md) の「2 つの bucket と研究ごとの prefix」)。

### ジョブ

ジョブは、時間のかかる処理を DB の行として登録し、アプリのプロセスが後から実行するものである。専用の worker は使わない。

- ファイルの公開と非公開の切り替え (`file_publish_job`) は、ファイルの中身を bucket 間でコピーするので、公開の操作とは別に実行する ([files.md](files.md) の「公開・非公開の切り替え」)。
- 申請管理システム・DDBJ Search・DDBJ の公開 FTP からの取得 (`upstream_refresh`) は、取得元ごとに、配置先で決めた間隔で実行する ([upstream.md](upstream.md) の「取り直しと失敗」)。
