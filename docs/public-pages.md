# 公開画面

読者が認証なしで見る画面と、その URL。編集画面はここに含まれない。機械が読む JSON は
[public-api.md](public-api.md) で、**同じ公開集合の別の出口**になる — 何が公開されているかの判定と
検索の受け口は共有し、応答の形と約束するものが違う。

## URL 体系

骨格は現行ポータルと同じにしてある。外部が焼き込んでいるのは HTML ページの URL とファイルの URL だけで、
形を変えると得るものが無い。

| URL | 中身 |
|---|---|
| `/` | トップ |
| `/research` `/dataset` | 一覧 = 公開検索 (`?q=` `?sort=` `?page=`) |
| `/research/{humId}` | 最新公開版 |
| `/research/{humId}/v{n}` | 版指定 |
| `/research/{humId}/versions` | リリース情報 (公開版の一覧) |
| `/dataset/{datasetId}` | dataset |
| `/research/export` `/dataset/export` | 一覧の結果を表で渡す (`?format=csv` / `?format=copy`) |
| `/cart` | 利用申請に持っていくデータセットの控え |
| `/data-submission` `/data-use` `/contact-us` | 提供・利用・問い合わせの入口 |
| `/news` `/news/{id}` | お知らせの一覧と個別 |
| `/{slug}` | document。`guidelines/data-sharing-guidelines` のように `/` を含む |
| `/{humId}` `/{humId}-v{n}` `/{humId}-latest` `/{humId}-v{n}-release` `/{humId}-latest-release` | 上のいずれかへの redirect |
| `/en/…` | 上のすべての英語版 |

**到達性を約束するのは research のページ (最新公開版と版指定)、裸の hum ID、そして document の slug。**
DDBJ Search が `/{humId}` の形でリンクを組み、外部の submission metadata がガイドラインの slug を焼き
込んでいるので、どちらも恒久的に応答し続ける必要がある。ファイルの URL は約束の対象にしない
([data-model.md](data-model.md) の「ファイル」)。

**document は catch-all が受け、hum ラベルと旧アドレスの解決を先に済ませる。** 順序がそのまま優先順位に
なるので、document が research のアドレスを横取りすることが起こらない。route が持つアドレスの一覧は
`app/public/urls.ts` の `SCREEN_PATHS` にあり、**この一覧にある slug の document は作れない** — 作っても
route の後ろに隠れて届かない。

**redirect は server 側で返す。** 現行は裸の hum ID を client side の redirect で救っているため、
JS を実行しないクライアントに届いていない。

## 言語

**日本語には prefix が付かず、英語は `/en` の下に居る。** 日本語に prefix を付けると、既に書き留められた
すべてのアドレスの前に redirect が挟まる。`/ja/…` も応答するが redirect で、**1 つのページが持つ
アドレスは 1 つ**に保つ。

言語は URL からだけ決める。cookie も `Accept-Language` も見ない — 誰が開いても同じページが出て、
リンクが「どの言語を指すか」を名指しできる必要がある。

**未翻訳のフォールバックはページ単位で 1 度だけ告げる。** 片言語しか埋まっていない値は、もう一方の
言語の値を出したうえでページ上部に注記を置く。欄ごとに印を付けない — 言語が丸ごと入っていないページでは
すべての欄が印だらけになる。CAU は content ではないので (同節) この注記の対象から外れる。

**これは research 系の規則で、サイトコンテンツには当てはまらない。** document と news は locale ごとに
公開状態を持つので、公開されていない言語は**もう一方に倒れず 404 になる** (「サイトコンテンツ」)。

## 何を根拠に「公開されている」と言うか

**research 系は `search_doc` からしか集合を引く** ([data-model.md](data-model.md) の「検索用の行」)。
ページに固有なのは順序だけで、**ラベルの解決 (pin 台帳) と公開判定は別の手順**、この順に行う。

**サイトコンテンツは公開状態の列そのものが根拠になる。** 版も pin も検索行も持たないので、
`document_content` / `news_content` の `published` が立っている行が公開されているものになる。**版なし
slug は指し先を 1 段辿ってから同じ判定を受ける**ので、公開されていない版を指したまま張り替えを忘れると
その言語で 404 になる (「ガイドラインの版」)。

**secondary のラベルで辿り着いたら primary のアドレスへ redirect する。** 旧 dataset id と typo された
hum ラベルは記事の地の文・申請書・URL の fragment から参照されていて書き換えられない
([data-model.md](data-model.md) の「identity と label」)。

**公開されていないものと、存在しないラベルは同じ 404 を返す。** 区別できると、未公開の research が
あることが外から分かる。

## 本文の書式

**どう持つかは [data-model.md](data-model.md) の「値と文」。** 描く側で決まるのは 2 つだけ。

**research 系の木はそのまま描く。** 行の切れ目が改行になり、span は文字かリンク 1 つになる。**HTML 文字
列を作る経路が無い**ので、値に書かれた文字が markup になることはなく、sanitize する対象も無い。
**サイトコンテンツは markdown 文字列**なので `app/public/markdown.server.ts` が server 側で HTML にする。
生 HTML を parse しないから**出せる要素の集合は markdown が表せる集合で決まる**。これは PBT で守る。

**引用は注記として出す。** 文書の中の `>` は引用ではなく但し書き (「この版は差し替えられた」「違反者は
ここに載る」) なので、[ui.md](ui.md) の注記の器に入れて描く。器も ⓘ の字形も部品から取るので、画面の
注記と記事の注記が離れることはない。**この器だけが markdown に対応する記法を持たない要素**で、PBT は
引用が入力にあるときだけそれを許す。

**リンクの行き先は描く時点でもう一度検査する。** `http` / `https` / `mailto` とサイト内の絶対パス以外は、
文字だけを出してリンクにしない。木は生 HTML の経路を塞ぐが、リンクの URL に `javascript:` と書く経路まで
は塞がないため。保存時にも弾くので検査は 2 箇所にあり、**ここが最後の砦になる**。サイトコンテンツでは
markdown のリンクと画像の行き先が対象。

## ページの中身

**version が持つのは dataset の identity の列だけ**なので、過去版を開くと dataset の一覧は当時のもの、
各 dataset の記述は最新になる。この非対称がそのまま画面に出る。

### research の版 (`/research/{humId}`, `/research/{humId}/v{n}`)

2 つは同じ画面で、違うのは 2 つだけ — 「最新」のバッジか最新版へのリンクか、そしてパンくずの終わり方。
節は研究題目 / 研究概要 / データセット一覧 / ダウンロード / 提供者情報 / 研究プロジェクト情報 /
助成金情報 / 関連論文 / 制限公開データの利用者一覧。

**版を名指すアドレスでは、研究そのものが 1 段上になる。** `/research/{humId}/v{n}` のパンくずは
研究一覧 → hum ラベル → `hum0103-v1` で終わる。`/research/{humId}` と同じ終わり方をすると、読者は
別のアドレスに居ることになり、しかもそこへ戻る道がパンくずから消える。

**ダウンロードの節は公開 bucket の箱を list したもので、hum 単位。** content には無く、dataset の選択
からも作らない ([data-model.md](data-model.md) の「ファイル」)。**箱は版を持たないので過去版のページにも
現在の箱が出る** — dataset の記述と同じ性質なので、下の断りが両方を受け持つ。

- **名前順に並べ、100 件を超えたらページを送る。** 一覧の出所はストアの list なので、どこで切るかも
  server が決める。ファイルを持つ箱の 85% は 5 件以下なので、この分岐が見えるのは大箱だけになる
- **list が取れなければ節ごと出さない。** ページの他の部分は外部の可用性に左右されない
- 行き先は `/files/{humId}/{名前}` で、前段の proxy が `nosniff` と `Content-Disposition` を付ける

**experiment はここに出さない。** dataset に属するものなので dataset のページで見る。旧記事が
分子データ節を assay 中心に並べていた順序は復元できないので、再現もしない。

**過去版のページには「データセットの記述は現在のものを表示している」と明記する。** 版が凍結するのは
research content と dataset の一覧までで、各 dataset の記述は最新になる ([data-model.md](data-model.md) の
「research / experiment / dataset」)。断らないと、読者は版全体が当時の姿だと読む。

**content にあってこの画面に出さない field がある** — 提供者の ORCID・メールアドレス・所在地。
content にも JSON API にも残るが、公開ページには描かない。**画面に出す field を決めるのは描画側**で、
公開表現 (`app/content/public.ts`) はこの判断をしない。落とすことしかしないという公開表現の性質と、
画面がその一部だけを描くことは別のことになる。

### リリース情報 (`/research/{humId}/versions`)

公開版を新しい順に並べ、版ごとに「このリリースで追加されたデータセット」「リリースノート」「公開日」を
出す。

**追加されたものは、隣り合う *公開版* どうしの差で決める。** 取り下げた版は公開集合に居ないので比較から
外れ、その版が入れた dataset は次の公開版の追加分として現れる。番号の隣ではなく集合の隣で比べるのは、
読者が開けない版との差を見せないため。

### dataset (`/dataset/{datasetId}`)

公開日 / 更新日 / 研究 / データの種類 / アクセス制限 と、解析手法。

**「データの種類」と「アクセス制限」は画面が場所を決めて置く。** どちらも catalog のキーに紐づく値
スロットだが ([data-model.md](data-model.md) の「catalog と語彙」)、読者が最初に探すもので、アクセス制限は
バッジとして描く。表示ラベルは catalog から引くので rename は効く。**解析手法の中の値は catalog の
表示順**で並ぶ。

日付は公開表現が 1 つに解決したものを出す — ポータルが発行した id は content の値、外部 accession は
上流のキャッシュ ([data-model.md](data-model.md) の「日付」)。公開ページが読むのは検索用の行に焼かれた
その値で、preview だけは行を持たないので同じ関数をその場で通す。

**この dataset が選んだファイルは注記として出す。** 研究のダウンロード節が箱の全部なのに対して、
こちらは「この dataset のデータはこれ」を指す部分集合になる。**箱の list に無い名前は出ない**ので、
非公開に倒したファイルは同時に消える。選択が空なら節ごと出ない。

**疾患は公開ページに出す。** 構造化スロットは既定では facet としてだけ使うが、疾患は読者がこの画面で
見たい値であり、**公開表現に載ることが「ICD10 のコードで検索窓から引ける」の前提**になる — 全文は
公開表現から作るので (「検索用の行」)、出さないキーの値は窓から引けない。同じ理由で疾患は JSON API の
応答にも載り、**ICD10 のコードが外部との共通鍵になる**。

## 一覧と検索

**一覧 (`/research` `/dataset`) は公開検索そのもの**で、2 つは同じ枠を共有する。違うのは引く行の種類と
表の列だけで、検索窓・件数・条件のチップ・並び替え・ページ送りは同じ部品になる。research の一覧は
research の行を、dataset の一覧は dataset の行を引く。**版の行は引かない** — 引くと同じ研究が版の数だけ
並ぶ。

### 検索窓

**置くのはトップと一覧の 2 か所で、ヘッダには置かない。** トップの窓は研究一覧へ送り、よく打たれる語を
3 つ添える。**同じ箱が 2 つの一覧の上に出る**ので、窓は探している対象を言う — 「キーワードで研究を検索」
と「キーワードでデータセットを検索」。**それは窓の名前でもある** (`aria-label`)。読み上げは中の薄い字を
読まないので、名前を対象ごとに分けないと、見えている人にだけ分かる違いになる。

**一覧の上の窓は、打つのをやめると自分で検索する。** 打鍵が止まってから投げるので、1 語打つあいだに
何度も走ることはない。**日本語を変換しているあいだは走らない** — 書きかけの仮名は、まだ誰も探して
いない語になる。**トップの窓だけは走らない**: そこは別の画面へ送る窓なので、語の途中でページが
変わってしまう。**ボタンはどの窓にも残る** — キーボードだけで操作する人と、script を実行しない
クライアントにとっては、それが窓の意味そのものになる。

**窓に打つのはキーワードであって検索式ではない。** 区切り方は 3 つだけ。

| 打ち方 | 意味 |
|---|---|
| 空白で区切る | すべてを含むもの |
| カンマで区切る | どれかを含むもの |
| `"..."` で囲む | その並びのまま (空白を含む語はこう書く) |

窓の中身は検索式のパーサに渡さない。**記号を含む語がそのまま打てる**のはこの分担による — `NGS(Exome)`
は括弧ごと 1 つの語になり、アドレスへ書き出すときにクオートされる。

### アドレスは常に検索式

`?q=` には検索式が入る (`app/search/dsl.ts`)。窓からの送信は `k` として届き、**そこから作った木を
書き出したアドレスへ redirect する** — 1 つの検索が 1 つのアドレスを持ち、共有でき、JavaScript を
実行しないクライアントでも動く (窓は GET の form)。

**窓に出せない条件は、結果の上に外せるチップとして出す。** 窓に出ないものが黙って効いている状態を
作らない。読み取れない `?q=` は、結果を出さずに読み取れなかったことを告げる。

**facet の条件は `キーの code : 語彙値の code` で書く** (`platform:hiseq-2500`)。数値は範囲で
`read-length:[100 TO 150]`、片側だけなら `[100 TO *]`。id を載せないのは、**rename が表示ラベルの
変更でしかないという規則をアドレスの側でも成立させる**ため — ラベルを載せると rename のたびに共有済みの
アドレスが黙って 0 件になり、id を載せると何で絞ったのか読めなくなる
([data-model.md](data-model.md) の「catalog と語彙」)。

### 絞り込み

**絞り込んだ状態はアドレスに載る。** 値を選ぶと、その条件を足した (あるいは外した) アドレスへ行く。
**選ぶことと外すことが同じリンク**なので、絞り込みの側は状態を持たず、絞り込んだ結果はそのまま共有でき、
戻れば 1 つ前の条件に戻る。数値だけは両端を打つ必要があるので GET の form で、一覧はそれを**アドレスへの
redirect で答える** — 窓からの検索と同じ扱いになる。

**置き場は一覧の横の常設のパネルで、facet ごとに畳む。** 一度に全部開くと縦が数千 px になり、
読者は語彙をすべて通り過ぎてから結果に着くことになる。畳めば「何で絞り込めるか」の一覧が視界に残り、
それがまだ何も選んでいない読者の読んでいるものになる。

**何が開いているかは覚えずに導く。条件が入っている区画は必ず開く** — 効いている絞り込みが見えない
一覧は、自分について嘘をつく。加えて先頭のカテゴリは常に開く (何も開いていないパネルは、絞り込める
ものが無いように読める)。畳み方は状態を持たないので、アドレスにも載らない。

**並びは facet のカテゴリと catalog の順、値は件数の降順。** 0 件の値は出さないが、**選んだ値は 0 件でも
残す** — 外す手段が消えるため。

**件数は、その facet 自身の条件だけ外した集合で数える。** 全条件で数えると 1 つ選んだ瞬間に同じ facet の
他の値が 0 件になって消え、複数選べなくなる。選んでいない facet は全条件で数える。

**一度に出すのは facet ごとに上位 10 件までで、残りは同じ一覧の `?facet=<キーの code>` が全部出す。** 語彙は数百から
1 万件の規模があるので、全部を毎回送れない。展開した側だけが自分の窓を持つ。

**ICD10 はどちらでも 3 桁で数え、全値を出した側でだけ配下の 4 桁がぶら下がる**
([data-model.md](data-model.md) の「検索用の行」)。フラットな語彙では根が語彙値そのものなので、同じ
規則がそのまま当てはまる。

**疾患だけはコードを打つ入力欄を併せて持つ。** 値の一覧から選ばせる形だけでは足りない — 語彙値は
3 桁の根に散り、その半分近くが研究を 1 件しか指さないので、目当てのコードは全値を開いてから探すことに
なる。**打ったコードは値を選んだのと同じ条件になる**ので、ロールアップも件数の数え方も一覧から選んだ
ときと変わらない。点の有無と大文字小文字は問わない。

**辞書があるので、返す言葉を 3 つに分けられる** ([data-model.md](data-model.md) の「ICD10」)。

| 打たれたもの | 返すもの |
|---|---|
| 語彙にあるコード | その条件を足したアドレスへ |
| ICD10 にはあるが、公開データが 1 件も持たないコード | そのコードのデータが無いこと |
| ICD10 に無いコード | コードとして存在しないこと |

これは検索窓に検索式を打たせないという決定と衝突しない。**入力欄が作るのは facet の選択であって、
窓の文法ではない**。窓に打った `C34` は今までどおり全文の部分一致で、本文に `C34` を含む別の値にも
当たる。

**選んだ値はチップにも出る。** 絞り込みの側がどこにあっても、いま何で絞っているかは結果の上で分かる。

### 並びと件数

**並びは選べ、既定は検索語の有無で変わる。** 語があれば全文検索のスコアの降順、無ければ研究一覧は
更新日の降順・dataset 一覧は id の昇順。**同点の並びを日付と id で固定する** — 順位が揺れると、ページを
めくったときに同じ行が 2 度出る。

**結果には、もう一方の一覧を同じ語で引いた件数を添える。** 窓が 1 つのまま両方の一覧に届く。

**0 件のときに緩和した検索を投げない。** 見つからなかったことと、もう一方の一覧と、打ち方の案内だけを
出す。「この語を外せば n 件」を出すには外し方の数だけ検索することになる。

**ラベルを打ったときの特別扱いを持たない。** 完全一致を別枠に出すことはせず、全文検索の結果として
並べる。裸のラベルは URL の側が redirect で受けている。

### ページ送り

**番号は現在のページから離れるほど間隔が開く。** 3 つ隣までは 1 つずつ、その先は 7 / 15 / 31 … と
倍々に離れ、**最初と最後は常に出る**。狙いは「どのページからどのページへも数回で届く」ことで、
そこだけが読者に効く。前後 2 ページだけを出す形と、全ページ対の最悪値で比べると:

| ページ数 | 前後 2 ページ | この形 |
|---:|---:|---:|
| 34 (お知らせ) | 9 回 | **3 回** |
| 50 (dataset 一覧) | 13 回 | **3 回** |
| 1,283 | 321 回 | **6 回** |

出るリンクの数はページ数の**対数**でしか増えないので、一覧がどれだけ長くなっても十数個に収まる。
狭いところに置くときは上限を渡せて、**削るのは隣のページから**になる — 倍々の段が回数を抑えている
ものなので、そちらは落とさない (隣は「次へ」でも 1 回で届く)。したがって**上限は目安**で、段だけで
それを超える長さの一覧では超えたまま出る。この repo の一覧はどれも 50 ページ以下なので、そこには
届かない。

**番号のあいだに省略の印を置かない。** この間隔では隣り合う番号の大半が連続していないので、印のほうが
番号より多くなる。飛んでいることは番号そのものが言っている。

**表の上と下の両方に置く。** 20 行は窓より長いので、下だけだと「次のページへ行く」が「1 ページ読み
終える」の後ろに隠れる。

### 結果を持ち出す

一覧の見出しの横に 2 つ — クリップボードへの「コピー」と、CSV のダウンロード。どちらも
`/{一覧}/export` が答え、**アドレスを一覧と同じに読むので、渡されるのは画面に出ている検索そのもの**に
なる。

- **渡すのは全件で、見ているページではない。** 「この結果を書き出す」が真になる読み方はこれだけで、
  母数は最大でも検索行の全体 (約 2,000 行) にとどまる
- **列は画面より多い。** 表は絞り込みパネルの横に収まる必要があるが、ファイルにはその制約が無い
- **CSV は BOM から始まる。** 付けないと Excel が UTF-8 と読まず、日本語の題目が化ける
- **`=` `+` `-` `@` で始まる値には `'` を前置する。** どちらの形も表計算で開かれることを前提に書いて
  いるので、表計算がその値を数式として評価することまでが書き出しの責任になる。題目は提供者が書く
  自由文で、クオートしても評価は止まらない。機械可読な経路は JSON API の側にある
- **コピーはタブ区切りで、値の中の改行とタブは空白に潰す。** 貼り付け先はクオートを解釈しないので、
  潰さないと 1 つの値が列や行を増やしてしまう

## カート

制限公開データの利用申請は JGA の申請システムで行う。ポータルがするのは**申請書に貼る accession を
集めること**で、カートの出口は `/cart` に出る JSON ひとかたまりになる。

- **中身はブラウザだけが持つ** (`sessionStorage`)。行も、アカウントとの結び付きも、移行の対象も無い
- **入るのは JGAD の dataset だけ。** 非制限公開のデータに申請は要らず、ポータルが振った id は申請
  システムが知らない
- **上限は 100。** 申請書は人が確認するもので、最大の研究は dataset を 200 以上持つ
- **`localStorage` ではない。** 共有端末で前の人の控えが残らないほうがよく、訪問を越えて持つほどの
  ものでもない

**印は 3 通りの状態を持つ。** 入っている / 入っていない / **一部だけ入っている** — 研究の行は配下の
dataset をまとめて指すので、20 件のうち 19 件が入っている行を「入っていない」と言うわけにいかない。
状態は色だけでなく読み上げにも出る。**表の見出しの印は帯の上に乗る**ので、そこだけは白で描く
(ページの文字色はその上で 1.2:1 にしかならない)。

**カートの中身はアドレスに写す。** `/cart` は `?ids=` を読んで行を組み立て、ブラウザは自分が持っている
ものをそこへ書き戻す。**画面が従うのはカートであってアドレスではない** — 行を外したらその場で消え、
下の JSON からも消える。貼り付ける内容が、外したはずのものを名指してはいけない。**表を server が描くための写しであって、共有の手段ではない** — 開いた側の
カートが常に正で、人から渡されたアドレスは開いた瞬間に自分の中身で書き換わる。集めているものが
リンクを踏んだだけで置き換わるほうが驚きが大きい。

**取り下げられた dataset は行にならない。** 集合の根拠は他の公開画面と同じ検索行なので
(「何を根拠に『公開されている』と言うか」)、控えだけが古いことは起きず、見つからなかった id は
そう告げる。

一覧と dataset のページに付くカートの印は、**研究の行なら配下の JGAD をまとめて**、表の見出しなら
そのページ全体を、dataset のページならその 1 件を出し入れする。**申請できないものに印は出ない** —
押しても何も起きない印を全行に並べても、読者には区別が付かない。

**ただし列そのものは、どちらの一覧でも常に 1 列目にある。** dataset の一覧はアーカイブ自身の
accession を多く含むので、印が 1 つも立たないページが普通に出る。列を中身に応じて出し入れすると、
表の上に置いた「カートの印を押すと」の注記が画面のどこも指さなくなり、並び替えやページ送りのたびに
他の列が横にずれる。

## サイトコンテンツ

ガイドライン・ポリシー・FAQ・お知らせと、それらを束ねる画面。**research 系とは別の規則で動く** —
版も pin も公開表現も無く、公開検索の対象にもならない ([data-model.md](data-model.md) の
「サイトコンテンツ」)。

### 画面と document の境い目

**境界は「本文があるか」で引く。** 本文を持つものは document で、admin が直せる。持たないものは画面で、
コードが持つ。

| | 何が持つか |
|---|---|
| `/data-submission` `/data-use` `/contact-us` | route。ボタンと短い文だけで、本文が無い。問い合わせは**フォームをページに埋め込む** (下記) |
| `/` (トップ) | route が枠を持ち、`home` document が本文を差し込む |
| `/news` `/news/{id}` | route が枠を持ち、`news` が中身を持つ |
| `/{slug}` | document |

ここを混ぜたことが現行の markdown に拡張記法とレイアウト用の生 HTML を持ち込んだ原因になっている。
**画面の部品は component で持ち、本文の書式に持ち込まない** (`app/components/site.tsx`)。

`guidelines` (改定履歴のリンク集) や `dac` (審査委員会の回ごとのリンク) のように、項目が増えていくが
本文を持つものは document のまま残す — 増えるかどうかは境界ではない。

**問い合わせフォームはページの中に置く。** 申し込み先は Google フォームで、ja/en で別のフォームになる。
`forms.gle` の短縮アドレスは redirect を返すので frame が追えない — 埋めるのは展開後のアドレスで、
辞書がそれを持つ。**リンクも下に残す**: frame が動かない環境から出られなくなるため。ここだけ外部の
サービスを自分の origin に埋めることになるが、**一番使われる入口が「外に飛ばすだけの空ページ」に
なるほうが失うものが大きい** (現行ポータルも同じ形をしている)。

### ガイドラインの版

**各版が独立した document で、slug は `{slug}/version/{n}`。最新版も番号の slug を持つ。** 版なし slug は
本文を持たず現在の版を指すので、`/guidelines/data-sharing-guidelines` は指し先の本文を 200 で返す
([data-model.md](data-model.md) の「サイトコンテンツ」)。版なし slug は外部の submission metadata に
焼き込まれているので、**恒久的に応答し続ける必要がある。**

**redirect にしない。** research の最新公開版が `/research/{humId}` と `/research/{humId}/v{n}` の両方で
200 を返すのと同じで、版なし slug は「いまのガイドライン」を名指す独立したアドレスになる。redirect に
すると、引用しようとした人が版付きのアドレスを写して、次の改定で古い版を指すことになる。

### グローバルナビとフッタ

**`app/public/navigation.ts` の定数**で、DB には無い。admin が編集する UI を持たないので、DB に置く
理由が無い。ラベルは document のタイトルではなく手書きの短縮名なので、性質は UI 文言の辞書と同じになる。

**定数が指す先が実在することは test で守る** — 型では守れないため。route が持つアドレスか、移行が作る
document の slug のどちらかであることを確かめる。

### お知らせの検索

一覧の上に窓を 1 つ。**タイトルと本文に対する部分一致で、公開検索とは別の経路**になる — お知らせは
検索用の行を持たないので (「何を根拠に『公開されている』と言うか」)、682 行に対する 1 回の走査で足りる。
窓は他の一覧と同じ箱で、打ったものは同じ `?q=` に載り、打つのをやめれば同じように自分で走る。
**どの索引が答えるかは読者に見えるものではない**ので、綴りも振る舞いも分けない。

**ただし `?q=` を検索式として読むのは 2 つの一覧だけで、ここでは打たれた語がそのまま探される。**
`%` や `_` は LIKE のワイルドカードなので、そのまま渡すと「全件が一致する」になる。エスケープして
literal として扱う。

**空の条件はアドレスに残さない。** GET の form は何も打たれていない窓も送るので、放っておくと `?q=`
だけが残る。**空の値を持つものを落としたアドレスへ redirect する**ので、一覧は 1 つのアドレスを持ち、
**窓を空にすることがそのまま検索を解くこと**になる (「検索を解除」のような別の操作を置かない)。

**窓・件数・ページ送りは 1 行に並ぶ。** どれも「いま画面に出ているのはどれか」についてのもので、
窓だけが読者の先に触るものなので左に置く。**下にはページ送りと件数だけ**を同じ順で置く。

**この窓は行を分け合うので、幅も深さも詰めた形を使う** (`SearchBox` の `compact`、384px)。行いっぱいに
広げると、件数とページ送りが 1440px の画面の端まで押し出される。

**一覧は上と下も罫線で閉じる。** 一覧はその画面の全部なので、どこから始まってどこで終わるかを線が言う。
トップの右カラムは card の中の 1 ブロックなので閉じない — 箱の中に箱を描くことになる。

**件数は「1–20 / 675 件」の形で、一覧の上と下に出る。** 検索しているときはその検索が当てた数になる。
**見出しには出さない** — 同じ数を 2 か所に書くことになる。

**一覧は読み幅ではなくページの幅を使う。** ここに並ぶのは告知の題目 1 行で、本文ではない。読み幅
(880px) に置くと、実測で 20 件のうち 5 件が 2 行に折り返していた (必要な幅は最大 930px)。

### お知らせの並べ方

**日付・題目・本文の書き出しの 3 つ**を、**項目のあいだに横線**を引いて並べる。書き出しがあると 1 件が
3 行になるので、日付だけでは 1 件の始まりと終わりが読めない。

**書き出しは記法を落とした素の語で、行数は画面が決める。** 本文は Joomla からの変換でリンク・表・
見出しを持つので、文字列を切ると `[…](…)` や `|---|` が読者に出る。木を歩いて語だけを取り
(`leadingText`)、**server は多めに切って渡し、何行に収まるかは幅と言語で決まるので画面が clamp する。**

**日付の置き場は幅で決まる。** 一覧では日付が自分の列を持ち、日付どうしが縦に揃って、読者は題目の列を
まっすぐ読める。トップの右カラムは 408px しかなく、そこに列を作ると題目が 3 分の 1 行になるので、
日付は題目の上に乗る。

### alert

全ページ共通のバナー。**on / off だけで期間を持たない。** ja/en の対を 1 つ持ち、片言語しか無ければ
もう一方が出る。

**立っているものは全部、ヘッダの下に縦に積む。** 事務局が on にしたものが画面に出ないほうが害が大きい。
× で閉じられるが、**閉じたのはそのページを開いているあいだだけ**残る — 恒久的に消せると、読んでいない
告知を読者が自分で消せてしまう。

## ヘッダとフッタ

**ヘッダは 1 行で、決して折り返さない。** ロゴ、グローバルナビ、入り切らない行き先を畳むメニュー、
そして操作 3 つ — 言語、カート、アカウント。**バーはページの幅ではなく窓の幅いっぱいに広がる**。
左右に残す余白はページと同じ ([ui.md](ui.md) の「幅」)。

**バーの項目は 1 つずつ「その幅から出す」段を持つ** (`public/navigation.ts` の `NAVBAR_STEP`)。
段は両言語のラベルを実測して決めてあり、1440px の窓なら 8 つ、1280 で 7 つ、1024 で 5 つ、768 で 3 つ、
それ未満は 0。**バーが出さないものはメニューが出す** — 2 つの並びは相補で、どちらにも無い行き先が
生まれないことを test が見る。

**メニューは ≡ と「メニュー」の語を持つ。** グリフだけの ⋮ はサイトの他の場所では「いま見ている項目への
操作」の印で、ここに入っているのは行き先なので語を添える。中身は 2 段 — **常にここにあるもの**
(データの提供・データの利用・成果発表) と、**その幅で入り切らなかったもの**。

**開いたメニューは、Escape でも外を押しても、行き先を選んでも閉じる。** バーのメニューは全画面の
右上を覆うので、同じ印をもう一度押す以外に閉じ方が無いと、読者が別のことを始めた後も居座る。
行き先を選んだときはページを読み込み直さないので、**着いたことが閉じる合図**になる。

**行はロゴのワードマークで揃え、サイト名はその下にぶら下げる。** 読者がロゴとして見るのは絵のほうで、
2 段を 1 つの塊として中央に置くと絵だけがナビと操作の線より上に出て、ヘッダが頭でっかちに見える。

**バーの下に罫線を引かない。** バーは白でその下はページの地なので、どこで終わるかは既に描かれている。

- **ここから検索はできない。** 読者が検索に入るのはトップと一覧の 2 つで、どちらにも窓そのものがある。
  一覧へ送るだけの丸は、覚えることが 1 つ増えるだけだった
- **言語は 1 本のトラックに 2 つ**で、常に両方出る。読んでいる側が塗られる。片方だけを出すと、いまどちら
  の言語にいるのかが読めない。行き先は**いま見ているページの別言語**で、クエリも連れていく

**いま見ているアドレスのクエリを持ち出すものは、それを `normalizeQuery` に通す** (言語の対と、
サインインの戻り先の 2 つ)。`,` `:` `(` `)` `|` はクエリの中では符号化しなくてよい文字なので、
**同じアドレスがブラウザには `?q=a,b`、ページを描く server には `?q=a%2Cb` として届く**。どちらの綴りで
書くかを決めておかないと、手で書かれたアドレスで開いたページはすべて hydration が食い違う。
サイト自身が組むアドレスは元から符号化された側なので、これで両方が 1 つの綴りに揃う。
- **カートは件数を持つ。** 中身はブラウザにあるので、server が描いた直後は 0 で、開いた後に埋まる

**未ログインならアカウントは丸 1 つ**で、押すとサインインに行く。ログイン済みならメニューになり、名前・
管理画面 (admin のみ)・ログアウトが入る。**公開ページは認証を要求しないし、ログインしても見えるものは
変わらない** ([auth.md](auth.md) の「誰が何をできるか」)。

- **ログインのリンクはいま見ているアドレスを戻り先に持つ。** サインインの後にトップへ落とさないため
- **ログアウトは POST。** 他人が置いたリンクや画像でセッションを終わらせられないようにする
- 出すのは名前と admin かどうかだけで、**capability は server 側に留める**

**フッタはサイトマップ 1 つ。** ヘッダの ⋮ に入った行き先も、4 本のガイドラインの正式名称も、ここには
全部ある。**列になるのは子を持つ 2 つだけで、残る 9 つは 1 行に並ぶ** — 11 個を 4 列に流すと、1 行しか
持たない列が 4 本のガイドラインに高さを合わせることになり、サイトマップと同じ高さの穴が空く。

**列の幅は中身が決める。** ガイドラインの正式名称はここにしか出ないもので、いちばん長いものは半分では
足りず、均等に割ると末尾の 2 文字だけが次の行に落ちる。もう一方は 3 行しか持たないので、その差は
そちら側の余白になる。

**列の名前はラベルで、その行き先は子の先頭のリンクとして出す。** 見出しそのものをリンクにすると、
行き先はあるのに 11 個のうちその 2 つだけ下線が付かず、押せると読めない。**フッタの下端に社名の帯を
置かない** — サイトマップの最後の行の下にもう 1 本罫線を引いて同じ名前を繰り返すだけになる。

**告知はバーの外に出て、窓の幅いっぱいに広がる。** バーの中に置くと同じ白の上に乗り、事務局が今日
言っていることがサイトの備品に見える。バーの下・ページの地の上に置く — サイトが全員に言うことは窓に
属し、ページには属さない。左右の余白は他のすべてと同じ `page-gutter` で、**バー・告知・ページ・
サイトマップの左端が 1 本の線に乗る**。

## 意図的にやっていないこと

| やらないこと | 理由 |
|---|---|
| 検索窓から `field:value` を打つ経路 | 窓はキーワードの窓。field を持つ条件はアドレスと facet の側から入る |
| ラベルを打ったときの完全一致カード | 全文検索の結果として並べる。裸のラベルは URL が redirect で受ける |
| 0 件のときの緩和した検索 | 外し方の数だけ検索することになる。案内だけ出す |
| facet の「不明」のバケット | 未確定と該当なしは集計にも検索にも載せない。絞る対象が存在しない |
| 目次 (TOC) と document の版一覧 | 現行の 62 document すべてで表示が切られていて、誰も使っていない |
| お知らせの期間指定 | 日付順に並んでいるので、窓と送りで足りる |
| エクスポートの Excel 形式 | 表計算はどれも CSV を読む。workbook を書くには依存が 1 つ増える |
| カートを訪問を越えて持つこと | 申請の途中経過であって設定ではない。共有端末で前の人の控えが残る |
| cookie / `Accept-Language` による言語の切り替え | 言語は URL が決める |
| 欄ごとの未翻訳の印 | ページ単位で 1 度だけ告げる |
| サイトコンテンツの未翻訳フォールバック | locale ごとに公開状態を持つので、無い言語は 404 |
