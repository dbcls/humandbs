# 外部から取ってきたデータ

申請管理システム・DDBJ Search・DDBJ の公開 FTP が正本の値を、ポータルがどう取得し、保存し、表示するかをまとめる。取得元のシステムは [overview.md](overview.md) の「構成要素」、データセットの日付をどこから取るかは [data-model.md](data-model.md) の「日付」、取得のジョブは [concepts.md](concepts.md) の「ジョブ」にある。

## 取得元とキャッシュ

他のシステムが正本の値は、Postgres のキャッシュ用の表に置き、読む処理はキャッシュだけを見る。申請管理システムの DB を読むのは取得の処理だけで、画面を表示するときには接続しない。

- 取得元は 8 つある (`app/upstream/sources.ts`)。申請管理システムの DB から 6 つ (制限公開データの利用者 (CAU)、研究 ID と JGA の accession の対応、JGAD の日付、JGAD のファイル、承認済みのデータ提供申請、JGAD の登録内容)、DDBJ Search からそれ以外のアーカイブ (DRA、GEA、MetaboBank、BioProject) の日付、DDBJ の公開 FTP から DRA・GEA・MetaboBank のファイルを取る。DDBJ Search の entry にはファイルの大きさが無いためである。
- 取得元が止まっても、公開ページも管理画面も前回の取得の値で表示できる。キャッシュは取り直せるので、失っても backup から戻さなくてよい。
- 公開ページと API が読むキャッシュには、公開済みの accession の、そのまま公開ページに出る値だけを入れる。例外は照合のためのキー (利用課題の番号) で、公開用の表示データにも API にも出さない。
- 承認済みのデータ提供申請と JGAD の登録内容は、申請から下書きを作る画面だけが読む ([editing.md](editing.md) の「申請から研究を作る」)。公開前の申請と JGAD も入る。入れるのは下書きに取り込む値 (研究題目・目的・方法・対象、研究代表者の氏名と所属、国、アクセスの種類、疾患、登録した JGAS と JGAD) と、JGA に登録された JGAD の題目と dataset type である。下書きに取り込んだ値と同じく、DB の backup にも入る。
- 申請の連絡先・住所・電話・研究分担者は、どのキャッシュにも入れない。取得の処理も読まない。
- 研究 ID と accession の対応の正本は申請管理システムで、ポータルの ID の割り当ては正本ではない。食い違いは公開前の確認で一覧に表示する ([publishing.md](publishing.md))。
- 申請管理システムの DB への接続は read-only を強制する。接続の設定が無い環境では、この DB から取る 6 つを飛ばす。

## 取り直しと失敗

キャッシュは、アプリのプロセスが取得元ごとに一定の間隔で取り直す。

- 間隔は配置先ごとに `HUMANDBS_UPSTREAM_INTERVAL_MINUTES` で決め、空なら 180 分である。JST の 0 時から数えた区切り (180 分なら 0 時・3 時・6 時…) を過ぎたら、その区切りのあとにまだ成功していない取得元を取り直す。`0` にすると自動では取り直さない。CLI (`npm run upstream:refresh`) は間隔に関係なく取り直す。
- 1 日の分数 (1440) の約数でない間隔と、60 分より短い間隔では起動しない。1 回の取得で、他のプロジェクトの DB に重い query を流すためである。
- 更新は取得元ごとに行い、それぞれ独立に失敗する。失敗した取得元は前回の値を残し、1 時間ごとに取り直す。一時的に応答しないことと値を消したことを区別できず、消した側として扱うと公開ページが空になるためである。
- 取得できた件数が前回の半分より少ないとき (0 件を含む) も失敗として扱い、前回の値を残す。止まる途中や戻す途中の取得元は、応答しても一部の行しか返さないことがあるためである。本当に減ったときは、CLI に `--allow-shrink` を付けて取り直す。
- 成功した取得元だけを全件置き換え、同じトランザクションで検索用の行を作り直す。今回返らなかった行は消える。JGAD の検索用の行には JGAS の ID が入るので、対応が変わると行も変わる ([data-model.md](data-model.md) の「全文検索」)。
- 取得元ごとに、最後に試した日時・最後に成功した日時・件数・直近の失敗の理由を記録し、`/admin` に表示する。

## 制限公開データの利用者 (CAU)

CAU は研究の内容ではないので、値の状態が無く、未翻訳にも数えない。1 行は 1 つの利用課題 (J-DU の案件) と 1 つの研究の組で、人ごとにまとめない。1 つの利用課題が複数の研究のデータセットを使っていれば、研究ごとに、その研究のデータセットだけを載せた行になる。

- 載せるのは、利用が承認された利用課題である。案件の状態が申請承認 (160)・利用報告未提出 (210)・利用期間切れ (220)・利用期間終了 (190)・利用期間終了・二次データ保管 (200) のものを載せる。承認のあとに破棄された案件 (重複して登録した申請を片付けたもの) は載せない。
- 利用課題の申請には新規・データセットの追加・延長・利用報告・利用終了があり、どれも 1 つの案件の枝番として並ぶ。値を読む枝番は、先に承認済みのものに絞ってから種類で選ぶ。最新の枝番は未承認のことがあり、承認済みの最新の枝番は多くが利用報告で、そこに書かれた研究代表者は報告した時点の後任者であるためである。
- データセットは、承認済みの枝番で許可されたもの (新規と追加) をすべて合わせたものである。
- 研究代表者・所属・国・題目は、利用を承認したときの新規の申請から取る。あとの申請 (延長・報告・終了) は、そのときの後任者や異動後の所属を書くためである。国と所属だけは、新規の申請に書かれていないときに同じ利用課題のほかの申請から補う。
- 所属は、部署と機関を `, ` でつないだものである。申請者が部署や機関の代わりに書いた `N/A`・`unknown`・`missing`・`(Filled by DDBJ)` は除く (例: `N/A, Broad Institute of MIT and Harvard` は `Broad Institute of MIT and Harvard`)。新規の申請で所属が空の言語は、同じ利用課題の承認済みの申請のうち、研究代表者の英語の姓が同じものから補う。
  - 日本語だけあるときは、日本語の所属が同じ申請の英語を使う。異動したあとの英語を並べると、日本語と違う機関を表示するためである。無ければ英語は空のままで、英語のページには日本語を表示する。
  - 日本語も英語も無いときは、所属の書かれたいちばん新しい申請から日本語と英語を組で使う。古い申請書には所属を書く項目が無かったためである。
- 国名は、申請者が英語で自由に書いた文字列を、ポータルの国名の表 (ISO 3166 の国コードごとの日本語名と英語名、`app/upstream/country.ts`) に照らして両言語の名前にする。表で分からない国名は、書かれた文字列のまま両言語に出す。訳せない国を一覧から除くより、英語のまま出す方がよいためである。
- 州は、米国・カナダ・オーストラリアのときだけ国名に添え、それ以外の国では表示しない。この 3 国では州が個人データの利用について独自の法を定めるので、州が利用の条件を表すためである。表で分からない州は出さない。欄には州の代わりに選択肢の既定値などが入っていることが多いためである。

### データ利用期間

開始日と終了日は承認した日で決める。申請管理システムでは、利用の開始・延長・終了のどれも、承認した日に案件の状態が変わるためである。日付は日本時間で数える。

- 開始日は、新規の申請が承認された日である。延長が承認されて利用期間切れから申請承認に戻っても、開始日は変わらない。
- 利用終了の申請が承認された案件 (利用期間終了・利用期間終了・二次データ保管) の終了日は、その申請が承認された日である。期限までに申請していても、承認が期限を過ぎれば承認日になる。
- それ以外の案件の終了日は、利用期限 (`nbdc_use_period.expire_date`) である。利用期限は延長が承認されると延びる。
- 利用期間切れは、利用期限を過ぎたが利用終了の申請が承認されていない状態で、利用中として扱う。期限を過ぎてから利用終了の申請が承認されると、終了日は利用期限から承認日に変わる。例として、2017-07-19 に承認され、利用期限が 2018-04-01 で、利用終了の申請が 2023-07-13 に承認された案件は、その承認までは `2017-07-19 – 2018-04-01`、承認のあとは `2017-07-19 – 2023-07-13` と表示する。

## データセットのファイルの大きさと形式

JGAD・DRA・GEA・MetaboBank のデータセットの総データ量とファイル形式は、取得元のファイルから作る。NHA はファイルの選択から作る ([files.md](files.md) の「データセットとファイルの対応」)。

- 取るのは大きさの合計とファイル形式だけで、ファイル名は持ち込まない。大きさは利用者がダウンロードする大きさである。JGAD は最新の登録が参照する JGAR・JGAZ の暗号化したファイル、DRA は fastq のディレクトリのファイル、GEA と MetaboBank はファイルの一覧 (`<ID>.filelist.txt`) に載ったデータのファイル (GEA の zip は zip のまま) を足す。GEA と MetaboBank の idf・sdrf とファイルの一覧は、メタデータなので足さない。
- ファイル形式は、ファイル名の拡張子を語彙 `file-type` の値にしたものである。語彙はコードに置いた形式の一覧 (表示名と拡張子の書き方。`fq` も FASTQ、`h5` も HDF5) から作る。
- JGA の `.encrypt` と圧縮の拡張子 (`.gz`・`.bz2`・`.zip`) は外してその前の拡張子を読み、それが一覧に無ければ圧縮の形式 (ZIP など) にする。ファイル名の途中の点は拡張子と区別できないためである (`hum0014.v8.ALT.zip` は ZIP、`hum0014.v5.AF.v1.txt.zip` は TXT)。
- GEA の zip は中のファイルの名前で読む (`E-GEAD-1076.processed.zip` は中の rds・csv・h5 から RDS・CSV・HDF5)。
- 一覧に無い拡張子は形式にせず、取り直しの出力に件数を出す。一覧に足すのは開発の作業である。NHA のファイルの選択も同じ規則で読む。

## やっていないこと

- 外部から取ってきたデータを画面から取り直すこと。取り直すのはアプリのプロセスと CLI で、画面は結果を表示するだけである。
