# ファイル

配信するデータファイルと、記事から参照する画像や PDF の置き方と公開の決まりをまとめる。ファイルは、ポータルの中で唯一、実体と公開状態を Postgres の外 (S3) に置くデータである。研究のフォルダとジョブの意味は [concepts.md](concepts.md)、データセットの ID の読み方は [data-model.md](data-model.md) にある。

ファイルは、アップロード・ダウンロード・公開状態の切り替えができる置き場として扱い、研究・データセット・記事への所属はモデルで管理しない。本文からの参照は URL の文字列で、外部のサイトから直接参照されることもあるので、どこからも参照されていないファイルは判定できない。整理は人が一覧を見て行う。

## 2 つの bucket と研究のフォルダ

ファイルの実体は S3 (SeaweedFS) の 2 つの bucket に置き、どちらの bucket にあるかがそのまま公開状態である。

- Postgres には公開状態を置かない。bucket を分けるのは、S3 で匿名の読み取りを許せる単位が bucket だからである。
- 非公開の bucket (`private`) の key は `{研究の実体の ID}/{ファイル名}` で、読めるのは admin だけである。サーバーが署名付き URL を発行して渡す。
- 公開の bucket (`files`) の key は `{研究 ID}/{ファイル名}` と `common/{slug}` で、誰でも読める。proxy が `/files/` への要求をそのまま渡す。
- 非公開側を実体の ID にするのは、研究 ID が付く前からファイルが届くためである。公開側を研究 ID にするのは、`/files/hum0009/…` の URL が ID の解決を挟まずにファイルに届くようにするためである。
- 研究のフォルダには階層が無く、key の後半はファイル名だけである。名前に `/` を含むアップロードは 400 にする。
- 記事の画像と PDF は、公開の bucket の `common/` に置く。
- 同じ研究の同じファイル名が、両方の bucket に同時にあってはならない。両方にあるのは切り替えの途中で止まった状態で、ジョブの再実行で解消する。一覧ではその間、公開として表示する。

### 配信の安全

- S3 のポートは外に出さない。filer の HTTP は認証なしで非公開の bucket の中身まで返すためである。読み書きはすべて proxy を通し、署名付き URL の宛先もこのサイトの origin で作る。署名が host を含むためである。
- 配信するファイルを、このサイトの origin の文書として動かさない。Content-Type はアップロードした人が決め、S3 は中身から種類を推測することもあるので、proxy がどちらの bucket にも `X-Content-Type-Options: nosniff` を付け、画像と PDF 以外は `Content-Disposition: attachment` にする。
- SVG は画像として扱わず、attachment にする。直接開くと、SVG の中の script が実行されるためである。
- PDF 以外には `Content-Security-Policy: sandbox` を付け、inline で開いても別の origin として script なしで表示させる。PDF を外すのは、ブラウザの PDF viewer が sandbox の中では動かないためである。`/private/` は常に attachment で sandbox を付ける。
- 非公開のファイルの中身は admin 以外に渡さない。共有リンクのプレビューは名前とサイズを表示するが、取得はさせない。

## アップロード

アップロードは署名付き URL で行い、ファイルの中身はアプリを通らない。

- 署名に Content-Type と長さを含めるので、発行時に決めた種類と大きさ以外は 403 になる。
- 64 MiB を超えるファイルは multipart で送る。開始と完了はサーバーが行い、各 part の PUT だけが署名付き URL になる。
- 研究のフォルダへのアップロードは、非公開の bucket に入る。受け取った瞬間に誰でも取れる状態を作らないためである。
- 同じ名前のアップロードは上書きになる。名前が key なので、画面は送る前に既にある名前を挙げて確認する。確認の問い合わせに失敗したときは送らない。
- ページを閉じた後のアップロードの再開は無い。入れ直せば同じ名前で上書きされる。
- ファイルの名前の変更は、両方の bucket でコピーしてから削除する。既にある名前への変更と、切り替え中のファイルの変更は断る。操作の記録に残すのは公開側の変更だけである。
- `common/` は置いた時点で公開されるので、アップロードと削除を操作の記録に残す。アップロードは、署名を発行した時点 (multipart は完了した時点) で記録する。
- `common/` の slug には `/` を書けて、後から変えられる。変更はコピーしてから削除し、既に別のファイルがある slug は断る。変えると元の URL は 404 になり、本文の参照は人が直す。

## 公開・非公開の切り替え

公開状態の切り替えは、bucket 間でファイルの中身をコピーして元を消す操作なので、ジョブ (`file_publish_job`) にして、操作した人を待たせない。

- Postgres に置くのは実行待ちのジョブだけである。ジョブを失っても、ファイルは公開か非公開のどちらかに留まる。誰がいつ切り替えたかは操作の記録に残る。ファイル名は変えない。
- ジョブは 1 ファイルに 1 行である。研究とファイル名の組で upsert し、新しい指示は行き先を上書きする。途中の指示ごとに大きなファイルをコピーしないためである。
- 実行は、今ファイルがある場所を見て、行き先と違うときだけ動かす。順番はコピーしてから削除で、2 度実行しても結果は同じである。途中で止まっても次の実行で直る。
- 完了のときは、実行を始めたときの行き先と今の行き先が一致するときだけ行を消す。実行中に指示が変わったら実行待ちに戻り、最後の指示に落ち着く。
- ジョブはアプリのプロセスが `FOR UPDATE SKIP LOCKED` で 1 件ずつ取り出して実行する。長く実行中のまま残った行は、プロセスが止まったものとして実行待ちに戻す。失敗は決まった回数まで再試行し、その後は失敗として画面に表示する。
- 研究 ID が無い研究のファイルは公開できない。公開側の置き場所が無いためである。
- 切り替えが終わっていないファイルは、名前の変更も削除もできない。どちらの bucket にあるかがまだ決まっていないためである。失敗で止まったファイルは削除できる。
- ファイルの公開は研究の公開と独立している。研究を公開してもファイルは公開されない。公開前の確認は、データセットが選んだ非公開のファイルを挙げてまとめて公開に切り替えられるが、ジョブの完了を公開の条件にはしない ([publishing.md](publishing.md))。

### 研究 ID の付け替えと研究の削除

公開側の研究のフォルダは研究 ID で決まるので、研究 ID を変える操作と研究を消す操作はファイルの置き場所に関わる。

- 新しい研究 ID を主にすると、元の研究 ID の公開側のフォルダにあるファイルを新しいフォルダへ移すジョブを、ID の割り当てと同じトランザクションで登録する。S3 の一覧はトランザクションの前に取り、S3 が応答しなければ何も確定しない。
- 公開側のフォルダにファイルがある研究 ID と、切り替えが終わっていないファイルがある研究の研究 ID は外せない。外すと公開中のファイルが 404 になり、その番号を次に割り当てた研究の一覧に残りのファイルが出てしまうためである。付け替えは、新しい ID を主にし、移動が終わってから元の ID を外す。
- 研究の削除は、非公開のフォルダか、その研究のどの研究 ID の公開側のフォルダにでもファイルが残っているあいだは断る。S3 のファイルは DB の削除と一緒には消えないためである。ファイルは研究のフォルダの画面で先に削除する。
- 研究の画面は、これらの操作のボタンを押せない形にして、理由と次にすべき操作を表示する。移動中の元の研究 ID にはマークを付ける。S3 が応答せずフォルダの中身が分からないときは押せるまま残し、押した先で断る。

## データセットとファイルの対応

データセットとファイルの対応は、研究のフォルダの一覧に対する選択として、データセットの記述に保存する。

- ダウンロードの一覧は記述に置かず、研究のフォルダの一覧から作る。公開ページは公開の bucket だけを、admin の画面と共有リンクのプレビューは両方の bucket を名前で合わせて見る。下書きの段階では公開の bucket が空だからである。
- 選択 (`fileSelection`) は集合で、順序は無い。記述には名前の順で書く (`app/files/selection.ts`)。
- 選択はファイルの存在を主張しない。一覧に無い名前は表示しないが、選択からは消さないので、同じ名前で入れ直せば再び選ばれる。非公開にしたファイルは、公開ページのデータセットからも同時に消える。
- 選択は一覧の作り方には使わない。一覧は研究のフォルダのままで、選択はその上の注記として、ファイルごとに選んでいるデータセット ID を添える。
- 外部のアーカイブのデータセットではファイルを選択できない。判定は主のデータセット ID で行い ([data-model.md](data-model.md))、ID がまだ無いあいだも外部として扱う。選択を含む保存は 400 にする。

## やっていないこと

- ファイルの所属の管理と、どこからも参照されていないファイルの検出。参照を追いきれない。
- データセットとファイルの名前の規約。対応は研究のフォルダの一覧に対する選択で表す。
- アップロードの再開。入れ直せば同じ名前で上書きされる。
- 研究のフォルダの中のディレクトリ。`common/` で階層に置くのは、後から slug を変える操作である。
- ファイル名の全文検索。名前の正本は記述ではなく研究のフォルダにある。
