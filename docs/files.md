# ファイル

配信するデータファイルと、記事から参照する画像や PDF の保存先と公開の決まりをまとめる。ファイルは、ポータルの中で唯一、実体と公開状態を Postgres の外 (ファイルストア) に置くデータである。Postgres に置くのは、終わっていないジョブとラベルだけである。研究ごとの prefix とジョブの意味は [concepts.md](concepts.md)、データセット ID からの判定は [data-model.md](data-model.md) にある。

ファイルは、アップロード・ダウンロード・公開状態の切り替え・ラベルの編集ができるものとして扱い、研究・データセット・記事への所属はモデルで管理しない。

- 本文からの参照は URL の文字列で、外部のサイトから直接参照されることもある。
- そのため、どこからも参照されていないファイルは判定できない。整理は人が一覧を見て行う。

## 2 つの bucket と研究ごとの prefix

ファイルの実体はファイルストア (SeaweedFS の S3 互換の API) の 2 つの bucket に置き、どちらの bucket にあるかがそのまま公開状態である。

- Postgres には公開状態を置かない。bucket を分けるのは、S3 で匿名の読み取りを許せる単位が bucket だからである。
- 非公開の bucket (`private`) の key は `{研究の実体の ID}/{ファイル名}` で、匿名の読み取りは許さない。admin は研究のファイル一覧の画面から、サーバーが発行する期限の短い署名付き URL でダウンロードできる。読者も、共有リンクからプレビューを読む提供者も取り出せない。
- 公開の bucket (`files`) の key は `{研究 ID}/{ファイル名}` と `common/{slug}` で、誰でも読める。proxy が `/files/` へのリクエストをそのまま渡す。
- 非公開の bucket を実体の ID で分けるのは、研究 ID が付く前にファイルがアップロードされることがあるためである。公開の bucket を研究 ID で分けるのは、`/files/hum0009/…` の URL が ID の解決を挟まずにファイルを指すようにするためである。
- 研究ごとの prefix の下には階層が無く、key の後半はファイル名だけである。名前に `/` を含むアップロードは 400 にする。
- 記事の画像と PDF は、公開の bucket の `common/` にアップロードする。
- 同じ研究の同じファイル名が、両方の bucket に同時にあってはならない。両方にあるのは切り替えの途中で止まった状態で、ジョブの再実行で解消する。一覧ではその間、公開として表示する。
- admin の研究一覧の「ファイル」の列と絞り込みは、非公開の bucket の研究の実体の ID の prefix と、公開の bucket の primary の研究 ID の prefix の両方を数える。絞り込み (あり・なし) は全研究について、bucket ごとに prefix の一覧 (区切り `/`) を 1 度取って決める。研究ごとに prefix を読むと、1 回の表示で研究の数だけファイルストアに問い合わせることになるためである。ファイルストアが応答しないときは、この絞り込みは使えず、URL にあっても適用しない。

### 配信の安全

- ファイルストアのポートは外に出さない。ファイルストアの filer の HTTP は認証なしで非公開の bucket の中身まで返すためである。読み書きはすべて proxy を通し、署名付き URL の宛先もこのサイトの origin で作る。署名が host を含むためである。
- 配信するファイルを、このサイトの origin の文書として動かさない。Content-Type はアップロードした人が決め、ファイルストアは中身から種類を推測することもあるので、proxy がどちらの bucket にも `X-Content-Type-Options: nosniff` を付け、画像と PDF 以外は `Content-Disposition: attachment` にする。
- SVG は画像として扱わず、attachment にする。直接開くと、SVG の中の script が実行されるためである。
- PDF 以外には `Content-Security-Policy: sandbox` を付け、inline で開いても別の origin として script なしで表示させる。PDF を除くのは、ブラウザの PDF viewer が sandbox の中では動かないためである。`/private/` は常に attachment で sandbox を付ける。
- 非公開のファイルの中身を取り出せるのは admin だけである。共有リンクのプレビューは名前とサイズを表示するが、ダウンロードはできない。

## アップロード

アップロードは署名付き URL で行い、ファイルの中身はアプリを通らない。

- 1 回の PUT では署名に Content-Type と長さを含めるので、発行時に決めた種類と大きさ以外は 403 になる。
- 大きいファイルは multipart で送る。開始と完了はサーバーが行い、各 part の PUT だけが署名付き URL になる。種類は開始時に決まるが、part の大きさは署名に含まれない。
- 研究ごとの prefix へのアップロードは、非公開の bucket に入る。受け取った瞬間に誰でも取れる状態を作らないためである。
- 同じ名前のアップロードは上書きになる。名前が key なので、画面は送る前に既にある名前を一覧に表示して確認する。その確認のためのリクエストに失敗したときは送らない。
- ページを閉じた後のアップロードの再開は無い。アップロードし直せば同じ名前で上書きされる。
- ファイルの名前の変更は、両方の bucket でコピーしてから削除する。既にある名前への変更と、切り替えが終わっていない (失敗で止まったものを含む) ファイルの変更はエラーにする。操作の記録に残すのは公開の bucket の変更だけである。
- `common/` はアップロードした時点で公開されるので、アップロードと削除を操作の記録に残す。アップロードは、署名を発行した時点 (multipart は完了した時点) で記録する。
- `common/` の slug には `/` を含められるが、ディレクトリとして扱うわけではない。slug は後から変えられ、変更はコピーしてから削除する。既に別のファイルがある slug への変更はエラーにする。変えると元の URL は 404 になり、本文の参照は人が直す。

## 公開・非公開の切り替え

公開状態の切り替えは、bucket 間でファイルの中身をコピーして元を消す操作なので、ジョブ (`file_publish_job`) にして、操作した人を待たせない。

- Postgres に置くのは終わっていないジョブ (実行待ち・実行中・失敗) だけで、完了した行は消す。ジョブを失っても、ファイルは公開か非公開のどちらかに留まる。誰がいつ切り替えたかは操作の記録に残る。ファイル名は変えない。
- ジョブは 1 ファイルに 1 行である。研究とファイル名の組で upsert し、新しい指示は行き先を上書きする。途中の指示ごとに大きなファイルをコピーしないためである。
- 実行は、今ファイルがある場所を見て、行き先と違うときだけ動かす。順番はコピーしてから削除で、2 度実行しても結果は同じである。途中で止まっても次の実行で直る。
- 完了のときは、実行を始めたときの行き先と今の行き先が一致するときだけ行を消す。実行中に指示が変わったら実行待ちに戻り、最後の指示どおりになる。
- ジョブはアプリのプロセスが `FOR UPDATE SKIP LOCKED` で 1 件ずつ取り出して実行する。長く実行中のまま残った行は、プロセスが止まったものとして実行待ちに戻す。失敗は決まった回数まで再試行し、その後は失敗として画面に表示する。
- 研究の編集と研究のファイル一覧の画面は、終わっていないジョブ (失敗を除く) があるあいだ 3 秒ごとに表示を読み直し、ジョブが無くなったら止める。ジョブはリクエストとは別に動くので、終わったことが画面に送られず、読み直さないと「移動中」「切り替え中」の表示と押せないボタンが再読み込みまで残るためである。
- 研究 ID が無い研究のファイルは公開できない。公開の bucket での prefix が無いためである。
- 切り替えが終わっていないファイルは、名前の変更も削除もできない。どちらの bucket にあるかがまだ決まっていないためである。失敗で止まったファイルは削除できる。
- ファイルの公開は研究の公開と独立している。研究を公開してもファイルは公開されない。公開前の確認は、データセットに紐づけた非公開のファイルを一覧に表示してまとめて公開に切り替えられるが、ジョブの完了を公開の条件にはしない ([publishing.md](publishing.md))。

### 研究 ID の付け替えと研究の削除

公開の bucket の研究ごとの prefix は研究 ID で決まるので、研究 ID を変える操作と研究を消す操作はファイルの場所に関わる。

- 新しい研究 ID を primary にすると、元の研究 ID の prefix にある公開のファイルを新しい prefix へ移すジョブを、ID の割り当てと同じトランザクションで登録する。ファイルストアの一覧はトランザクションの前に取り、ファイルストアが応答しなければ何も確定しない。
- 公開の bucket の prefix にファイルがある研究 ID と、切り替えが終わっていないファイルがある研究の研究 ID は外せない。外すと公開中のファイルが 404 になり、その番号を次に割り当てた研究の一覧に残りのファイルが出てしまうためである。付け替えは、新しい ID を primary にし、移動が終わってから元の ID を外す。
- 研究の削除は、非公開の bucket の prefix か、その研究のどの研究 ID の公開の bucket の prefix にでもファイルが残っているあいだはエラーにする。ファイルストアのファイルは DB の削除と一緒には消えないためである。ファイルは研究のファイル一覧の画面で先に削除する。
- 研究の画面は、これらの操作のボタンを押せない形にして、理由と次にすべき操作を表示する。移動中の元の研究 ID には「ファイルの移動中」と表示する。ファイルストアが応答せず prefix の中身が分からないときは押せるまま残し、押したあとでエラーにする。

## データセットとファイルの対応

データセットとファイルの対応は、研究ごとの prefix の一覧に対する選択として、データセットの内容に保存する。

- 研究とデータセットのページの非制限公開ファイルの一覧はデータセットの内容に置かず、研究ごとの prefix の一覧から作る。公開ページは公開の bucket だけを、admin の画面と共有リンクのプレビューは両方の bucket を名前で合わせて見る。下書きの段階では公開の bucket が空だからである。
- 選択 (`fileSelection`) は集合で、順序は無い。データセットの内容には名前の順で書く (`app/files/selection.ts`)。
- 選択されていても、ファイルがあるとは限らない。一覧に無い名前は表示しないが、選択からは消さないので、同じ名前でアップロードし直せば再び選択された状態になる。非公開にしたファイルは、公開ページのデータセットからも同時に消える。
- 選択は一覧の作り方には使わない。一覧は研究ごとの prefix の一覧のままで、選択はその上の注記として、ファイルごとに紐づけたデータセット ID を添える。
- 外部のアーカイブのデータセットではファイルを選択できない。判定は primary のデータセット ID で行い ([data-model.md](data-model.md))、ID がまだ無いあいだも外部として扱う。選択を含む保存は 400 にする。

## ラベル

研究ごとの prefix のファイルには、日本語と英語の自由文のラベルを付けられる。ファイル名だけでは分からない中身を読者に示すためのもので、「Dictionary file」「SNVアレル頻度（常染色体）」のように書く。

- ラベルはファイルに付け、データセットのファイルの選択には付けない。同じファイルを複数のデータセットが選択していても、ラベルは 1 つである。紐づけの作業とは別に、ファイルの一覧を見ながら付けられるようにするためである。
- 決まった選択肢から選ぶ分類にはしない。ファイルの役割は選択肢に分けきれないためである。
- 研究の実体の ID とファイル名の組で、Postgres の表に置く。ファイルストアのメタデータには置かない。一覧の取得ではメタデータが返らずファイルごとに問い合わせることになり、変えるたびにファイルの中身ごとコピーし直すことになるためである。
- 実体の ID とファイル名で持つので、公開と非公開の切り替えや研究 ID の付け替えでは変わらない。ファイルの名前を変えるとラベルも新しい名前に移り、ファイルを削除するとラベルも消える。
- admin が研究のファイル一覧の画面で編集し、保存した時点で公開ページに反映される。ファイルの公開と同じく、研究の公開とは独立している。公開の bucket にあるファイルのラベルの変更は、操作の記録に残す。
- ラベルを表示するのは、ファイルの表 (公開ページの研究とデータセットの非制限公開ファイル、共有リンクのプレビュー、admin の研究のファイル一覧とファイルの紐づけのダイアログ) と、公開 API の `files` である。片方の言語が空なら、そのページにはもう一方の言語のラベルを表示する。日本語だけの PDF と英語だけの PDF のように、言語ごとに別のファイルがあるためである。
- 検索用の行には入れない ([data-model.md](data-model.md) の「全文検索」)。

## やっていないこと

- ファイルの所属の管理と、どこからも参照されていないファイルの検出。参照を追いきれない。
- データセットとファイルの名前の規約。対応は研究ごとの prefix の一覧に対する選択で表す。
- アップロードの再開。アップロードし直せば同じ名前で上書きされる。
- 研究ごとの prefix の下のディレクトリ。`common/` の slug の `/` も、ディレクトリとしては扱わない。
- ファイル名の全文検索。名前の正本はデータセットの内容ではなくファイルストアにある。
