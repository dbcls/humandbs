# ファイル

配信するデータファイルと、記事から参照する画像や PDF。**ポータルの中でここだけが Postgres の外に
実体を持ち、公開状態もそちら側にある。**

## 帰属を持たない

**ファイルは upload / download と公開状態の切り替えができるストアとして持ち、research・dataset・
記事への従属関係をモデルに持たせない。** 本文からの参照は URL の文字列で、外部サイトからの直接参照も
ありうるので、どこからも参照されなくなったこと (orphan) は判定できない。棚卸しは人が見る。

## 2 つの bucket

**実体は S3 (SeaweedFS) の 2 bucket に置き、公開状態は bucket の在籍そのもの。** Postgres は公開状態を
持たない。bucket を分けるのは、store で公開を表せるのが anonymous identity への bucket 単位の grant
だけだから。

| bucket | key | 読み手 |
|---|---|---|
| 非公開 (`private`) | `{研究の identity}/{ファイル名}` | admin のみ。server が presigned URL で渡す |
| 公開 (`files`) | `{研究 ID}/{ファイル名}`、`common/{slug}` | anonymous。proxy が `/files/` をそのまま渡す |

非公開側が identity なのは、ファイルの受け入れが研究 ID の pin より前に起きるため。公開側が研究 ID
なのは、`/files/hum0009/…` の URL が解決を挟まずに object に届くため。**研究の箱は flat** で、key は
ファイル名だけ。記事の画像と PDF は `common/` の箱に置き、公開 bucket 固定。

- **同じ (研究, ファイル名) が両方の bucket に同時に居ない。** 切り替えの途中で落ちて両方に居るのは
  未完了で、job の retry が解消する。job ごと失ったなら公開側を残す
- **store の port を外に出さない。** filer の HTTP は無認証で非公開 bucket の中身まで返す。読みも書きも
  proxy を通し、presigned URL の宛先もこの site の origin で作る (署名が host を含む)
- **配信するファイルをこの origin の文書として動かさない。** store は MIME を中身から推測し、upload の
  Content-Type は upload した人が決めるので、proxy がどちらの bucket にも `X-Content-Type-Options: nosniff`
  を付け、画像と PDF 以外を `Content-Disposition: attachment` にする。**SVG は画像ではなく文書**
  (直接開くと自分の script を走らせる) なので attachment に倒す。PDF 以外には
  `Content-Security-Policy: sandbox` を付け、inline で開いても別の origin として script 無しで描かせる。
  PDF が外れるのは、ブラウザの PDF viewer が sandbox の中で動かないため。`/private/` は常に attachment
  で sandbox
- **非公開のファイルの byte を admin 以外に渡さない。** 共有リンクの preview は名前とサイズを見せるが
  取得はさせない

## upload

**upload は presigned URL で、byte はアプリを通らない。署名に Content-Type と Content-Length を入れる**
ので、発行時に決めた種類と大きさ以外は 403 になる。64 MiB を超えるものは multipart で、開始と完了は
server、part の PUT だけが presigned になる。

- **upload 直後は非公開。** 受領した瞬間に匿名で取れる状態を作らない
- **同じ名前の upload は上書き。** 名前が key なので、画面は送る前に既にある名前を挙げて確かめる。
  問い合わせられなかったときは送らない
- **ページを閉じた後の再開は持たない。** 入れ直せば同じ名前で上書きされる
- **`common/` だけは置いた時点で公開される**ので、upload も削除も証跡に残る。slug は `/` を書けて
  階層に置き直せるが、変えると元のアドレスは 404 になる (本文の参照は人が直す)。コピーを先に行い、
  既に別のファイルがいる slug は拒む

## 切り替えの job

**公開状態の切り替えは CopyObject + DeleteObject の実バイトコピーなので、job にして操作を待たせない。**
Postgres が持つのは実行待ちの job だけで、job を失ってもファイルは公開か非公開のどちらかに留まる。
ファイル名は変えない。誰がいつ切り替えたかは証跡に残る。

- **1 ファイルに 1 行。** (研究, ファイル名) を鍵に upsert し、新しい意思は action を上書きする
- **完了は、読んだ action と行の action が一致するときだけ行を消す。** 実行中に意思が変われば実行待ちへ
  戻り、最後の意思に収束する
- **アプリのプロセスが `FOR UPDATE SKIP LOCKED` で回す。** 再起動で中断したものは起動時に実行待ちへ戻す
- **研究 ID を付け替えたら、公開側の箱を新しい箱へ移す job を pin と同じトランザクションで積む。** S3 は
  トランザクションの前に list し、S3 が答えなければ何も commit しない
- **切り替え中のファイルは名前の変更も削除もできない。** どちらの側にいるかがまだ決まっていない
- **ファイルの公開は研究の公開と独立。** 研究を公開してもファイルは公開されない。公開前の確認は、
  データセットが選んだ未公開のファイルを列挙してまとめて公開に倒せるが、job の完了を公開の条件にしない

**公開側の箱にファイルがあるか切り替えが終わっていない研究 ID の pin は外せない。** 外すと公開中の
ファイルが 404 になる。研究 ID の付け替えは、新しい ID を primary にして箱の移動が終わるのを待ってから
旧い ID を外す。**研究の削除も、非公開の箱か研究 ID の公開の箱にファイルが残るあいだは断る。**
研究の画面はこれらの操作を押せない形にして理由と次の操作を添え、移動中の旧い ID には印を立てる。
ストアが答えずに箱の中身が分からないときは押せるまま残し、押した先の断りに任せる。

## 一覧と選択

**ダウンロード一覧は content に持たず、箱を list して作る。** 公開ページは公開 bucket だけを、admin の
画面と共有リンクの preview は両方の bucket を名前で合成して見る (下書きの段階では公開 bucket が空なので)。

**データセットは、属する研究の箱の list に対する選択を content の中に持てる。**

- **選択は集合で順序を持たない。** content には名前順で書く (`app/files/selection.ts`)
- **選択は存在を主張しない。** 源は箱の list で、list に無いものは描かれない。非公開に倒したファイルも
  同時に消える
- **一覧の導出には使わない。** 一覧は箱の list のままで、選択はその上の注記 (ファイルごとにそれを選んで
  いるデータセット ID を添える逆引き)
- **外部アーカイブのデータセットは選択を持たない。** 判定は primary のデータセット ID の綴りで
  ([data-model.md](data-model.md))、ID が未 pin のあいだも外部として扱う。選択を伴う保存は 400

## 意図的にやっていないこと

| やらないこと | 理由 |
|---|---|
| ファイルの帰属と orphan の検出 | 参照が追いきれない |
| データセットとファイルの名前の規約 | 対応は箱の list に対する選択で持つ |
| upload の再開 | 入れ直せば同じ名前で上書きされる |
| upload でディレクトリを作ること | 名前に `/` を含む upload は 400。`common/` で階層に置くのは後から slug を変える操作 |
| ファイル名を全文索引に入れること | 名前の原本が content ではなく箱の側にある |
