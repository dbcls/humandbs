# 申請支援アシスタント

申請書とその添付を読んで、確認の材料を作る道具。ポータルの隣で動く別のサービス (`assistant-api/`) で、
管理画面から使う。ここに書くのは**ポータルとの境界**で、アシスタント自身が何をどう調べるかは
`assistant-api/` 側の doc にある。起動の手順は [development.md](development.md)。

## 境界

**アシスタントは認証も認可も持たない。** compose のネットワークの中だけで動き、port を外に出さない。
誰が使えるかはポータルが決め、`/admin/assistant/api/…` の proxy (`app/routes/admin-assistant-api.ts`) が
`use-assistant` を確かめてから要求を渡す ([auth.md](auth.md))。

**不変条件は 2 つで、崩れるとアシスタントは無認証で誰にでも開いた API になる。** どちらも
`app/assistant/boundary.test.ts` が source を読んで守る。

- **proxy は capability を確かめてから渡す**
- **ポータルの他のどこからもアシスタントを呼ばない。** 画面は proxy のアドレスを叩き、サービスの
  アドレスを知らない

加えて proxy が守ること。

- **ポータルの資格情報を渡さない。** session cookie と `Authorization` は落とし、帰りの `Set-Cookie` も
  落とす (アシスタントの cookie がポータルの origin に載るため)
- **よそのサイトから来た要求は断る。** 書き込みはポータル全体の検査 ([auth.md](auth.md)) が先に 403 に
  し、proxy は読み取りでも `Origin` が別のホストを名指せば 400 にする。形がアシスタントのもので、読み取りが
  何も起こさないとは言えないため
- **`..` を節に持つ道のりは断る。** アシスタントは「ここからしか呼ばれない」前提で書かれている
- **道のり・body・status は素通し。** API の形はアシスタントのもので、ポータルは endpoint を知らない。
  endpoint が増えてもポータルは変わらない
- **アドレスは `app/admin/urls.ts` の `assistantApiPath()` から取る。** 管理画面は言語の prefix を持たない
- **redirect はそのまま返る。** 相対の `Location` はポータルの側で解決されるので、アシスタントは redirect を
  返さないか proxy のアドレスで書く

## 大きさと時間

**body の大きさに上限を置かない。** 申請書の PDF は 1 MB を超えるので、この道は proxy の上限を
外してある (`docker/nginx/default.conf`。他に上限が無いのはファイルの upload を通す道だけ)。

**1 つの要求で、応答の 1 バイト目までが 5 分。** 超えると 502 になる。ポータルの HTTP client がそこで
待つのをやめるので、前段の timeout を伸ばしても変わらない。**5 分を超える処理を 1 つの要求で持たない** —
受け付けて id を返し進み具合を別の要求で取りに来るか、途中経過を流し始める。

## 責務

| | 持つもの |
|---|---|
| ポータル | アドレス、認可、画面の器、部品 |
| アシスタント | 画面の中身、API、申請書の解析、外部サービスとのやりとり、自分の state |

**画面はアシスタント側が書き、ポータルの部品で組む** ([development.md](development.md) の「画面の規則」)。**ポータルのデータは public API
から読む** — 認証が要らないので資格情報を渡さず、ポータルの DB に触る経路も作らない。

**アシスタントが外へ取りに行く URL は、宛先を検査してから繋ぐ。** URL は申請書と検索の結果から来るので、
内側のサービスを指されうる。http / https だけを通し、host を 1 度だけ解決して、アドレスが 1 つでも global
でなければ断り、繋ぐのは解決したそのアドレス (引き直すと DNS rebinding の窓が開く)。redirect は 1 hop
ごとに同じ検査を通し、Playwright はページが出すすべての要求を検査に通す (`assistant-api/src/url_guard.py`)。
**network でも隔てる** — `assistant-api` は `app` とだけ network を共有し、DB とファイルストアには届かない
([deployment.md](deployment.md))。

**state はアシスタントの中に閉じる。** 申請書と解析の途中結果は container の `work/` (名前付き volume) に
置き、ポータルの Postgres にも S3 にも入れない。失えばもう一度読ませればよく、backup の対象にしない。

**アシスタントが立っていない環境では、画面が「動いていません」と言う。** 無い環境を壊れた環境にしない。

## 意図的にやっていないこと

| やらないこと | 理由 |
|---|---|
| アシスタントに認証を持たせること | ポータルが前に立つので、2 つ目の認可があると答えが 2 通りになる |
| アシスタントの port を外に出すこと | proxy を迂回する経路になる |
| API を型で受けること | 形はアシスタントのもの。写しを持つと増えるたびに両方を直すことになる |
| state をポータルの DB に持つこと | ポータルのデータではない |
| 5 分より長く待てるようにすること | 長い処理を分けるほうが画面も作りやすい |
