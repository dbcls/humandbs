# 画面の部品

**画面は `app/components/` の部品から組む。** ここに書くのは、部品を足すときと画面を書くときに守らないと
壊れるものだけ。**どの部品をどこで使うかは書かない** — 見た目は文章で決まらないので、規範は
`/dev/ui` に並んだ実物のほうにある ([development.md](development.md) の「部品を見る」)。

## 層

| ファイル | 中身 | 知っていること |
|---|---|---|
| `app/components/icons.tsx` | アイコン (inline SVG) | 何も知らない |
| `app/components/base.tsx` | 帯・見出し・バッジ・ボタン・チップ・パンくず・タブ・折りたたみ・注記・確認・メニュー | 何も知らない |
| `app/components/form.tsx` | 入力とその見出し・エラー・送信 | form であること |
| `app/components/page.tsx` | ページの枠・カード・節・表・値の描画・注釈の層 | content の型 |
| その他 | 画面ごとの組み立て | ドメイン |

**下の層は上の層を知らない。** 部品は「何を描くか」と「どれだけ強いか」だけを受け取り、意味は画面が
与える。`base.tsx` に research や draft が出てきたら、それは画面側に属している。

## 色

`app/app.css` の `@theme` が唯一の定義。**Tailwind 既定のパレット (`gray-*`、`blue-*` …) を併用しない** —
独自色を定義しながら既定色も使うと、同じ役割に 2 系統の色が付く。

**コントラストは WCAG 2.1 AA を満たす** — 通常の文字で 4.5:1、押せるもの・入力できるものの境界で 3:1。
この要件は `app/app.contrast.test.ts` が持っていて、`app.css` から値を読んで計算する。**色を変えると
その test が落ちる。** 白文字を載せてよいのは `brand` / `brand-light` / `accent` / `deep` / `ink-muted` /
`danger` の 6 つだけ。

罫線は 2 系統ある。`line` は意味を持たない仕切り、`line-strong` は**押せるもの・入力できるものの境界**。
後者は 3:1 を満たす必要があるので、入力欄の枠に `line` を使わない。

## 壊れるもの

- **`SectionTabs` の中でブラウザの検証 (`required` 等) を使わない。** 隠れた節の中の必須項目はフォーカス
  できないので、保存を押しても何も起こらず理由も出ない。検証は server 側で行う ([editing.md](editing.md))
- **class 名を実行時に合成しない。** 見た目の表は完全なクラス文字列を値として持つ (`BUTTON_VARIANT` など)。
  断片を繋ぐと Tailwind がクラスを見つけられない
- **フォーカスの輪郭を消さない。** `app.css` が `:focus-visible` に置いていて、部品はこれを上書きしない。
  キーボードだけで操作する人にとって、いまどこに居るかを示すものが他に無い
- **アイコンだけのボタンには名前を付ける** (`IconButton` は必須にしてある)。アイコンは `aria-hidden` なので、
  名前が無いとその操作は「ボタン」としか読み上げられない

## 意図的にやっていないこと

| やらないこと | 理由 |
|---|---|
| ダークモード | 配色が 2 系統になり、コントラストの要件も 2 倍になる |
| アニメーション | 色の遷移だけ |
| CSS を書くこと | `app.css` にあるのは `@theme` と、markdown が吐く要素の見た目と、上のフォーカスの輪郭だけ。他は Tailwind のクラスで、部品の中に閉じている |
| ユーティリティに別名を付けること | `.btn` のような CSS クラスを作ると、部品と CSS の 2 箇所に同じ意匠が住む |
| アイコンのパッケージを依存に持つこと | 必要な字形だけを `icons.tsx` に inline SVG として持つ。輪郭は Lucide のもの (ISC) |
