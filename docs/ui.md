# 画面の部品

すべての画面は `app/components/` の部品から組む。ここに書くのは、部品を選ぶときと足すときに
従う規則。個々の部品の props はコードの側が SSOT なので写さない。

**見た目は旧ポータルから引き継ぐ。実装は引き継がない。** 帯とその下の白い箱、一覧の見出しの縦罫、
輪郭だけの丸ボタン、一覧を切り替える台形のタブ — これらは読者がこのサイトだと分かる手がかりなので
再現する。一方、旧ポータルは角丸を 20 種類・バッジを 4 実装・独自色と Tailwind 既定色を並行して
使っていたので、**そこには寄せる先が無い。この doc が挙げる規則は v2 で 1 つに決めたもの。**

## どこに何があるか

| ファイル | 中身 | 知っていること |
|---|---|---|
| `app/components/icons.tsx` | アイコン (inline SVG) | 何も知らない |
| `app/components/base.tsx` | 帯・見出し・バッジ・ボタン・チップ・パンくず・タブ・折りたたみ・注記・確認・メニュー | 何も知らない |
| `app/components/form.tsx` | 入力とその見出し・エラー・送信 | form であること |
| `app/components/page.tsx` | ページの枠・カード・節・表・値の描画・注釈の層 | content の型 |
| その他 | 画面ごとの組み立て | ドメイン |

**下の層は上の層を知らない。** 部品は「何を描くか」と「どれだけ強いか」だけを受け取り、意味は
画面が与える。`base.tsx` に research や draft が出てきたら、それは画面側に属している。

## 帯と見出しの使い分け

**帯 (`Band` / `PageHead`) は「自分の名前を持つ 1 つのものについてのページ」だけが持つ。**
research、dataset、draft がそれにあたる。一覧・記事・カタログの管理画面は `Heading` (青い縦罫 +
大見出し + 件数) で始める。

この線を引くのは、帯に意味を持たせるため。すべてのページが同じ帯で始まるサイトでは、帯は何も
言っていない。

帯は 3 段。`deep` がそのページの主題そのもの、`brand` がその下の節と表、`accent` はページが
1 つだけ持てる呼びかけ。**1 ページに `deep` が 2 つあってはいけない** — 主題が 2 つあることになる。

## 色

`app/app.css` の `@theme` が唯一の定義。**Tailwind 既定のパレット (`gray-*`、`blue-*` …) を
併用しない** — 独自色を定義しながら既定色も使うと、同じ役割に 2 系統の色が付く。

**白文字を載せてよいのは `brand` / `brand-light` / `accent` / `deep` / `ink-muted` / `danger`
の 6 つだけ。** それ以外の上に白を置くと読めない。

**コントラストは WCAG 2.1 AA を満たす** — 通常の文字で 4.5:1、押せるもの・入力できるものの境界で
3:1。この要件は `app/app.contrast.test.ts` が持っていて、`app.css` から値を読んで計算する。
色を変えるとその test が落ちる。

このため **3 つの値が旧ポータルから一段暗い**。旧ポータルの帯の右端は白文字に対して 2.2:1、
ピンクは 4.4:1、入力欄の枠は 2.1:1 しか無かった。色相はそのままに明度だけ落としてあるので、
並べないと分からない差になる。

罫線は 2 系統ある。`line` は意味を持たない仕切り、`line-strong` は**押せるもの・入力できるものの
境界**。後者は 3:1 を満たす必要があるので、入力欄の枠に `line` を使わない。

## バッジ・ボタン・印

**バッジは輪郭と文字色だけで、塗らない。** 塗ると帯と目の奪い合いになり、40 行の一覧が 40 個の
色の塊になる。帯の上に置くときだけ `onBand` で白い輪郭にする。

**バッジの色は意味を運ばない。** 語が運ぶ。色が区別できない読者にも同じことが伝わる。

**アクセス制限はバッジではない。** 鍵と語だけで書く。制限公開かどうかはデータセットが通り過ぎる
状態ではなく持っている性質で、一覧の全行が輪郭で囲われていると飾りとして読み飛ばされる。

ボタンは 5 種。`primary` はその画面がしてほしい 1 つのことで、**1 画面に 1 つまで**。`danger` は
戻せないこと (取り下げ・削除・下書きの破棄) に限る — そこを緩めると色が意味を失う。`pill` は
形であって強さではないので、どの種類とも組み合わせる。

**アイコンだけのボタンには名前を必ず付ける** (`IconButton` は必須にしてある)。アイコンは
`aria-hidden` なので、名前が無いとその操作は「ボタン」としか読み上げられない。

## タブ

2 種類あり、**アドレスを持つかどうかが違う**。

`SwitchTabs` は一覧の切り替えで、中身はリンク。どちらを見ているかがアドレスに載るので共有でき、
戻るボタンで戻れる。

`SectionTabs` は長いフォームを節に切るもので、中身はボタン。**切り替わるのは表示だけで、全 field は
文書に残る** — 1 回の保存がフォーム全体を運び、タブを移動しても入力が失われない。そのぶん、
見えていない節に起きたこと (未保存・公開版との差・未読のコメント・保存が返した問題) は
**タブの側に印として出す**必要がある。

**このフォームでブラウザの検証 (`required` 等) を使わない。** 隠れた節の中の必須項目は
フォーカスできないので、保存を押しても何も起こらず理由も出ない。検証は server 側で行う
([editing.md](editing.md))。

タブの帯はキーボードの停留点が 1 つで、矢印キーと Home / End で中を移動する。

## 表

**列には上限と下限の両方がある。** 上限が無いと 1 つの長い要約が他の列を潰し、下限が無いと
狭い画面が列を 1 文字ずつに折り返す。表はページより広くなってよく、自分の箱の中で横スクロールする。

accession のような識別子の列は折り返さない (`nowrap`)。

**並べ替えはリンク** (`SortHeader`)。順序がアドレスに載るので共有でき、script を要さない。
どちらの順かは語でも言う — 薄い矢印の向きは誰にでも見える差ではない。

## 絞り込みパネル

facet ごとに畳む。**条件が入っている区画は必ず開く** — 効いている絞り込みが見えない一覧は、
自分について嘘をつく。詳しくは [public-pages.md](public-pages.md) の「絞り込み」。

## アイコン

**アイコンのパッケージを依存に持たない。** 必要な字形だけを `icons.tsx` に inline SVG として持つ。
輪郭は Lucide のもの (ISC) で、旧ポータルが描いていた字形と同じ。

**アイコンはそれ自体では意味を運ばない。** すべて `aria-hidden` で、意味は隣の語かボタンの名前が持つ。

## `/dev/ui`

全部品を実データで並べた 1 枚。部品を変えたら開いて確かめる。手順は
[development.md](development.md) の「部品を見る」。

## 意図的にやっていないこと

- **ダークモードを持たない。** 配色が 2 系統になり、コントラストの要件も 2 倍になる
- **アニメーションを持たない**。色の遷移だけ
- **CSS を書かない。** `app.css` にあるのは `@theme` と、markdown が吐く要素の見た目だけ。
  それ以外は Tailwind のクラスで、部品の中に閉じている
- **class 名を実行時に合成しない。** 見た目の表は完全なクラス文字列を値として持つ
  (`BUTTON_VARIANT` など) — 断片を繋ぐと Tailwind がクラスを見つけられない
- **ユーティリティを別名にしない。** `.btn` のような CSS クラスを作ると、部品と CSS の 2 箇所に
  同じ意匠が住む
