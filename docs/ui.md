# 画面の部品

**画面は `app/components/` の部品から組む。** ここに書くのは、部品を足すときと画面を書くときに守らないと
壊れるものだけ。**どの部品をどこで使うかは書かない** — 見た目は文章で決まらないので、規範は
`/dev/ui` に並んだ実物のほうにある ([development.md](development.md) の「部品を見る」)。

## 層

| ファイル | 中身 | 知っていること |
|---|---|---|
| `app/components/icons.tsx` | アイコン (inline SVG) | 何も知らない |
| `app/components/base.tsx` | 積み方・帯・見出し・バッジ・ボタン・チップ・パンくず・タブ・折りたたみ・注記・知らせ・確認・メニュー | 何も知らない |
| `app/components/form.tsx` | 入力とその見出し・エラー・送信 | form であること |
| `app/components/page.tsx` | ページの枠・カード・節・表・値の描画・注釈の層 | content の型 |
| その他 | 画面ごとの組み立て | ドメイン |

**下の層は上の層を知らない。** 部品は「何を描くか」と「どれだけ強いか」だけを受け取り、意味は画面が
与える。`base.tsx` に research や draft が出てきたら、それは画面側に属している。

## 色

`app/app.css` の `@theme` が唯一の定義。**Tailwind 既定のパレット (`gray-*`、`blue-*` …) を併用しない** —
独自色を定義しながら既定色も使うと、同じ役割に 2 系統の色が付く。**`@theme` に無い名前も同じ穴** —
そちらはクラスが生成されないので、枠は残ったまま `currentColor` を取り、意図した灰ではなく本文の色で
出る。どちらも `app/app.contrast.test.ts` が見張る — 色を取る接頭辞の付いた綴りを集めて `@theme` と
突き合わせるので、**色ではない同じ形のユーティリティ (`border-b`、`text-sm`) はそこに書き出してある**。

**通った・正しいを色で言わない。パレットに緑が無いのはこのため。** 色が付いているものは読む人が
見にいくものなので、通ったものにも付けると見にいく先が無くなる — 検証の表は行の大半が通っていて、
全部に色を敷くと「見るべき 1 行」が同じ密度の中に沈む。**外れたものだけが色を取り、通ったものは本文の
色のまま立つ。**

**コントラストは WCAG 2.1 AA を満たす** — 通常の文字で 4.5:1、押せるもの・入力できるものの境界で 3:1。
この要件は `app/app.contrast.test.ts` が持っていて、`app.css` から値を読んで計算する。**色を変えると
その test が落ちる。** 白の本文を載せてよいのは `brand` / `brand-light` / `accent` / `deep` /
`ink-muted` / `danger` の 6 つだけ。

**`accent-light` / `accent-lighter` / `brand-lighter` は 3:1 しか満たさない。** どれも大きい文字しか
載らないところ — 帯の右端と、トップの入り口 2 つ (`BigAction`) のグラデーションの右端 — にだけ使う。
入り口が帯と別の色を持つのはこのため: 帯は小さい白文字を運ぶので、両端とも 4.5:1 を要る。

**帯の振れ幅は暗いほうへ広げる。** 明るい側は 4.5:1 が天井なので動かせず、リンクの色から始めると輝度が
1.43 倍しか動かず、目にはべた塗りに見える。**暗い側には失うものが無い**ので、帯の左端だけ `brand-dark`
(7.1:1) から始めて 1.8 倍にする。**取れるだけ取らない** — 8.2:1 まで落とせば v1 と同じ 2.2 倍になるが、
そこまで行くと左端がこの site の青ではなく紺に見える。要るのは「動いて見える帯」であって最大幅ではない。
**`brand` を暗くして済ませない** — あれは白地の上の線と字でもあり (`Badge`、`LISTING_CONTROL`)、
そちらは濃くすると別の設計になる。

**帯は箱の中で振り切る。表の幅の中ではない。** 表は箱より広く横に流れるので、表いっぱいに引いた
グラデーションは振れ幅の 3 割強を画面の外で使い切る — 端から端までが 1.77 倍でも、**読者が見ている
範囲は 1.46 倍**にしかならない。だから表の見出しだけ、読者の画面の箱の幅あたりで明るい側に着かせる
(`page.tsx` の `to-[1200px]`)。横に流したその先は明るい側を走る。**この停止位置は `BAND_FILL` には
置かない** — ほかの帯は最初から箱と同じ幅で、同じ塗りを取る丸い印は 28px しかないので、そこで止めると
暗い側のべた塗りになる。

**固定列の見出しも同じ帯を継ぐ。** 固定されたセルは自分で背景を塗らないと下を通る行が透けるが、平らに
塗ると帯がそこで振り出しに戻る — **1,200px の掃きに対して、研究一覧の固定列 164px は 13.7%、データ
セット一覧の 284px は 23.7% 進んだ位置**で、縦の継ぎ目として出る。**同じ帯を、セルの立つ位置ぶん左へ
ずらして敷く** (`page.tsx` の `STUCK_BAND`)。掃きの幅を書き出すのは、原点をセルではなく表に取るため —
書かないと 60px の中で全域を走る。**横に流しているあいだはズレる** (固定列は箱に留まり、隣は表と
一緒に動く) が、そのときはそこに `FROZEN_EDGE` が立つので、継ぎ目ではなく境として読める。

罫線は 2 系統ある。`line` は意味を持たない仕切り、`line-strong` は**入力できるものの境界**。後者は 3:1 を
満たす必要があるので、入力欄の枠に `line` を使わない (`line` は白に対して 2.09:1 しかない)。

**押せるものの縁は brand で、`base.tsx` の `LISTING_CONTROL` が 1 つ持っている** — 白地・brand の細枠
(8.6:1)・`rounded-full`。一覧の上に立つものはこれを取る: コピー・TSV・並び替え・表示件数・ページ送りの
箱。**v1 も 1 つの class (`captionAction`) でこの 5 つを描いていた**ので、寄せ先を決め直す必要が無かった
唯一の軸になる。**帯の上の丸だけは別**で、地が濃いので白で描く。

面の色は 4 つ。`surface` がページの地と絞り込みのパネル、`surface-hover` が指したとき、`surface-input`
が入力欄の塗り、`surface-light` が**ページの地より明るい面** — 一覧のタブのうち選ばれていない側だけが
使う。**枠を持たない面は、地と違う色でなければ形を失う**ので、タブに `surface` を当ててはいけない
(それはページの地そのもの)。

**フォーカスの輪郭は `focus` の 1 色**で、brand より薄い。輪郭は縁に重なるので (「壊れるもの」の
フォーカスの項)、**控えの縁と、その外の地の両方**に対して 3:1 が要る。いちばん暗い地 (ページの tint)
が下限を決めていて、いまの値はそこで 3.28:1 — **これ以上薄くする余地は無い。**

**リンクの下線は、文の中にあるときだけ引く。** WCAG 1.4.1 が求めているのは「周りの語と見分ける手段が色
だけにならないこと」で、これが問われるのは**流れている文の中**だけ。一覧の題目・サイトマップの項目・
パンくずの段は位置がリンクであることを言っているので、そこに下線を引くと画面が罫線の原になる。
文であるのは 2 か所だけ — 記事の markdown (`.markdown a`) と、research content の文の span
(`components/page.tsx` の `SpanText`)。**指したときはどのリンクにも下線が出る**が、リンクではなく
コントロールである部品 (ボタン・バーの丸・チップ・絞り込みの行) は `no-underline` を持ち、hover でも
出さない。

**枠を持たないのは検索の窓 1 つだけ。** 塗った丸に色のついたボタンが入っている形は他の何とも見間違え
ようがないので、境界の 3:1 をこの 1 つには当てない。規則が守っているのは、見つけるまで何も無いように
見える入力欄のほう。

## 押せるもの

**面が答えるのは「どれだけ押してほしいか」の 1 つだけ。** 塗り・枠・字だけの 3 段と、取り消せない
ものの警告で 4 つあり、どれをいつ取るかは `base.tsx` の `ButtonVariant` が理由ごと持っている。
**画面が面を増やさない** — 選べる面があると、次に画面を書く人はそこから選ぶ。

**5 つ目の `accent` だけは、画面が選ぶものではない。** 着るかどうかを決めるのは**欄に何が打たれたか**で、
送っていない変更を抱えた保存だけが着る。**だから画面に 1 つとは限らない** — 編集するものが 4 つ並ぶ画面は
4 つとも待っていることがある。塗りが画面に 1 つなのは `primary` の話で、こちらは状態の報せ。

**取り消せないものは、入口から警告の面を着る** (`Confirm`)。外す・取り下げる・削除するは、確かめる
画面まで進んでから危ないと分かるのでは遅い。**読者が持っているアドレスが答えなくなるものも同じ** —
消さずに名前を変えるだけでも、外から書かれた参照は同じように届かなくなる。**押し返せるものは着ない** —
公開と公開停止のように、隣り合う 1 つのボタンで往復できるものは、確かめる面を挟むより押し直すほうが
速い。**着るのは、押し返す先が画面に無いもの**。**その入口は小さいほうを取る** — 隣に立つのは自分が
作用する対象で、同じ大きさで並ぶと対象より操作のほうが大きくなる。
**バッジと同じ枠色・同じ字色にならないのはこのため**で、小さい枠付きの箱が 2 つ並ぶとき見分けている
のは色のほう。

**確かめる面は、対象と操作を見出しで名乗る。** 入口の語は行の中にあるので「削除」で足りるが、面は
それだけで 1 つの画面になる — 開いた人が知りたいのは何が消えるかで、警告の文はそれを言わない。
**警告の文が言うのは、押したあと何がどうなるか** — 戻せないものだけが「元に戻せません」と結び、戻せる
ものは「直して同じ番号で公開し直せます」のようにどう戻すかを書く。**識別子を裸で置かない** — `v1` や
`hum0588` だけでは、それをどうするところなのかがどこにも書かれていない。見出しは他の見出しと同じ印を
継ぐ。**ただし対象が欄に立っているときは名乗らない** — slug を打ち直す面は、打つ欄そのものに今の値が
入っている。見出しが繰り返すと同じ文字列が 2 度出るだけで、しかも欄のほうは打つと変わるので、2 つは
すぐ食い違う。

**面の幅は 2 つしかなく、どちらも中身なりには縮めない。** 中身に合わせると、短い警告の面が 288px、
長いものが 448px になり、同じ形の問いが画面ごとに違う大きさで出る。**問う面は 448px、書く面は 672px**
(`base.tsx` の `Dialog` の `wide`) — 前者はいちばん長い問いで止めた幅、後者は欄が入る幅で、ja と en を
上下に積んだ対が 448px では 1 行を読む幅に足りない。**窓がそれより狭いときだけ譲る。**

**繰り返しの要素は、一覧では名乗るだけで、書くのは面の中** (`fields.tsx` の `ItemList`)。研究の編集
画面は 4 つの一覧を持ち、要素 1 つが最大 8 欄あるので、開いたまま並べると画面は百個の箱になり、
**一覧そのものが言うこと — 何件あるか、どの順か — がその中に埋もれる**。行は要素の名前と、要素に
できること 4 つ (編集・上へ・下へ・削除) だけを持つ。**足したらその面が開く** — 何も書かれていない
要素は行の上で何も名乗らないので、足して閉じたままにすると、読む人は空の行を探して開くことになる。
**面は書いたそばから一覧に入る** — 確定も取り消しも持たない。下書きを保存するのは画面が 1 つ持つ保存で、
面が自分のボタンを持つと、work の置き場所が 2 つあるように見える。

**警告の字は赤くない。** 危ないのは操作のほうで、それを実行するボタンが警告の面を着ている。同じ赤を
文にも敷くと、いちばん読ませたい 1 文がいちばん読みにくい色 (14px の赤字) で出る。**面の中で色を持つ
のは実行するボタンだけ。**

**押せるものは印を持つ。** 語だけのボタンが 3 つ 4 つ並ぶ行では、どれが何をするのかは読むまで分からず、
同じ行に 1 つだけ印があると、その 1 つだけが別の種類の操作に見える。**印が言うのは操作の種類で、画面が
選ぶものではない** — 作る・追加は `plus`、保存は `save`、消すは `trash`、公開は `upload`、探すは
`search`、取り込むは `download`、割り当て・張り替えは `link`、表示と非表示は `eye` / `eye-off`。同じ
操作が画面ごとに違う印を持つと、印は手がかりではなく飾りになる。**確かめる面を開く入口も、その面の中で
実行するボタンと同じ印**を持つ。

**管理画面では、押せるものの語は名詞で、動詞で終わらない。** 「アラートを作る」ではなく「アラートの作成」、「消す」で
はなく「削除」。**面の名前が既に名詞だから**で、「アラートの削除」という見出しの下に「削除する」という
ボタンが立つと、同じ 1 つの操作が 1 つの面の中で 2 通りの語で名乗ることになる。**丁寧語も命令形も使わない**
— 「削除します」は画面が話しかける形、「削除せよ」は画面が命じる形で、どちらもボタンが自分の名前を言う
形ではない。**「〜する」を落として名詞が残らない語は、その語を選び直す** — 「変える」は「変更」、
「捨てる」は「破棄」、「見る」は「表示」。**公開側はこの規則の外**で、そこは読者が自分の手で何かを
するところなので、控えめな名詞より「カートに入れる」のほうが通じる。

**同じ操作なら同じ語で名乗る。** 増やす操作の語は 2 つしかない — 保存されて一覧に行が増えるものは
「作成」、その場のフォームに行が 1 つ増えるだけのものは「追加」。分かれ目は押した後に何が残るかで、
対象の重さではない。**「足す」と「新しく」は使わない** — 前者は「追加」を別の語で言い直しただけで、
後者は `plus` の印が既に言っている。**消すことの語は「削除」1 つ** — 「消す」と使い分けない。対象の
重さで語を替えても、押す側にその境目は読めない。en は `Create` / `Add` / `Delete` が同じ割り方を負う。

**入口と実行は同じ語幹で、長さだけが違う。** 対象の名前を持てるのは入口 (「アラートの作成」) で、確かめる
面の中のボタンは面が名乗った対象を繰り返さない (「作成」)。**押せるものの語に目的語は要らない** — 同じ
行に並ぶ 3 つが「保存」「公開停止」「削除」で読み分けられるのは、それぞれが違うことをするからで、
何に対してするかは節の名前が既に言っている。

**選ぶことは押すことではない。** 選ばれているものを塗るのは**今どうなっているか**を言うもので、
どれを押してほしいかではない。**操作の面を借りると、その画面の primary が読めなくなる** — 編集画面は
欄ごとに 3 択を持つので、借りた瞬間に「画面に 1 つ」のはずの塗りが数十個に増え、保存の塗りがその中に
埋もれる。**選択は溶接された 1 つの器で描く。** 輪郭を持つのは器のほうで、中の区画が選択肢を分け合い、
選ばれた区画だけが塗られる。**単独で立つボタンとは形が違う**ので、同じ brand の塗りでも読み違えない。

**既定の状態は描かない。** 欄ごとに 1 つ持つ選択はそのほとんどが既定のままで、中身の無い下書きでも
20 を超える — 欄が値を持つという当たり前を、欄の数だけ塗って言うことになる。**言う値打ちがあるのは
既定から外れたものだけ**なので、既定のあいだは器ごと畳んで外れ方だけを出し、外れているあいだは何で
あるかを語で名乗って、値に戻る道を隣に置く。こうして画面に残る塗りは、保存とペインの切り替えだけになる。

**選択の姿は 2 つあり、分かれ目は数。** 語が短く 2〜3 個なら全部見せ (`Choice`)、それ以上なら閉じて
いまの答えだけを名乗る (`Chooser`)。開くほうが器を持つ理由は「色」の `LISTING_CONTROL` にある。

**行が並ぶ画面はどれも同じ道具を持ち、その道具は 1 つの行にまとまる。** 並び替え・1 ページの件数・
件数・ページ送りの順に右端へ寄せ、**表の上と下に同じ行を置く** ([public-pages.md](public-pages.md) の
「並びと件数」)。**2 行に割らない** — 割ると 4 つが別々の設備に見え、このページを見限った読者が次の
ページへの道を別の行から探すことになる。ペインを持つ一覧ではこの繰り返しを `search.tsx` の
`RefinableList` が引き受け、ペインを持たない画面は自分で 2 か所に置く。**ページに切られない一覧も、
件数だけの同じ行を同じ場所に持つ** (`page.tsx` の `Counted`) — 表が何行あるかは、ページを繰れるか
どうかとは別に読みたいものになる。**どれも選ばれている値をアドレスに書く** — 既定はアドレスに
書かないので、何も選ばなかった人のアドレスは素のままになる。**並べ替えたら 1 ページ目に戻る**: 見たことのない並びの 7 ページ目は誰も
求めていない。**並びは全順序**でなければならず、同じ値で並んだ行は識別子で決着させる — 順の決まらない
2 行は要求ごとに入れ替わり、ページの境目をまたいで二度読まれたり消えたりする。

**探す窓の薄い字は「キーワード検索」の 1 つ** ([public-pages.md](public-pages.md) の「一覧と検索」)。
管理の一覧も公開と同じで、**何を探す窓なのかを言うのは `aria-label` の側**になる — 窓の上には画面の
名前が、下には列の名前が既に立っているので、薄い字がそれを繰り返すと 256px の幅をもう一度読まなくて
よい語に使うことになる。

**部品を通さずに押せるものを描かない。** 手で書いた面は規則の外に立つ — 実際、管理画面には枠の色も
字の色もどの面とも違うものが 48 か所あった。`Button` / `ButtonLink` / `IconButton` / `Choice` の
どれかを通す。**要素が `button` になれないところ**だけは例外で、`<summary>` は `controlFace()` から
面を借りる。

**file input は browser の控えを隠して、本物のボタンで押す** (`form.tsx` の `FileField`)。browser が
描く控えは擬似要素なので `file:` を 1 つずつ付け直すことになり、**同じ面を 2 度綴った先は必ずずれる**。
隣に browser が自分の言葉で書く「選択されていません」も、どのファイルを求めている欄なのかを言わない。
隠したうえで**選ばれたものは画面が言う**。**隠した欄に `required` を置かない** — フォーカスできない相手を
指して止まるので、要るかどうかは画面が言い、送るものが揃うまで送りを閉じる (「壊れるもの」の隠れた節の
検証と同じ根)。

**pull down は browser が描く矢印を落として、site の印を重ねる** (`form.tsx` の `PULLDOWN` /
`Pulldown`)。select が描くもののうち page から手の届かないのは閉じているときの矢印だけで、そこだけが
同じ面に並ぶ欄と別の絵になる。重ねるのは、メニューが値を持つときに出すのと同じ `chevron-down`。
**大きさを言い直す** — 他の欄は page の字を継ぐが、select は行が `normal` から始まるので、放っておくと
隣の欄より 4.4px 低い箱になる。**書くのは大きさで、行の高さは書かない** — 大きさごとの行は `app.css` が
持っているので、ここに `leading-*` を書くと同じことを言う規則が 2 つ並び、勝つのは後から書いたほうに
なる。**開くリストは browser のまま** — page の外に描かれるものなので、引き取ると
keyboard の歩き方も打ち込みでの絞り込みも電話が出す picker も自分で書くことになる。

**絞り込み pane を畳む・開く 2 つは `search.tsx` が持つ** (`RefinableList`)。見出しと同じ大きさで読ませる
字の控えと、効いている数を連れて立つ 36px の箱で、どちらも上の 5 つの面のどれでもない — **同じ 2 つを
公開と管理の 6 つの一覧が使う**ので、面を持つのは画面ではなく部品の側になる。**畳んだ側が数を連れるのは
不可欠**で、条件そのものは畳んだ pane の中にあり、数が無いと絞り込まれた結果を前にして絞り込みを
名乗るものが画面から消える。

## 管理画面の枠

**管理画面はポータルの器を着ない。** お知らせ・サイトマップ・背景の写真・カートはどれも読者に向けた
もので、編集しに来た人には出さない。**バーの行き先は管理のものに入れ替わる。****判定はアドレスと、その人が admin かどうかで
行う** (`app/root.tsx`) — route が決まる前に描かれる層なので、画面が自分で名乗る形にはできない。
admin かどうかも見るのは、`/admin` の下でどの画面にも当たらないアドレスが session を要求しないまま
404 を返すため。よそから来た人には公開の器と、そこから出られるナビが出る。

**区画から出る道はアカウントのメニューが持つ。** wordmark はいまいる区画のトップを指す (管理画面では
`/admin`) ので、バーも wordmark も区画の中だけを指す。**渡る先の区画の名前を名乗る 1 行が向きを変える**
形で、「Admin」と「Public」が同じ位置に排他で出る — いま立っている側の名前はメニューに出ない。**その行
だけが遷移の印を持つ** — 隣が session を終わらせるログアウトで、行き先と操作が同じ姿で並ぶと押して
確かめることになる。

**行き先はバーが持つ。** 公開ページが行き先を並べているのと同じ 1 行に、管理の 8 つが並ぶ
(`components/layout.tsx` の `AdminNav`)。**同じ器で同じ文法** — 前から入るだけ入れて、入り切らない分は
行の端のメニューに畳む。バーは窓の幅を使い切るので、管理画面が表と 2 言語を横に並べた編集画面である
ことは変わらない — **行き先に画面の幅も高さも渡さない**。

**並べる 8 つは、区画のトップが並べるのと同じ集合を、同じ順で。** 片方で覚えた位置がもう片方でも同じ
ところにある。**諦める順は並びから決まる** — バーは前から入るだけ入れるので、作業の最後に来るものが先に
メニューへ落ちる。集合と順の食い違いは `app/admin/navigation.test.ts` が突き合わせる。**入り切る数は語の
幅から決める** — ja / en の両方で測り、wordmark とメニューと右の 3 つが取ったあとに行がまだ空いて見える
幅を段にする。**3 段目から先は en が決める** — 同じ 9 画面が en では 2 割ほど広く、ja だけ見て詰めると
en で溢れる。

**足す先は `app/admin/navigation.ts` の 1 箇所**で、画面が区画の行き先を自分では持たない。

**区画のトップが並べるのは作業で、行き先の一覧ではない。** 節が何についての編集かを名詞で言い、その下に
押せるものが並ぶ — **区画そのものが編集の場所なので、節ごとに動詞を繰り返さない**。「お知らせ」が読む
画面か書く画面かは `/admin` の下にあることが決めていて、項目の名前をいくら長くしても決まらない。**押せるものの語は h1 と同じでなくてよい** — h1 はどこから来た人にも役割を言うので「お知らせ一覧」と
名乗り、節の下に並ぶ入口は節が場所を言っているぶん「お知らせ」で足りる。**ただし同じ行き先を指す語は、
バーと区画のトップで 1 つに揃える** — 同じ画面が 2 つの名前で呼ばれると行き先が 2 つあるように読める。
**入口は語の前に印を持つ** — 印が言うのは対象で、遷移ではない。**遷移の印を持つのは 2 つだけ** — 区画を
渡る 1 行と、画面から出る 1 本 (`AdminBack`)。
**識別子を要らない 8 画面はどれかの節に入り**、残る 14 は
研究・下書き・記事・項目を 1 つ選んだ先にある。**押せるものは行き先とは限らない** — 研究を新しく作るのは
操作で、行き先だけを並べると始め方が 3 通りから 2 通りに減って見える。**説明の 1 文を持つのは、名前で中身を言えない節だけ**で、どの節にも付けると読む価値の
ない文が並んで節の名前まで読まれなくなる。
**capability では絞らない** (`navigation.ts`) が、**capability を 1 つも持たない人にはトップの中身ごと
出さない** — 開かない扉の一覧は「なぜ何もできないのか」の答えにならない。

**画面の名前は、その画面ですることを言う。** 識別子だけの h1 を置かない — `hum0588` が研究の画面にも
下書きの画面にも出ると、開いた人は自分がどちらにいるか分からない。**h1 は役割を言い、識別子はその隣に
立つ** (`Heading` の `title` と `aside`)。

**隣に立つのは「どれについてか」だけ。** 件数は置かない — いくつ見ているかは表の上が言うことで、画面の
名前の一部ではない。**大きさは本文と同じ 16px** — そこに立つのは番号か slug で、読み流す添え書きでは
なく 1 文字ずつ確かめる値なので、12px の添え書きの扱いにすると用が足りない。**identity を持たない画面は
隣を空ける** — お知らせは日付も題も下のフォームの値で、名前の隣に据えると読者が打つたびに画面の名前が
動く。**h1 と識別子は中心で揃える** (下の「揃え」)。

**窓の名前は、画面が隣を空けていても識別子を載せる。** 画面の中ではフォームの値の写しになるものが、
**窓では唯一の手がかり**になる — 同じ役割の画面を 2 つ開いた人は、窓の名前が同じなら区別する道を持たない。

**窓の名前は、画面の名乗りをそのまま並べる** — h1、その隣に立つ識別子、サイト名の順
(`app/i18n/title.ts` の `pageTitle`)。**綴れる場所は 1 つで、画面が自分で組み立てない** — 語順の違いは
同じ区画の画面をいくつも開いた人にしか見えないので、画面ごとに書ける形にすると割れたまま残る。
**区分の名前は挟まない** — 区画を名乗ることは窓の名前の仕事ではない。**件数も載せない** — いくつ見て
いるかは、窓をいくつも開いた人がそれを見分ける手がかりにならない。**識別子を持たない画面は名前だけ**に
なり、無いものを役割の言い直しで埋めない。

**管理画面の名前はどれも同じ形** — 白い箱の中の、縦棒を持つ h1。**帯で名乗る管理画面は無い**。
帯 (`PageHead`) は公開ページそのものの印で、公開画面と、その姿を見せる場所 (編集画面のプレビュー面・
共有プレビュー) だけが着る。同じ画面に 2 つの名乗り方があると、読む人は形の違いに意味を探す。
**編集画面のバー (`DraftBar`) だけは識別子と役割を 1 つの名前にする** — 「hum0588 下書きの編集」。
バーは箱の外にあって、隣に小さく置く場所を持たない。**一覧の名前は対象の名前だけで、「一覧」を付けない** —
画面が一覧であることは表が言っている。

**編集画面のバーは 2 段で、段が役割を分ける。** 上は名前と、そこから出る道と、下書きの別の顔と、保存 —
いま何を編集していて、どこへ抜けられて、書いたものをどうするか。下は誰が一緒に開いているかと、画面の
並びの切り替え。**名前は箱の縁から始まり、他の画面の h1 と同じ段に立つ** — 編集画面だけ小さい見出しを
持つと、同じ区画の中で画面の名前の読み方が 2 通りになる。**名前の右に並ぶものは控えの面のボタンで、語の
前に印を持つ** — 素の語のまま並べると名前の続きの文に読めて、押せるものだと分からない。

**管理画面はパンくずを持たない。** 区画の中の位置はバーと区画のトップが言うので、同じ階層をどの画面の頭にも
書くと、読めるのは自分の居場所ではなく段の数になる。**一覧から開く画面は、その一覧へ戻る道を 1 本持つ**
(`components/admin.tsx` の `AdminBack`)。**親がバーに並んでいても持つ** — バーが並べるのは区画の入口で、
いま開いている 1 件がどの一覧から来たかは言わない。行を見比べる作業は 1 件ずつ開いては戻るので、戻る道の
無い画面はその往復のたびにバーを経由することになる。**1 画面に 1 本で、行き先を名指しする** — 隣に何も無い 1 本のリンクに「戻る」と書いても、
どこへ戻るのかを言うものが画面に無い。**控えの面のボタンで描く** — 画面から出る道は、その画面が並べる
行き先と同じ高さのものなので、素の語で置くと見出しの添え書きに見える。**公開の画面では、その 1 本が公開のボタンの隣に立つ**「やめる」で、
公開をやめることと下書きへ帰ることが 1 つの操作だから。**編集画面の帯に並ぶ行き先は戻る道ではない** —
下書きの別の顔 (データセット・レビュー・公開) で、役割が重ならない。

**操作の答えは画面の上に浮く。** 保存したことを画面の中に書くと、いま直した欄の上に 1 本増えて、押した
瞬間に読んでいた行が下へ動く。**答えは窓の上端中央に出て、数秒で消える** (`Answered`) — 公開側が
データセットをカートに入れたときに出すのと同じ器で、管理画面のどこで保存しても同じ場所に出る。**読んで
いる間は消えない** (指が乗っているか focus が中にある間はタイマーを止める)。**消える時間は公開側と
同じ 1 つの値** — site の中に 2 つの長さを持たない。長く読ませたいのは失敗を言う箱だけで、それは読んで
いるあいだ消えないことで足りる。**JavaScript を切っていても出る** — 管理の
フォームは素の POST で動くので、最初の描画から立っている。

**保存は、送るものがあるかどうかを自分の姿で言う。** 打ち込んだだけでは読者に届くものは何も変わらないのに、
画面は打つ前と同じ姿をしている。**送るものが無いあいだ保存は押せず、送るものができた瞬間に `accent` を
着る** (`Submit` の `saves`)。**判定は欄が覚えている読み込み時の値と突き合わせる** — 画面が同じ値をもう
1 か所に抱えると、2 つの持ち主が食い違う。**色だけでは言い切らない**: 面は見ている人にしか届かないので、
「未保存の変更があります」を `role="status"` で出す (`Unsaved`)。**立つのは保存の右で、ボタンに対して
縦中央**。右なのはその 1 つのボタンについての言葉だから。**保存と報せは 1 つの箱に入れて、その箱の中で
中央に揃える** — 報せの側に「中央へ」と書いても揃うのは行の中央で、保存の隣に背の高い欄が立つ行では
行の高さを決めるのは欄のほうなので、ボタンの中心から 13px ずれる (実測)。**揃える相手はボタンであって
行ではない**ので、2 つを組にして初めて揃う。**公開はこの条件に入らない** —
出るのは画面にあるものなので、打ち直していなくても公開はできる。

**画面の状態を言うものは浮かせない。** 「指し先が公開されていない slug」のような、操作の結果ではなく
画面がいまそうであるという報せは、消えると気づけないので画面の中に残す。

**打ったものを記法として読む欄は、名前の脇でそれを名乗る。** 名前の右に語だけのバッジを 1 つ置く
(`form.tsx` の `Accepts`)。**無印は「打った文字がそのまま値になる」を意味する**ので、読む欄には必ず
付ける — メモも題名も申請から運んだ箱も無印で、そこに書いた記号は記号のまま残る。**語は記法の名前
そのもの。** 2 つあって、サイトコンテンツの本文が `markdown`、研究の文が「リンクと改行」— 見出しも表も
弾かれる側を `markdown` と呼ぶと、その語が嘘になる。**箱の下に文で書かない** — 欄が縦に並ぶ画面では
同じ 1 文が欄の数だけ増えて、読むものではなく間隔になる。**押せない** — 許す記法は語で言い切れる短さで、
開く面を持たせるとバッジは読むものから押すものに変わる。

**書く欄の書体は 2 つで、分かれ目は記法が桁で意味を持つかどうか** (`form.tsx` の `TEXTAREA_LOOK`)。
表の縦棒が列に立ち、`\` が次の文字を読ませず、行末の空白 2 つが改行になる本文だけが**等幅**で、比例字だと
列が揃わず行末の空白も見えないので、書いたものを読み返せない。**等幅のほうが小さい** — 長い記事は送って
読むもので、14px の等幅は同じ文が 3 割早く折り返す。**それ以外は読む字のまま** (14px)。記法を読まない欄が
等幅を着ると、隣に置いた比べる相手と書体も大きさも違って見え、**同じ 1 文が別の文に見える** — 取り込みの
画面は下書きと申請と書き先の 3 つを並べるので、そこが揃わないと 3 つが 3 つに読めない。**受け取る記法とは
別に決める** — 研究の文は markdown を受けるが表を持てないので、読む字で書く。

**欄に添える説明は文で書く** (`form.tsx` の `hint`、`Fold` の `note`)。名詞句で止めると、欄の規則を
言っているのか打てる値を見せているのかが形から読めない — **例を見せるものだけが名詞句で立つ** (「例:
JGAD000001, JGAD000002」)。**順は「何を入れる欄か」から「どう書くか」へ** — 書き方を先に置くと、何の
規則なのかを知らないまま読むことになる。

### 編集画面の 2 ペイン

編集画面は左右 2 つのペインを持ち、どちらも同じものを持てる。**2 つは同じ幅で、動かせない** — 並ぶのは
フォームとそれが書くページで、どちらが主役でもないので選ぶべき幅が無い。掴んで動かせる境目は、開く
たびに幅を決めさせたうえで、次に開いた人に誰かの答えを渡す。片側だけにする入口は下書きの帯に立つ。
**どちらに何を出すかと、片側だけにするかは `sessionStorage` が持つ** — 行を 1 つも変えないものは
アドレスに載せない (「一覧」と同じ線)。**片側だけにする入口は丸い器で、語を添えて立つ**
(`Choice` の `pill`) — 選んでいるのは画面の並びであって値ではないので、下の欄と同じ角を持たせない。
**並びは左・両方・右**で、面そのものの並びと同じ (「両方」から始めると、いま見ている形を探すことになる)。

**ペインは箱で、タブはその箱の上端。**そのペインが何を持つかを選ぶもので、**フォームはタブを持たない**
(段が 2 つあると、「どこを見るか」と「どこを直すか」が同じ姿で並ぶ)。地の上に置いたタブは、左右どちらの
箱のものでもなくなる。フォームの箱は管理の他の画面と同じ白い箱で、**公開ページの箱は公開画面が着るのと
同じ帯と本文をそのまま着る** — 公開されたときの姿を見る場所なので、器が違えば見ているものも違う。
**中の帯は見出しではない** (`PageHead` の `level`) — 画面の名前は帯の上のバーが言っていて、識別子が
2 つ目の h1 として立つと、最初に渡される名前が `hum0588` になる。

**2 つの箱は窓の高さで、窓の上に貼り付く。** ページは普通にスクロールし、上のバーは流れて消える —
**残るのは画面いっぱいの 2 つの箱**で、書いている人がいちばん長く見ている形がそれ。**ページが上下に
残す余白はそのまま残す** — 窓いっぱいにすると、箱の上端に乗るタブがブラウザの枠にじかに着く。高さは
窓からその 2 つぶんを引いた分で、**測った値は使わない** — 測れるのは描いたあとなので、
バーが 2 行になった瞬間の答えだけが古い。**スクロールする箱は、その中の絶対配置の親でもある。** 箱が
切り落とせるのは自分が位置の親になっているものだけで、そうでないと欄の脇に下がるコメントの印はページの
長さぶん文書を伸ばし、**何も無い地を延々スクロールできる画面**になる。

## 寸法

**幅・縦の間隔・押せるものの大きさ・行間は、どれも数を選ぶ余地を残さない。** 選べるようにすると、
同じ関係が画面ごとに違う値で書かれ、揃っていない画面が 1 つずつ増えていく。

### 幅

`@theme` が 4 つ持っている。**画面がこれ以外の幅を書かない。**

| | 値 | 何に |
|---|---:|---|
| `content-max` | 1440px | ページの既定 |
| `content-narrow` | 1120px | 記事が主の画面 (`<Page width="reading">`) |
| `page-gutter` | 24px | 窓の端に届くものが、端に残す余白 |

**一覧は窓そのものを取る** (`<Page width="full">`)。研究一覧は v1 と同じ 11 列にカートを足した
12 列で、最小幅の合計が 1,917px ある。左の絞り込みパネルとカードの余白がさらに 376px 要るので、
**表が収まるのは 2,293px より広い窓だけ**になる。上限を名前付きで持つなら「横スクロールが止まる幅」
にするしかなく、それは実際に使われているどの窓よりも広い — 名前を付ける値が無いので、窓を渡して
足りない分は読者にスクロールしてもらう。**カートと ID の 2 列はその間も動かない** — 十数列が横に
流れたときに読者が最初に失うのは「どの行を読んでいるか」で、その 2 つがそれを言っている。
**データセット一覧も同じ 2 列を固定する。**

**`STUCK` が持つのは、どこに立つかであって幅ではない。** 幅を持つのは 1 列目だけで、それは 2 列目が
その終わりを `left` として読むため (`app/components/page.tsx`)。**2 列目の幅は一覧が `floor` で持つ** —
中身に任せると**ページを送るたびに幅が変わり、横スクロールの起点が動く**。研究 ID は `hum0358` の
7 文字で揃うが、**データセット ID は 10 文字 (`JGAD001067`) から 26 文字
(`hum0014.v2.jsnp.934ctrl.v1`) まであり**、任せていたときは 127.5 〜 210.7px に振れていた。いまは
研究一覧 104px / データセット一覧 128px。

**下限は最長ではなく分布で決める。** データセット ID は 989 件のうち **10 文字が 717 件 (72.5%)、
11 文字以下で 79%** で、26 文字は 1 件しかない。最長に合わせた 224px は**残る 4 分の 3 のページで 96px を
誰も使わない余白**にする — しかも固定列なので、その幅はどの画面でも表から引かれる。**代わりに、既に
区切られている場所でだけ折る**: `.` の後に `<wbr>` を置くので `hum0014.v2.` / `jsnp.934ctrl.v1` の 2 行に
なり、128px に収まる。**任意の位置で折らない** — 識別子が途中で切れると読み違える。**行の背は伸びない**:
一覧の行は他の列が既に 1〜6 行あり、ID の 2 行目はその中に収まる。

**折り返せないセルは上限を持たない。** 列の上限は 352px で、1 つの長い文が表を占めるのを止めている
(`page.tsx` の `CEILING`)。**`nowrap` のセルにそれを課すと、折る場所の無い識別子は次の行に落ちる代わりに
隣の列に乗る** — セルは中身を切らないので、記事の slug は 402px のまま 336px の枠から 66px はみ出して
いた。**上限は折り返せるセルにだけ置き、折れないほうは表の横スクロールに任せる。** 固定列だけは別で、
そこは幅が表から引かれるので `<wbr>` で折る。

**列の下限は測って決める。** 研究一覧の 100 行で「96px を超えて刈られるセルの数」を幅ごとに数えた
結果が下で、**解析手法はどの幅でも 0** — 文の列に見えて実際は平均 1.1〜1.3 行しかない。

| 幅 | 研究題目 | 解析手法 | データの種類 | 参加者 |
|---:|---:|---:|---:|---:|
| 160 | 37 | 0 | 19 | 23 |
| 224 | 12 | 0 | 6 | 12 |
| 288 | 4 | 0 | 2 | 9 |
| 352 | 1 | 0 | 1 | 7 |

既定の下限は 112px (`min-w-28`)。**文が入る列は 160px から始め、そこでもまだ刈られる 3 つだけを
上げる** — 研究題目 288、データの種類と参加者 224。**既定より狭いのは 3 つ** — 研究 ID は固定列なので
`STUCK` が 104px を持ち (下限は持たない)、公開日と更新日は日付 1 つぶんの 96px。どれも min-content が
既定を下回るので、既定のままでは誰も使わない余白になる。

**列がそれ以上狭くならないもう 1 つの理由は、上に立つ語。** この表の数はどれも値から出ていて、値より
名前のほうが長い列では、いちばん狭くなったときに折り返すのは帯だった — 日付の値は 96px だが
`Date published` は 124.4px あり、**英語版の研究一覧だけ帯が 36px から 56.8px になっていた**。
だから語の見出しは折り返さず (`page.tsx` の `Table`)、**下限は「値が要る幅」と「名前が要る幅」の
大きいほう**になる。**数をここに書き足して解決しない** — 名前は言語ごとに違うので (「公開日」42px に
対し `Date published` 100.4px)、長いほうに合わせた下限はもう一方の言語で 28px の使われない余白になる。

**帯が 1 行であることは、表が 1 つであることの一部。** 1 つの列の名前が折り返すと、他のすべての列の
名前が 1.5 倍の高さの箱の上端に付く。**幅を固定する列だけは語を持たない**ので (「押せるものの
大きさ」の操作のセル)、そこがはみ出すことはない。

**中で流れることは、箱自身が言う。** スクロールバーは場所を取らない overlay で、**読者が「常に表示」に
設定していなければ 0px しか取らない** (実測)。しかも表の箱は窓より高い (研究一覧で 2,215px) ので、
場所を取るバーだったとしても読者の見えるところには出ない。だから**まだ進める側の端を影で落とす** —
開いた瞬間から far 側が暗く、行き止まりに着くと消える。**表だけの話ではない** — 絞り込みパネルの値の
一覧も同じ影を使うので、`EDGE_SHADE` は 4 方向を持って `base.tsx` にある。**固定列を持つ表では、
手前側の端はその列自身の影になる** (`page.tsx` の `FROZEN_EDGE`)。止まっているあいだ手前側に影は出ない —
流れているものが無いのに境を引くと、読者はその線が何なのかを自分で説明することになる。

**far 側の影は、測る前から出ている。** どれだけ流れるかは描く時点では分からないが、**流れるかどうかは
server 側で分かることがある** (値の数が箱に入る数を超えているか)。そこを measure に任せると、**script の
無い読者にとって「まだ続く」を言う唯一のものが、script を要求するもの**になる。

**掴むところは表の上にも要る。** 影は「まだ流れる」としか言えず、どこまで来たかを言わないし掴めない。
だから**表の上に本物のスクロールバーを 1 本立てる** — 描いた偽物ではなく表の幅を中に持つ overflow の
帯なので、ブラウザが下のバーと同じ姿で描く。**溢れているあいだだけ出し、`aria-hidden` と
`tabIndex={-1}` で読み上げと Tab から外す** (同じスクロールが下の箱から届く)。**2 つの箱は
`scrollLeft` を写す前に値が同じかを見る** — 見ないと、片方を動かしたイベントがもう片方を動かし、
それが戻ってきて止まらない。

**ただし掴む手が渡るのは、バーを常に表示にしている読者だけ。** 上の 0px がこの帯にもそのまま効いて、
overlay では 1px の箱に何も描かれない。**影は誰にでも「まだ流れる」を言えるが、どこまで来たかと掴む
手は一方にしか渡らない** — この非対称は解けないので、影のほうを外さない。

**管理画面は上限を持たない。** 区画が `<PageWidthDefault width="full">` で一度決めるので、画面が
幅を書くことはここでも無い (`app/app.spacing.test.ts` が見張る)。上限を外すのは、管理の表に
どの画面でも正しい 1 つの数が無いため — 編集画面は同じものを 2 言語ぶん横に並べる。

**どれも `<main>` の外寸で、本文が流れる幅ではない。** 内側に `page-gutter` が 2 つとカードの
余白が 2 つ入るので、**文が実際に置かれるのは 96px 狭い** (1120 なら 1024px = 日本語 64 文字/行)。

**狭いほうは文だけの幅ではない。** 記事は表を持っていて (22 件が 147 枚、段落の 1.5 倍の幅)、
1 行の文字数だけで決めると 3 分の 1 が器の中で横スクロールする。1120 はその収まり (63% → 80%) と
行の長さが釣り合う点になる。

**`page-gutter` は窓の端に届くものすべてが使う** — ヘッダのバー、告知、ページ、サイトマップ。
4 つは画面の左を縦に並ぶので、ここに 2 つ目の値があると、まっすぐであるべき線に段差として出る。

**サイト自身のもの — ヘッダのバーと告知 — は幅の上限にだけ従わない。** どちらも窓いっぱいに広がる
([public-pages.md](public-pages.md) の「ヘッダとフッタ」)。左右の余白は他と同じ `page-gutter`。

**どちらの言語かは語が言う。** 箱ごとに `ja` / `en` を値の左か上に立てる (`fields.tsx` の
`SlotEditor`、`components/upstream.tsx`)。**色の濃淡で分けない** — 薄いほうが英語だと言うものが画面に
無く、読み取り専用の面では 1 つの文とその控えめな続きに読める。語が立っていれば、どちらも字の色でよい。

**1 つの値の 2 つの言語は上下に積む** (`fields.tsx` の `PairField`)。横に並べると、どちらも 1 つの文を
読む幅の半分しか取れず、**同じことを 2 回書いたものではなく表の 2 列**に見える。編集画面のペインは
窓の半分なので、半分の半分は日本語で 20 字ほどにしかならない。

### 縦の間隔

**`Stack` が 3 つ持っている。`tight` は 8px (ラベルと値)、`normal` は 16px (箱の中の要素どうし)、
`block` は 32px (節と節)。** 画面は `mt-*` / `mb-*` / `my-*` / `space-y-*` を書かない —
`app/app.spacing.test.ts` が公開画面を読んで落とす。

部品の中で見出しと中身のような固定の関係に margin を使うのはよい。**画面が margin を持つと、同じ
関係が画面ごとに違う値になる**のが問題で、実際そうなっていた。

**3 つの数は画面に見える距離のことで、書いた padding のことではない。** 隣り合う部品が自分の余白を
持っていれば足し算になる — 絞り込み pane の 2 群を 1 ブロック離すのに書くのは 24px で、最初の facet が
上に持つ 8px と合わせて 32px になる。**32 と書いて 40px になっていた**のがこれを踏んだ形。**測るのは
文字から文字まで**で、部品の矩形どうしではない — 余白が部品の内と外のどちらに付いているかで矩形は動くが、
読者が見ている距離は動かない。

**カードの中のいちばん外側の `Stack` は `block`。** h1 と、その下に続くものの距離が画面によらず 32px に
なる。`normal` を書くと同じ関係が 16px になり、画面を渡り歩く人には理由の無い差として残る
(`app/app.spacing.test.ts` が管理画面を読んで落とす)。**h1 の下に節の名前が来ない画面だけが `normal`** —
絞り込み pane を持つ一覧は下に来るのが pane の見出しで、見出しが 2 つ続く形に節と節の距離を空けると
h1 だけが浮いて見える。`common/` の箱は節を 1 つも持たず、下に来るのが upload の枠そのもの — 枠は
自分の余白を持つので、32px を空けると字から字までは 48px になる。アラートの画面も節を持たず、下に来る
のは 1 件目のアラートで、それが開くのは名前ではなく自分の状態のチップ。公開側の一覧も同じ理由で
`normal` になっている。**編集画面のバーだけが `tight`** —
あの箱が並べるのは節ではなく 2 段で、節と節の距離を空けると 1 本の帯が 2 つに割れて見える。

**節の名前と、その中身は `normal`。** 8px はラベルと値の距離で、節の名前はラベルではない — 節どうしが
32px で隔たっているところに名前が 8px で乗ると、画面に残る律動が 1 つになり、名前は節の最初の行に
くっついて読める。

**画面が何をするところかを言う 1 文は、見出しが持つ** (`base.tsx` の `Heading` の `note`)。h1 の 8px 下に
立ち、次のパートとは 32px 空く。**画面が自分で `<p>` として並べると、その距離は画面が立っている `Stack`
のものになる** — 同じ 1 文が、ある画面では h1 の 16px 下に、別の画面では 32px 下に落ちて、h1 にも次の節にも
属さない位置に浮く。

**節の 1 文も同じで、`Section` の `note` が持つ。** 名前の 8px 下に立ち、節の中身とは 16px 空く —
名前に属しているものなので、名前と同じ塊の中にいる。**持つのは名前で中身を言えない節だけ**という線は
「管理画面の枠」に書いたとおりで、どの節にも付けると読む価値のない文が並んで節の名前まで読まれなくなる。

**言語どうしは 8px、欄どうしは 32px** (`fields.tsx` の `PairField` と `Section`)。2 つの言語は 1 つの値の
2 つの姿なので、ラベルと値の距離で足りる。**欄が 3 行深くなったぶん、欄どうしは節と節の距離を取る** —
16px だと欄の中と欄の間が同じ距離になり、1 つの欄がどこで終わるかを読む手がかりが無くなる。

### 押せるものの大きさ

**アイコンだけの操作は 36px 四方** (`@theme` の `--spacing-tap`、クラスは `size-tap`)。`IconButton` /
`RoundLink` / `LanguagePills` / `Menu` がこれを持っている。文字を持つボタンは `Button` の大きさが
決める (`xs` でも 24px を下回らない)。**語を持つものに 36px を強制しない。**

**36px の的が、それより低い箱の中に立つこともある。** 答えの箱 (`Answered`) の×がそれで、箱が抱えるのは
印 24px と文 1 行 22.4px なのに、的をそのまま置くと箱が 54px になる。**的は縮めず、箱の中での背丈だけを
印に合わせる** — 24px の枠に入れて中央に置き、はみ出させる。押せる範囲は 36px のまま、箱は 42px に収まる。
**負の margin では書かない**: 管理画面は margin を書かず間隔は `Stack` が持つ規則で、
`app.spacing.test.ts` が見張っている。

**文の行の中に立つ操作は、その行より背を低くする** (`Button` の `size="row"`、24px)。表のセルと、値の
後ろに立つ「外す」がこれで、隣にあるのは**操作が作用する対象**になる。既定の `sm` は 36.4px あり、
22.4px の行に対して 1.6 倍 — **対象より操作のほうが大きい**うえ、セルの余白と合わせて行が 34.4px から
49.4px に伸びる。これは「押せるもの」の**取り消せないものの入口は小さいほうを取る**と同じことを、
大きさの側から言っている。**確かめる面の中のボタンは動かない** — あれは面そのものの主語で、隣に対象が
立っていない。

**その操作のセルは余白を持たない** (`page.tsx` の `Td` の `holds`)。`mark` は印 1 つで幅も 60px に
決まり、`control` は語を持つので幅は中身なり — **共通なのは上下の余白を持たないこと**で、持たせると
24px の操作に 12px が足されて行がまた伸びる。

**ただし 1 つの行に並ぶものは、行の高さを 1 つの値で決める。** ヘッダのバーがそれで、36px の言語ピル・
カート・アカウントの隣にナビの項目が立つ。項目を自分の行箱 (22.4px に上下 8px で 38.4px) のまま置くと
**そこだけが行より背高になり、ナビを描かない管理画面ではバーが 2.4px 浅くなる** — ロゴもその下の名前も
右端の控えも 1.2px 動き、1 つのヘッダが 2 つの高さを持つ。項目を `h-tap` に乗せて揃える。**押せる範囲は
36px のままなので、これは膨らませる話ではなく、揃える話。**

**消えるものが並ぶ行にも同じことが要る。** 件数とページ送りの行 (`page.tsx` の `Paging`) は、1 ページに
収まる一覧ではページ送りを描かないので、36px から件数 1 行ぶんの 22.4px に落ちていた — 絞り込んだ結果が
1 ページに収まった瞬間に、表とその下の全部が上へ動く。**行の高さは、その行が取りうるいちばん高い姿で
一度決める** — 画面ごとではなく、同じ画面の状態ごとに変わるほうが目につく。

**余白は押せるものの内側に置く。** 同じ距離を外に置いても画面は同じに見えるが、押せる範囲はその
ぶん小さいまま残る — `Fold` の 8px は `<details>` にあり、**押せるのは 22.4px の語の行だけ**だった
(上の 24px を割っている)。`<summary>` へ移して 38.4px になり、画面は 1px も動いていない。**部品の
矩形を見ても分からない** — 内と外のどちらに付いていても外寸は同じなので、押せる範囲そのものを測る。

**選択肢を開くもの (`Chooser`) は、ボタンより 1 段浅く、caret の側だけ 1 段狭い** — 上下 4px、
左 12px、右 8px で 32.4px になる。同じ行にページ番号の 36px 四方が並んでいて、**そこと同じ高さの
ものがもう 1 つ立つと、行の中に同じ重さの塊が 2 つできる**。並び替えと表示件数は「いま何で並んでいるか」
を名乗るもので、行の主語ではない。**右だけ狭いのは、この操作が caret で終わるため** — 字は自分の
左右に余白を持たないが caret は持っているので、両側を同じにすると右が広く見える。

**アイコンだけの操作が語を持つものに溶接されているときは、器の高さに合わせて描き、押せる範囲は
36px を名乗る。** 高さを揃えないと 2 つで 1 つの形に見えず、36px を強制すると行の中でその対だけが
背高になる。伸ばすのは疑似要素で、**器から引き算しない** — `CHOOSER_SIDE` の疑似要素は `h-tap` を
持って器の中心に立つので、器が浅くなっても押せる範囲は 36px のまま動かない。検索の窓の丸
(`SEARCH_DISC`) も同じく疑似要素で伸ばすが、あちらは丸の大きさが窓の 3 段それぞれに決まっているので、
伸ばす量もそこから決まる。

**36px が入れ物の大きさも決める。** 検索の窓は中に丸いボタンを持つので、**窓の深さの下限は 38.4px** に
なる (押せる範囲と、それを収めるだけの余白)。`SearchBox` の 3 段のうちいちばん浅い `compact` がその値で、
それ以上詰めることは「押せるものは 36px」を破ることと同じになる。

**ただし描く大きさと押せる大きさは同じではない。** 窓の 3 段は 48 / 44 / 38.4px あり、丸を 1 つの値に
固定すると深いほうで 75%・浅いほうで 94% を占める。94% では窓の上下に 1.2px しか残らず、**窓が丸の
縁飾りになる**ので、`compact` の丸は 28px に落として 5.2px 残す。**押せる範囲は 36px のまま**で、
足りない 8px は疑似要素が外へ伸ばす (`SEARCH_DISC`)。**フォーカスの輪郭は丸のほうに付く** — 押せる
範囲に付けると、輪郭が丸から 5px 離れたところに立って別のものの縁に見える。

**1 行しか入らない行は、文字ではなく印が高さを決める。** 表の 1 行は 34.4px (`py-1.5` + 22.4px の行)
で、36px の印のほうが背が高い。**それでも印は自分の余白を持たない** — 持たせると行が 48px に伸び、
**印だけが文字より沈む**。`Td narrow` は `py-0`、控えの印 (`preview` の `Marks`) は負の margin で行に
収まる。表の見出しも同じで、**語のセルだけが余白を持ち、操作のセルは持たない**
(`Table` が `typeof header === "string"` で分ける)。**2 行以上のセルを持つ行では文字のほうが決める**ので、
セルの余白はその種の行にだけ効く。

**行の高さを決めない印は、1 行ぶんの高さを取って自分をその中心に置く** (`form.tsx` の `MARK`)。
checkbox は 13px しかないので、素で置くと**そこに無い散文の baseline に乗り**、隣の欄の語より行で 1.5px・
帯で 1.7px 上に出る。**1 行ぶん (`1lh`) を数字ではなく行の高さそのもので取る** — 合わせる相手は隣の
セルが使っている高さで、数字を書くとそちらが動いたときに嘘になる。**バッジも同じ箱に入る**
(`base.tsx` の `Badge`) — 枠と余白を持つぶん 20px あるが、隣の語の行 22.4px には足りず、上端で揃えると
中心が 1.2px 上に出る。**印の側で閉じる** — セルごとに直すと、同じ 2px を表の数だけ踏み直す。

**セルの縦の揃えを `middle` に倒しても、この種のずれは直らない。** `vertical-align` が動かすのは行箱で、
バッジの中の字はその中で別に決まる — 取り込み状況の表で試すと 1.0px が 1.3px に増えた。**倒してよいのは
どの行も 1 行に収まる表だけ**という制限も別にあるので、揃わない原因が中身の背丈なら中身の側を直す。

**印の列は幅も持つ。** 印が 36px で左右の余白が 12px ずつなら列の幅は 1 つに決まるが、表が箱より
狭いと余った幅は**幅を名乗らない列すべてに配られる**ので、同じ印が一覧ごとに違う幅で出る。実際そうなって
いた (研究一覧 60px、データセット一覧 74px)。**その幅は 1 か所が持つ** (`page.tsx` の `MARK_COLUMN`)。

**固定はその幅を知らない。** 固定する先頭が印の列とは限らず、admin の研究一覧は名前の列を 1 つだけ
固定する。幅を固定の側に書くと、名前が印の 60px に押し込まれる。**2 列目を固定できるのは 1 列目が
印のときだけ** — 2 列目の `left` はその 60px を書き出したもので、この 1 つしか知らない。**幅のために
列を固定しない** — 固定は「横に流れたときにどの行を読んでいるか」を残すための道具 (「幅」)。

### 行間

**文字の大きさが行間を決める。`leading-*` を書かない。** `@theme` が `--text-*--line-height` を
持っていて、本文 (`text-base`) は 1.75、一覧や表の文字 (`text-sm` / `text-xs`) は 1.6 / 1.5、
見出しはそれより詰まる。日本語は字面が正方形で行の切れ目が見つけにくいので本文は緩め、密度が要る
ところは詰める、という 2 つの要求をここで分けている。

**`text-lg` は見出しの側にいる。** 節の名前と入り口 2 つが取る大きさで、**本文はこの大きさで書かれない**
ので、行間は本文の 1.6 ではなく見出しの 1.3 を持つ。ここが本文側に居ると、**見出しの脇の縦棒がその
行箱ぶんの長さになる** — 18px の語に 28.8px の棒が立ち、印ではなく帯に見える。棒の長さは行間が決める、
というのは絞り込みの見出し (上の「寸法」) と同じ話。

### 見出しの段

**部品が名乗る見出しと、記事の見出しは同じ段を降りる。** 画面の一部を名指す `Section` の h2 と、記事の
`##` は同じ種類のものなので、大きさと棒は 1 通りしかない。**記事の本文は最上段を持たない** —
`#` で書かれた本文は全体が 1 段下がるので、ページの h1 は題目だけになる。

| | 大きさ | weight | 色 | 棒 |
|---|---:|---:|---|---|
| ページの題目 (`Heading`) | 30 | 700 | brand | カードの縁 (`-ml-6`) |
| 画面の節の名前 (`Section`) | 18 | 500 | ink | 中身の開始地点 |
| 狭い器の見出し (`PaneHeading`) | 14 | 700 | brand | 左の棒 |
| 記事の節の名前 (`.markdown h2`) | 18 | 600 | ink | 中身の開始地点 |
| その下 (`.markdown h3`) | 16 | 600 | ink | 無し |
| さらに下 (`.markdown h4` 以降) | 14 | 600 | ink | 無し |
| 本文 | 14 | 400 | ink | — |

**`PaneHeading` は狭い器の中だけのもの。** 250px の絞り込み pane と、本文の中に立つ小さな箱がそれで、
器の字が `text-sm` だから見出しもその大きさに落ちる — 1 段上げると本文の行送り (1.75) を連れてきて、
言うことの割に背の高い塊になる。何が見出しかを言うのは大きさではなく棒と色のほう。**本文の節には
使わない** — 画面の節の名前は `Section` の 1 つで、そこに 14px の太字の青が混ざると、同じ段の 2 つの
見出しが別の種類のものに見える。

**記事の見出しは色を持たない。**記事は見出しでできていて段落はリンクで埋まっているので、青い行は
見出しより先にリンクとして読まれる — 大きさも下線の不在も、色を見たあとにしか確かめられない。
**色をリンクに預けると、記事の中で色が意味するものは「リンクであること」だけになる。**見出し自身が
リンクであるときもそのままで、そこだけが青く下線を持つ。

**記事では棒が「見出しである」を言う。** ページの上でリンクが決して持たない唯一の印がこれなので、
h3 から下が棒を落としても段は 1 つも失われない。**記事の段は weight を変えない** — 色が抜けた以上、
下の段落と分けるものは weight しか無く、それは節の段でも同じになる。

**節の名前は、画面の側も色を持たない。** 管理画面は欄とボタンでできた面なので、目印のつもりの青が
いちばん紛れる場所がそこになる — 押せるものと同じ色の見出しは、まず押せるものとして読まれる。**色を
持つのはページの題目だけ**で、節から下は棒と weight が段を言う。**同じ 18px と同じ棒を取る**ので、記事と
画面を行き来する読者が出会う h2 は 1 つの大きさのままになる。この 2 つが割れていないことは
`app/app.spacing.test.ts` が見張る。

**棒の立つ場所が 2 段を分ける。** 題目の棒はカードの縁へ張り出して語を中身の左端に戻す。**節の棒は
中身の開始地点に立ち、語がそのぶん右へ出る** (`PaneHeading` の 2 通りと同じ幾何、`docs` の「壊れるもの」)。
カードの縁はページ全体を名指すもののための線なので、節がそこに並ぶと題目と同じ格に見える。

### 角丸

**`rounded` (4px) と `rounded-full` が、どれが取ってもよい 2 つ。** 大きさを選べる `rounded-sm` /
`-xl` などは使わない (`app/app.spacing.test.ts` が見張る)。方向を指定する `rounded-t` / `rounded-b` /
`rounded-l-full` は、帯とその下の箱・溶接した 2 つのコントロールが 1 つのものに見えるために要る。

**`rounded-full` は「一覧の上に立つコントロール」の形でもある** (「色」の `LISTING_CONTROL`)。同じ行に
4px と丸が混じると、押せるものが 2 系統あるように読める — 実際そうなっていて、コピー / TSV が丸、
並び替えと表示件数とページ送りが 4px だった。

**ただし丸を取ってよいのは、中身が箱を埋めているものだけ。** ページ送りの番号は `rounded` のままにする —
**1 桁の数字は 7.8px で、箱は 36px** ある。中身の 4.6 倍の箱が 9 個並ぶところで角を落とすと、縦の辺が
消えて行が枡の帯ではなく数珠になり、**数え上げる手がかりが無くなる**。コピーや「更新日」の箱は自分の語で
埋まっているので、丸い端が語の終わりとして読める。**地と枠は `LISTING_CONTROL` のまま**で、角だけが
違う。

**`rounded-lg` (8px) は 3 つ目で、4px の角が消えてしまうものだけが取る。** 消える理由は 3 つある —
**面が大きすぎる**か (トップの入り口 2 つ、`BigAction`)、**縁を持たず、隣の面との差が小さい**か
(一覧のタブ)、**ページの上に浮いている**か (管理画面の行き先のカード、メニューが開くパネル)。2 つ目は塗りだけが形を描くので、
1.05:1 の差で 4px の弧を引いても 1〜2 ピクセルしか出ず、角が四角く見える。**線を 1 本引けば 4px でも
読めるのは、線が差を作っているから。** 3 つ目は逆で、影が輪郭を太らせるぶん 4px の角が影に埋もれる —
**紙の上に置かれた 1 枚として読ませるものだけ**で、ページの中に嵌っている箱には当てはまらない。

**画面が書くことは test が拒む**ので、要るなら部品の側に足す。角を指定する形 (`rounded-tr-lg` 等) も
同じ扱いで、`app/app.spacing.test.ts` は角の指定ごと見ている。

**線を持つ箱に帯を敷くときは、帯を丸めず箱の側で切る。** 箱の内側の輪郭は、外の半径から線の幅を引いた
半径で描かれる — 4px の箱を 1px の線で囲めば 3px になる。帯に箱と同じ `rounded-t` を渡すと 1px だけ
丸すぎて、**線と帯のあいだに地が三日月に覗く**。箱が `overflow-hidden` を持てば半径は 1 つで済み、
食い違いようがない。`app/app.spacing.test.ts` の「角丸」が見張る。

## 壊れるもの

- **知らせは、読み上げる器と描く箱を分ける。** `Toast` の `announce` が声を持ち、箱は
  `children` として来ては消える。**live region は中身が変わったときに読まれる**ので、メッセージを
  抱えたまま現れた器は何も言わないことがある。かといって箱の側も `live` にすると、同じ文が 2 度読まれる。
  **同時に立つのは 1 つだけ** — 2 つ並べば、読者はどちらを先に読むかを決めることから始めることになる
- **サイトの外へ出るリンクは、印と語を両方持つ。** `page.tsx` の `ExternalLink` を通す。印だけでは
  画面を見ていない読者に伝わらず、黙って新しいタブが開くと**戻る手段を探すことになる**。ボタンの形の
  ものは `newTabLabel` で語を受け取る (`base.tsx` は文言を持たない層なので、語は呼び出し側から来る)。
  **`external` は「外へ出る」ではない** — client-side navigation で答えられない宛先のことで、TSV の
  ダウンロードと IdP へのリダイレクトも `external` だが、どちらも同じタブに留まるので語は要らない。
  `app/app.navigation.test.ts` が見張る
- **列の下限を `className` に書かない。** `Td` の `floor` が持つ。既定の `min-w-28` の隣にもう 1 つ
  `min-w-*` を書くと、同じ重みの規則が 2 つ並んで Tailwind が最後に吐いたほうが勝つ — **広げるほうは
  たまたま効き、狭めるほうは黙って効かない。** `app/app.spacing.test.ts` の「列の下限」が見張る
- **一覧のセルを中でスクロールさせない。** 長い文は `Excerpt` が刈って、続きは押して開く。読者が
  すでに使っているスクロールの中にもう 1 本バーを置くと、研究一覧の 1 ページで 14 個同時に出る
- **表を `border-collapse` に戻さない。** collapse された表はセルの箱を表自身の背景の一部として描くので、
  セルに付けた `box-shadow` が 1 ピクセルも出ない。**computed style には出る**ので、実際の色を測るまで
  気づかない。固定列の縁はその影で描いている。罫線は `Td` の `border-b` しか無いため、
  `border-separate border-spacing-0` でも引かれる線は変わらない
- **値を区切る罫線は、対と対のあいだにだけ引く。** 段の端に来た 1 本は何も分けない — 枠付きの器では
  **その器自身の縁の数 px 上に浮き**、流し込んだ列の端では均衡がたまたま落ちたところに引かれる。
  **どちらの端も CSS では名指せない** (`:first-child` / `:last-child` は原稿の端であって列の端ではなく、
  列がどの対で始まるかは版が決まってからでないと分からない)。**だから全部に引いてから、端に来たものを
  器の外へ出す** — 各対を罫線 1 本ぶん上へずらすと、中の線は位置が変わらないまま、列の先頭の線だけが
  -1px に出て `Pairs` の clip に入る。**ずらすのは `top` で、margin ではない** — 列の頭の margin は
  段組みが落とすので、いちばん動かしたい 1 本が動かない
- **その罫線は `Pairs` が持ち、`KeyValue` は持たない。** 器の中に対が 1 つしか無いなら分けるものが無い —
  リリース情報は 2 つを横に並べていて、そこを分けているのは列のあいだの空き
- **語彙値のラベルを手で描かない。** `TermLabel` が描く。製品を指す値は「作った会社」を別に持っていて
  (`vocabulary_term.maker`、[data-model.md](data-model.md))、会社名だけ色を変えて 1 段空ける。
  **色が働くのは本文の中だけ** — 絞り込みパネルでは値の全体がリンクなので、会社名を何色にしても
  リンクとの差は 1.2:1 までしか開かない (本文に対する brand は 2.4:1)。そこは空きが分ける
- **切り詰めた箱の出口を手で書かない。** 「他 n 件」は `Clamped` が持つ。別の画面へ渡すのが `MoreLink`、
  その場で残りを開くのが `Clamped` で、**2 つは同じ姿をしている**。出口を呼び出し側に任せていたときは、
  研究一覧の 1 つの列が brand の 12px に矢印付き、4 列離れた列が灰色の 14px に印無しになり、
  どちらが押せるのかが読者に分からなかった。**その場で開くものは、開いているあいだ chevron を返して
  「戻す」を言う** — 開くものと閉じるものを別々に描くと、対であることが読めない
- **`Fold` の `open` は「開いている状態」ではなく「いま開いている理由があるか」。** 理由が消えても畳ま
  れない (`foldShown`)。渡した値をそのまま `<details>` に着けると、**facet の最後の条件を外した瞬間に、
  読んでいた節が読者の下で畳まれる**
- **`SectionTabs` の中でブラウザの検証 (`required` 等) を使わない。** 隠れた節の中の必須項目はフォーカス
  できないので、保存を押しても何も起こらず理由も出ない。検証は server 側で行う ([editing.md](editing.md))
- **隠れた節の中へアンカーで飛ばない。** `TabPanel` は `hidden` で隠すので、その中の要素は
  `<a href="#…">` の行き先として存在しない — 押しても何も起こらず、上の検証の項と同じ根になる。
  **先にタブを切り替え、描き直されてから運ぶ。** 焦点を乗せる相手も選ぶ必要がある — 節の中で最初に
  現れる入力が、注釈の層の `type="hidden"` か閉じた `<details>` の中にあることがあり、素朴に取ると
  焦点の乗らないものを掴む。編集画面の帯が「その項目へ」と言うのはこの経路になる
- **class 名を実行時に合成しない。** 見た目の表は完全なクラス文字列を値として持つ (`BUTTON_VARIANT` など)。
  断片を繋ぐと Tailwind がクラスを見つけられない
- **タブの斜辺の帯を、タブの高さと別々に変えない。** 斜辺は帯を右下を軸にせん断して作るので、帯の上端は
  `tan(角度) × 高さ` だけ右へ動く。**帯がそれより狭いと上端がタブの左辺に届かず**、角丸の脇にタブ本体の
  四角い角が出て、隣のタブとのあいだにページの地が三角に覗く。**角丸のぶんも要る** — 弧は角から半径だけ
  離れたところから始まるので、`帯の幅 − せん断量 ≥ 角丸` を満たさないと丸みの手前に四角い辺が残る。
  `app/app.spacing.test.ts` が `base.tsx` と `app.css` から 4 つの値を読んで見張る
- **フォーカスの輪郭を消さない。** `app.css` が `:focus-visible` に置いている。キーボードだけで操作する
  人にとって、いまどこに居るかを示すものが他に無い。**入力できるものだけが位置を変える** — 枠や塗りの
  縁から 2px 離すと線が 2 本並び、行の高さが小数なので (`text-sm` は 22.4px) 2 本が別々の物理ピクセルに
  落ちて滲む。`CONTROL` と `SearchBox` が `-outline-offset-1` を持ち、輪郭を自分の縁に重ねる
- **アイコンだけのボタンには名前を付ける** (`IconButton` は必須にしてある)。アイコンは `aria-hidden` なので、
  名前が無いとその操作は「ボタン」としか読み上げられない
- **一覧の件数を画面が書かない。** `page.tsx` の `Paging` が「範囲 / 総数」とページ送りを 1 つの器で
  描く。**近くに置く約束ではなく、1 か所でしか書けない形にしてある** — 各画面が書いていた間、管理画面の
  5 つの一覧が 5 通りの出し方をしていて、2 つは何も出さず、1 つは語彙全体の語数を出しながら表には検索の
  結果が並んでいた。総数だけを出してよいのはページに切られないもの (カート) だけで、**そこには
  「何ページ目か」という問いが無い**。`app/app.spacing.test.ts` が、件数とページ送りを書くファイルを
  数えて見張る
- **操作しているあいだ、ボタンの名前を書き換えない。** 「保存」が「保存中」になると、押したものが
  画面から消えて別のものが現れたように読める。**進み具合はボタンの隣の `role="status"` が言う** —
  そこは live region なので、変わったことが読み上げられる。ボタンは `disabled` になるだけで名前を保つ
- **1 つの form に確認を 2 つ置くなら、意図は隠しフィールドではなくボタンに載せる** (`Confirm` の
  `intent`)。隠しフィールドはどのボタンで送っても一緒に飛ぶので、**2 つの確認が同時に開いていると
  送られる意図が 2 つになり、先に書いてあるほうが勝つ** — 削除を押したのに非公開になる
- **帯の上でページの色を使わない。** `ink-muted` は帯の上で 1.2:1、`brand` の文字も 1.2〜2.6:1 にしかならず、
  フォーカスの輪郭 (`brand`) に至っては見えない。帯に乗る部品は白で描く形を持っている
  (`Badge onBand` / `Button onBand`)。**ボタンは面が裏返る** — 塗りが白に、枠が白い縁になる。
  白は帯の暗い側に対して 15.97:1 で、ページの色でいちばん強い `accent` の 3.10:1 より桁違いに離れる
- **入力欄と、入力欄の隣に置く小さなボタンを手で書かない。** 枠は 3:1 が要るので `line` ではなく
  `line-strong`、その組み合わせは `form.tsx` の `CONTROL` が持っている。**1 語違えても test は通る**ので、
  値を写すのではなく参照する。検索の窓だけは形も規則も違い (「色」の枠を持たない例外)、`search.tsx` の
  `SearchBox` が 1 つだけ持っている
- **一覧の上に立つコントロールの姿を手で書かない。** `LISTING_CONTROL` が持っている。**同じ行に地が
  3 通り・枠の灰色が 2 通り・角が 2 通りあったのがこれで消えた** — 選ぶものが入力欄の灰色を着ていて、
  ページ送りの箱の枠が 2.09:1 だった
- **一段下の見出しの棒を、その下の線と一緒に動かさない。** `PaneHeading` の棒は 2 通りの立ち方を持つ
  — `edge` はカードの余白へ張り出して h1 の棒と同じ縦線に乗り、`start` は名指すものの開始地点に立つ。
  **線はどちらでも pane を張る**もので、張り出しを行のほうに書くと線まで一緒に出て、pane が下の全部から
  左にはみ出して見える。**棒と語のあいだは棒の立ち方が決める** — 張り出したほうは語を中身の縁に戻すのに
  20px 要り、開始地点に立つほうは棒を語に結ぶ 10px だけでよい
- **一段下の見出しを、pane の本文より大きい文字で書かない。** `PaneHeading` は `text-sm`。一段上の
  `text-base` は行間が本文のもの (1.75 = 16px の語に 28px の行箱) なので、**言うことの量に対して
  ブロックが 1.5 倍の高さになる**。下の語と見分けるのは棒と色の仕事で、大きさの仕事ではない
- **pane の中の群の名前は `PANE_LABEL` から取る。** `PaneHeading` が pane 自身を名指すのに対し、これは
  その中の 1 つの列を名指すもの — 効いている条件と、facet の箱それぞれ。**手で書いた 2 つは既にずれて
  いた**: 色も大きさも weight も同じで、片方だけが日本語には何も起こさない `uppercase` と字送り 0.3px を
  持っていた。誰も選んでいない差が英語版にだけ出ていて、群が 1 つ増えるたびに 3 通り目が生まれる
- **いま何が選ばれているかを名乗るコントロールは `Chooser` から作る。** 一覧の並び替えと 1 ページの
  件数がこれで、**選べる値を全部並べる形ではない** — 中身は `Menu` なので閉じ方の 3 通りが揃い、
  項目はリンクなので選択はアドレスのまま残る。**溶接する 2 つ目は `CHOOSER_SIDE`** (向きの切り替え)。
  枠は外側の箱が 1 つ持つ — 半分ずつに枠を持たせると、あいだに 2px の線が出る。**語は枠の外**に置く:
  中に入れると、押せない語が押せる箱の中に入る
- **文の頭に置くアイコンを手で上げ下げしない。** `LineIcon` が行の高さの箱に入れて中央に置く。
  `mt-0.5` や `mt-1` で合わせると、文字の大きさが変わった瞬間にずれる
- **識別子の頭のアイコンは、その識別子が指すものだけで決める。** 研究は `book`、データセットは
  `database`。**同じ ID が一覧にも詳細の表にも関連論文の表にも出る**ので、置く場所ごとに選ぶと
  同じものが 2 通りの顔を持つ。字の隣に置くときは `mr-1 text-ink-muted` — 識別子そのものは
  リンクの色を持つので、アイコンまで brand にすると行の中で 2 つのものが同じ強さで光る
- **リンクで作ったコントロールには文字色を持たせる。** `app.css` の `a` は既定で `visited` を紫にする —
  読み物のリンクにはそれでよいが、ファセットの値やチップは押すたびに紫のまだらになる。`text-brand` を
  1 つ付ければ打ち消せる (utilities は base より後のレイヤ)
- **状態で名前を変えない。** `aria-pressed` を持つ操作の名前は固定する。「カートから外す」+「オン」は
  逆のことを 2 つ言っている。3 つ目の状態がある操作は `mixed` を使う
- **畳んで開くパネルは `Menu` から作る。** 開いたものは 3 通りで閉じる必要がある — Escape、外を押すこと、
  中の何かを選ぶこと。`<details>` が自前で持つのは自分の印をもう一度押すことだけで、それしか無い
  パネルは読者が別のことを始めた後も画面の上に居座る。**client 遷移はページを読み込み直さない**ので、
  行き先を選んで閉じることも自動では起こらない
- **`Fold` の `summary` の中に、開閉ではない操作を置かない。** `<details>` は summary の中で起きた
  クリックで開閉するので、そこに並べたボタンは押すたびに畳んだり開いたりするだけになる。**部品は
  script を持たないので伝播を止める先が無い。** 畳んだ行に操作を添えるなら `Fold` の外へ出して横に
  並べる — カタログの 82 行の並び替えと、データセットの experiment の移動と削除がそれで、
  **畳んだまま押せることが要る**ので中に入れる選択肢が最初から無い
- **ページ送りは `PageLinks` から作る。** どの番号を出すかは見た目ではなく、**どのページからどのページへ
  何回で届くか**を決めている ([public-pages.md](public-pages.md) の「ページ送り」)。画面が前後だけの
  リンクを手で書くと、その一覧だけが端から順に辿るしか無いものになる — お知らせの一覧が実際にそうで、
  34 ページを「過去のニュース」1 本で送っていた
- **大きさの違う文字を横に並べるところで `items-baseline` を使わない。** ベースラインが揃うぶん小さい方の
  中心が下に出る — `Heading` の 30px の題目と 16px の識別子で 5px、題目と右の操作で 2.8px ある。中心で
  揃えれば 0.5px に収まる。同じ大きさどうしなら
  差は出ないので、これは大小が混ざっている行だけの話になる。**複数行の値に件数や印を添えるところは別**で、
  そこは 1 行目に揃うのが正しい (絞り込みパネルの値と件数、`preview` の印)
- **1 件も無い一覧を、表ごと別のものに差し替えない。** `Table` の `whenEmpty` が、行のあった場所に 1 行を
  置く。列の見出しは**何を探していたか**を言っているもので、器ごと入れ替えるとそれが消えたうえに下の
  すべてが動く — 絞り込みを一段効かせすぎた読者は、戻る前に自分がどこに居るかを読み直すことになる。
  **`colSpan` の 1 セルにするのは幅のためでもある**: 列の下限は `Td` が持つので、行が無いあいだ表は
  窓の幅に戻り、中身が空のまま横に流れることがない (研究一覧は 12 列で 1,919px ある)。
  `app/components/page.test.tsx` が見張る
- **値が空になった facet の箱を落とさない。** 消えるのは値であって軸ではない。畳まれた箱は「この一覧は
  この軸で絞れる」と言っているので、空になったものを落とすと**絞り込みすぎた読者の前でパネルが分解して
  いく** — 0 件ではそれが全軸に及び、`categorise` がカテゴリごと落としていたときは pane が丸ごと消えて
  いた (実測で 1,310px → 0px)。**開いた箱は空にせず、値が無い理由を 1 行置く** (`Empty`)。日付の 2 つも
  同じで、`dateView` は結果がその日付を持たないとき `range` を `null` にして箱だけ残す — **`null` を
  返して消さない**
- **セルの縦の揃え方は表が持つ** (`Table` の `align`)。既定は `top` で、**行が 1 行に収まる表だけ
  `middle`**。`align-top` は「揃っている」ように見えて**中身の高さが違うぶんだけ違う量だけ上に寄る** —
  カートの行 37px で、文字 16.40 / バッジ 17.20 / ボタン 18.00px と中心が散っていた (中身の領域の中心は
  18.0)。`middle` にすると 17.65 / 17.99 / 18.00 に収まる。**一覧を `middle` にしない** — 研究題目は
  3 行、データセットは 4 行あり、読者は行の 1 行目を横に読むので、4 行のセルの隣で日付が中央に来ると
  何にも揃わなくなる
- **見出しの行はこの選択の外で、常に `middle`。** 語の見出しは折り返さないので (「幅」)、`<thead>` は
  どの表でも 1 行になる — 本文が `top` を要る理由 (3〜4 行のセル) がそこには無い。**同じ 1px が見出しにも
  出ていた**: 語 17.00 に対し、行の高さを決めている印が 18.00 だった。`app/components/page.test.tsx` が
  「セルは選択に従い、見出しは従わない」を見張る
- **遷移のあいだ、次の答えが置き換える場所を骨組みに差し替えない。** `PALE` が薄くするだけにして、前の
  答えは読めるまま残す。**server が返すまでが 12〜62ms** なので、骨組みを出すと点滅になる。**薄くするのは
  置き換わる部分だけ** (`RefinableList` の pane と結果) で、器が一緒に動くと遷移ではなく再読み込みに見える。
  **`useBusyHere` は同じアドレスへの遷移だけを数える** (`app/navigating.ts`) — 研究のページへ渡すときに
  薄くすると、去っていくページが具合を悪くしたように見える。**`SHOW_BUSY_AFTER` (200ms) を落とさない**:
  ほとんどの遷移はこれより速いので、落とすと押すたびに画面が明滅する

## 意図的にやっていないこと

| やらないこと | 理由 |
|---|---|
| ダークモード | 配色が 2 系統になり、コントラストの要件も 2 倍になる |
| 飾りの動き | 動きは「変わったことを言う」ためだけに持つ — 数が増えた印 (`bump`)、隅に出る知らせ (`rise`)、管理の区画の出入り、折りたたみの向き。どれも `motion-safe:` の下にあり、動きを消しても色と 文字が同じことを言う (`app.css` の `@theme`) |
| CSS を書くこと | `app.css` にあるのは `@theme` と、markdown が吐く要素の見た目と、上のフォーカスの輪郭だけ。他は Tailwind のクラスで、部品の中に閉じている |
| ユーティリティに別名を付けること | `.btn` のような CSS クラスを作ると、部品と CSS の 2 箇所に同じ意匠が住む |
| アイコンのパッケージを依存に持つこと | 必要な字形だけを `icons.tsx` に inline SVG として持つ。輪郭は Lucide のもの (ISC) |
| 使う先の無い部品を置いておくこと | カタログに並んでいる以上「これを使え」と読まれる。次の単元で要ると決まっているものだけ残す |
| 画面をモバイル向けに組み直すこと | 読者は机の上の画面で読む。狭い窓では段が落ちる (ヘッダのバー、絞り込みのパネル) が、**一覧の表が別の姿になることはない** — 列は 12 あって畳めるものではないので、横に送って読む |
| 印刷のための見た目 | 紙に要るのは画面ではなくデータで、それは書き出し (TSV) と JSON API が出す |
